当前目录已有用户偏好和稳定模型身份，但不能保存用户可读的名称与描述；常驻开发环境也需要可执行的供应商、对话配置与使用指引。本开发单元复用现有目录和文本链，为本人已有模型保存可清除的名称及描述覆盖，保留供应商原始元数据。

## 范围与契约

- 当前用户对已存在模型通过现有模型 PATCH 修改名称（最多 100 字符）和描述（最多 500 字符）；`null` 清除对应覆盖，省略表示不修改。GET 返回有效名称（覆盖或精确 raw ID）及描述（覆盖或供应商描述），并标识覆盖值。元数据独立于用途和运行资格；与偏好组合修改时在同一 owner/revision 事务中全部成功或全部失败。
- 四表结构中扩展 models 的可空字段，旧库显式增量迁移并保留数据；刷新、轮换及重启不覆盖用户值，不为未知发现时间生成值。当前 Key 成功目录仍是成员权威，元数据不得产生分类、适配或 verified，也不得创建模型或改变默认资格。
- 文档说明 dev 显式选择供应商数据库、独立主密钥/ID 和对话数据库、迁移与本人 HTTP 手动操作；可同认证使用物理库但各域独立连接池。复用原对话和声明入口，不新增运行链或默认联网。
- 保持固定 OneLink origin、当前用户 BYOK、精确 raw ID/稳定 model_key、用途唯一默认、版本冻结和去重、DSH 单 loop 及工具全拒绝。媒体 W3–W7、前端、生产以及 Claude/Messages 后续真实验收不在本单元。

## C0、C1 与验收

- **C0**：用户已确认上述结果、权限和持久化边界，并授权实施及必要的本人 dev 文本验证；W1/W2 已接受结果作为依赖，原接受不重判。真实联调使用本人授权的 Key、当前目录和明确的文本调用授权。
- **C1**：实施同事务元数据更新、显式迁移和只读结构检查，同步供应商/API/本地规范与说明；对稳定候选执行相关自动检查、独立审阅及 dev 真实业务验证，审阅和行为观察可以并行。
- **验收**：定向验证独立修改、清除回退、刷新/轮换/重启保留、跨用户拒绝、过期 revision、组合失败原子性、长度/类型和迁移重跑与旧数据保留；沿用 OneLink/对话相关回归。给出完整 `pnpm check` 的当前有效覆盖结论、质量及三方规范审阅。真实目录和默认文本调用另报实际环境、候选与观察，不能由自动化替身推定。
