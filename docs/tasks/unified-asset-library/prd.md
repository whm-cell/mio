# Mio 统一资产库 PRD

**状态**　待评审。本文基于 2026-11-23 资产模块产品交接要求及已确认的各项收口决策，重写个人空间下的统一资产库业务规则、领域模型、引用保护与 U1–U5 后端开发安排，替代原“全部资产 + 收藏夹 + 仅清空回收站”草案。文中全部新增接口与存储模型均为候选，不在规划阶段提前改写现行 API 契约或已接受开发成果。本仓库为纯 TypeScript 后端插件服务，正式产品前端 UI 位于外部独立前端仓库（`miioo`），由跨仓联调承接；后端单元完成条件与前后端联合业务验收分别判定。任务状态与规划交付遵循[当前任务的生命周期](../../coordination.md#当前任务的生命周期)与[规划交付要求](../../coordination.md#规划交付要求)。[任务资料入口](../index.md) · [画布接口承接 PRD](../canvas-integration/prd.md) · [漫剧工作流 PRD](../drama-workflow/prd.md) · [旧数据迁移 PRD](../legacy-migration/prd.md) · [万联素材库 PRD](../onelink-material-library/prd.md)

## 1. 目标、四菜单与角色分工

统一资产库面向个人空间登录用户，集中解决**媒体结果回看、个人目录文件整理、认证素材管理与误删恢复**四类诉求。仅纳入**图片、视频、音频**三类媒体（强枚举 `'image' | 'video' | 'audio'`），**排除生成文本**。团队成员与权限、团队回收站、团队审计查询、存储配额与计费策略均不纳入本期；平台既有登录鉴权、精确 Origin 与安全校验保持不变。

一级入口由四个并列菜单组成，撤销原草案“全部资产 + 收藏夹”及按上传自然日统一筛选与分组的规定，并取消资产页内角色/场景/道具等项目资产分类及独立的项目资产、画布资产入口：

| 一级入口（路由键建议）            | 业务定位与允许操作                                                                                                                                                       | 明确边界                                                                                                                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 生成历史（`history`）             | 回看本人在各生成、保存编辑与成片导出入口产出的全部有效媒体结果；支持单项/批量保存到我的资产、添加到新画布、下载与删除。                                                  | **首期仅提供媒体类型（全部/图片/视频/音频）筛选**，不提供名称、提示词、项目、来源或日期筛选；不提供历史改名；不展示排队/生成中/失败占位。                                                  |
| 我的资产（`library`）             | 个人逻辑目录与文件库，收录主动本地上传文件、从生成历史或项目主动保存的独立副本及其逻辑副本；支持目录整理、重命名、移动、复制、删除、全库文件名搜索、添加到新画布与下载。 | 全部生成结果与项目直接上传均**不自动进入**；本地上传专享 `jpg/jpeg/png/mp4/mp3` 与单文件 20 MiB 限制，保存平台已有媒体不受此限制。                                                         |
| Seedance 认证素材库（`seedance`） | 保留真人/AIGC 分组、手机扫码录入、专用图片上传、审核与模型联动；支持从生成历史或我的资产提交本人合法 `assetId` 导入建立独立认证关联。                                    | 导入不产生生成历史；删除互不连带；认证对象不进普通回收站；**严禁向客户端暴露上游 `supplier_asset_id`**；失效展示与重新认证归[万联素材库 PRD](../onelink-material-library/prd.md)条件单元。 |
| 回收站（`recycle`）               | 收容本人从生成历史与我的资产删除的逻辑对象（历史条目、个人库文件、顶层文件夹批次），固定保留 30 天；支持单项/批量恢复、彻底删除与清空。                                  | **不接收**项目直接上传素材、角色/分镜/项目/画布/节点、认证素材与临时失败上传；彻底删除与清空不破坏任何已有作品引用。                                                                       |

**跨模块角色分工**

- **统一资产库（本 PRD）**：负责底层媒体身份协调与统一解析、统一生成历史汇总索引层、我的资产个人目录库、回收站生命周期、全量持久引用保护、物理媒体 GC、添加到新画布导入入口，以及单文件下载签名与多文件/文件夹前端流式 ZIP 打包所需的目录清单展开与签名（严禁应用服务器拉取、打包或中转文件字节）。
- **漫剧与画布模块**：漫剧与画布继续各自维护独立项目表、业务对象与业务结果台账，**不合并漫剧与画布业务表**；角色、场景、道具、分镜当前图/视频、音频与全部成功导出成片的项目业务视图由[漫剧工作流 PRD](../drama-workflow/prd.md)的项目总览承接（总览只提供预览/试听、下载、保存到我的资产与跳转业务位置，不提供直接替换、取消定稿或删除项目内容）。旧资产深链（如 `module`、`project_id`、`category`）须逐一收口到新入口或项目总览，禁止在后端接口兼容旧参数别名或恢复旧级联删除语义。
- **前后端职责边界**：本仓库交付后端存储、领域服务、HTTP 契约、引用保护、后台回收/清理任务、轻量同步下载清单与私有 COS 短期签名，以及自动化/常驻环境实证；外部前端仓库（`miioo`）按正式冻结契约实现四 Tab 交互、素材选择器、项目总览扩展、浏览器直连私有 COS 流式 ZIP 组装、任务刷新恢复与前端工程检查，双方按第 10、11 节约定完成联合业务验收。

## 2. 对象、身份与持久关系

存储继续复用现有媒体数据库（`MIO_ASSETS_DATABASE_URL`）与 `mio_assets` 承载底层受控文件对象，遵循[资产 HTTP 契约](../../apis/assets.md)、[COS 集成契约](../../integrations/cos.md)与[PostgreSQL 使用契约](../../integrations/postgres.md)。**不新建不互通的第二套底层文件表，不侵入修改 `mio_assets` 核心列，绝不下调 `mio_assets` 通用 1 GiB 资产上限**。资产扩展表在媒体数据库独立持池并采用显式迁移。[资产表](../../../src/assets/schema.ts) · [图片结果登记](../../../src/generations/image/store.ts) · [转码结果登记](../../../src/compute/transcode/store.ts)

| 逻辑实体                              | 核心字段与职责                                                                                                                                                                                                                                                              | 独立性与约束                                                                                                                                                                                                                    |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 底层媒体（`assetId`）                 | 复用 `mio_assets` 的稳定 UUID、`owner_id`、私有 COS `raw_key`/`derived` 对象键、真实媒体类型、字节数、校验摘要、宽高/时长元数据及可选异步缩略图/预览派生物。                                                                                                                | 临时预览/下载签名 URL 只是短期凭证，绝非稳定身份；存在任一有效持有关系时禁止物理清理。                                                                                                                                          |
| 生成历史（`historyId`）               | 单表承载有效媒体产出可见记录与防复活墓碑：唯一键 `(ownerId, producerKind, businessTaskId, outputIndex)`，含 `assetId`、强枚举 `mediaType`（`image`/`video`/`audio`）、`completedAt`（仅旧库迁移允许 `null`）、来源快照、`state`（`active`/`recycled`/`purged`）与删除批次。 | 各生产域（生图/生视频/转码/漫剧/画布）各自维护原任务输出表，资产库**不重复拆建独立 `generatedOutput` 表或独立墓碑表**，且只读历史记录**不设无用 `revision` 列**；`state='purged'` 释放 `assetId` 强引用但保留唯一键防重放复活。 |
| 我的资产文件（`libraryItemId`）       | 个人空间可变逻辑条目，含 `folderId`（空为虚拟根）、显示名、`assetId`、来源追溯、乐观锁 `revision` 与删除批次。                                                                                                                                                              | 每次主动保存或复制均创建新 `libraryItemId`，共享底层 `assetId` 但名称、目录与删除态独立；来源追溯**不得设唯一约束阻碍重复保存或复制**。                                                                                         |
| 我的资产文件夹（`folderId`）          | 个人空间可变逻辑目录，含 `parentId`、显示名、规范化名称（去首尾空白 + 忽略大小写）、映射深度、乐观锁 `revision` 与删除批次。                                                                                                                                                | 同父目录下活动文件夹规范化名称唯一；支持受单次子树规模硬上限约束的单事务移动、复制、回收与批次恢复。                                                                                                                            |
| 作品业务引用（`businessReferenceId`） | 显式登记各消费方对 `assetId` 的使用位置（角色定稿/候选/参考图、分镜当前图/视频/音频、项目直接上传、剪辑草稿、成片、画布节点及全部保留版本输出/输入槽等）。                                                                                                                  | 作品通过自身有效引用解析媒体并重签短期地址，**不依赖来源历史或个人库条目存活**；来源追溯字段不是强引用。                                                                                                                        |
| 认证素材（`materialId`/`groupId`）    | 归属素材域，维护本地稳定身份、认证生命周期、内部服务端供应商映射及本地 `sourceAssetId` 持有关联。                                                                                                                                                                           | 严禁向客户端返回上游 `supplier_asset_id`；与生成历史、我的资产双向独立，不进入普通资产回收站。                                                                                                                                  |
| 回收批次（`recycleBatchId`）          | 记录顶层被删根对象（历史/文件/文件夹）、冻结子树成员明细、原路径/来源快照、`deletedAt`、固定 `expiresAt = deletedAt + 30 天` 及互斥状态（`open`/`restored`/`purged`）。                                                                                                     | 同一活动根对象同时最多一个开放批次；文件夹删除按冻结成员整体恢复，不吞并或复活更早单独删除的子项。                                                                                                                              |

**身份与鉴权铁律**：`historyId`、`libraryItemId`、`folderId`、`assetId`、`projectId`、`canvasId`、`nodeId` 与 `materialId`/`groupId` 严禁互换。所有接口的 `owner` 仅来自服务端路由层核实的 Mio 登录 Cookie；客户端提交的上下文 ID、对象键或临时 URL 均不能代替服务端归属与引用校验。

## 3. 生成历史

**纳入与排除规则**

| 来源场景                                                                                                                                                            | 是否纳入 | 关键语义                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 创作、角色/场景/道具、故事板、画布生成的图片、视频、音频                                                                                                            | 是       | 每个成功持久化且可解析的有效输出记一条历史，按 `(ownerId, producerKind, businessTaskId, outputIndex)` 唯一去重；仅保存用户可见 `displayPrompt`（配音同步保留 `transcript`），严禁将服务端拼装的私有入模词 `providerPrompt` 写入历史。 |
| 成功保存的裁剪、重绘、消除、扩图、超清、视频剪辑、抽帧等二次编辑独立结果                                                                                            | 是       | 每次保存的新结果记一条新历史（含浏览器裁剪/翻转经私有 COS 直传后由所属业务编辑入口核验本人 `sourceAssetId` 正式提交的衍生图片），固定写入 `displayPrompt = null`（不继承原提示词），原结果与原历史继续保留。                          |
| 故事板合成、剪辑成功导出的成片                                                                                                                                      | 是       | 每次成功导出的独立成片记一条历史，失败或导出中不收录，新版本不替换旧版本。                                                                                                                                                            |
| 一批多输出部分成功（例如一次 4 图中有 3 张成功、1 张失败）                                                                                                          | 部分纳入 | 已确认成功的 3 个输出分别纳入历史，失败项不纳入；已确认成功的输出不因同批后续失败而被撤销。                                                                                                                                           |
| 生成文本；失败或取消而未产出有效结果的任务项                                                                                                                        | 否       | 不进入资产模块或生成历史。                                                                                                                                                                                                            |
| 本地上传（我的资产或项目直传）、素材选择器选用、保存到我的资产、复制文件、添加到新画布                                                                              | 否       | 仅产生目录条目或业务引用，不发生产成功事件，不新增生成历史。                                                                                                                                                                          |
| 未保存的编辑预览、缩略图、播放转码、视频封面，以及视频原件上传确认同事务自动建立的 `ordinary` 派生物（preview MP4、poster、私有 HLS）和画布播放派生等内部附属派生物 | 否       | 仅作为媒体展示附属内容，不作为独立历史条目、不自动进入我的资产；派生排队或失败绝不影响原件 `ready` 与下载（见[通用媒体处理设计](../compute-service/media-compute.md)）。                                                              |

**画布多输出与原位防复活墓碑**

- 服务端在单个输出落库并核实私有 COS 原件后，在同一业务确认链路上事务性写入生成历史（`state = 'active'`，线上新登记必填真实非空 `completedAt`），单个输出独立成立，不依赖前端页面处于打开状态才保存历史。
- 画布一次生成四图属于一个节点版本（包含四条输出），在生成历史中展示四条独立记录。删除其中一条历史仅将该条改为 `recycled` 隐藏，**绝不把画布节点版本从四图改为三图**；平台不新增删除单个生成版本的能力，画布不新增导出视频能力。
- 生成历史彻底删除或 30 天到期清理后，将该历史行原位更新为 `state = 'purged'`（释放对 `assetId` 的持有，保留 `(ownerId, producerKind, businessTaskId, outputIndex)` 唯一键作为不可复活墓碑），即使 24 小时后再次收到延迟回调或对账重放，已永久删除的历史也绝不复活。

**全局视图、上下文同源视图与排序分页**

- **全局生成历史筛选边界**：首期**仅提供媒体类型（全部 / 图片 / 视频 / 音频）筛选**；明确拒绝名称搜索、提示词搜索、项目筛选、来源筛选或日期范围参数（传入未知查询参数直接返回 `400 QUERY_INVALID`）。
- **展示字段、默认命名与只读约束**：底层唯一性由稳定 UUID `historyId` 保证；`mediaType` 严格限定为 `'image' | 'video' | 'audio'`（非此三类在写入或迁移转换边界直接拒绝，不设未知媒体类型兼容分支）。展示与下载名称沿用既有业务命名规则，无既定业务命名的入口正式采用 **`<prompt前4个有效字符>_<YYYYMMDD>_<原子递增序号>.<ext>`**——日期固定取北京时间（`UTC+8`）`YYYYMMDD`，序号按**本人当日（`ownerId + YYYYMMDD`）从 `1` 原子递增**（不暴露全站生成总量）；前缀过滤控制字符、空白与路径分隔符后不足 4 字按实际截取，**若过滤后有效字符为 0 或属抽帧、成片导出等无提示词入口，统一采用 `<来源简称>_<YYYYMMDD>_<原子递增序号>.<ext>`**（绝不产出下划线开头的残缺文件名），不使用提示词全文充当名称，且**不提供历史改名**。同时返回缩略信息（原文件与缩略图地址分离，缩略图失败不判原文件失效）、媒体类型、`completedAt` 完成时间及来源名称/项目/画布/角色等上下文说明（仅作只读展示，不构成筛选控件）。
- **排序与存量未知完成时间处理**：仅查询 `state = 'active'` 记录，按单输出 `completedAt DESC` 加稳定唯一历史序列倒序分页，使用绑定当前账号与媒体类型条件的不透明游标；列表不显示排队、生成中、失败或取消占位。恢复、存量补录或事件重放均**保留原 `completedAt`（不置顶）**。**仅旧库迁移存量允许完成时间未知（`completedAt = null`），在数据库排序层单点排在所有已知完成时间记录之后、内部按稳定入库身份倒序；严禁用 `createdAt` 或当前时间伪造完成时间，线上新生成入口严禁写入 `completedAt = null`**。
- **上下文同源视图与来源快照**：项目、角色、分镜、画布内部的历史是同一批生成历史按服务端核实的业务归属范围过滤出的同源视图，共享同一 `historyId` 与删除状态（非复制记录）。任一入口删除或恢复均同步影响全局与对应上下文视图。当源角色、节点、画布或项目被删除或归档后，历史记录与来源名称快照仍完整保留，服务端返回 `sourceDeleted = true` 且前端不提供失效跳转；历史查询绝不得以存活项目内连接过滤掉既有历史。

**允许操作**：单项与批量支持「保存到我的资产」「添加到新画布」「下载（单文件或 ZIP）」「删除（移入回收站）」。保存时可选目标文件夹（默认根目录），每次明确保存创建独立逻辑副本（同 `requestId` 网络重试幂等回放不重复创建），且**保存平台已有生成媒体不受我的资产本地上传 20 MiB 限制**。

## 4. 我的资产（个人目录文件库）

**内容范围与目录浏览**

- 收录三类条目：在我的资产本地上传的文件、从生成历史主动保存的独立副本、从漫剧项目/总览主动保存的独立副本（覆盖项目生成结果与项目直接上传，经服务端按稳定 `assetId`/有效引用核验后创建逻辑副本，严禁下载缩略图重传冒充原件）及其后续复制产生的逻辑副本。生成结果、项目直接上传均不自动进入我的资产；认证素材维持独立入口，不混入普通目录。
- 浏览支持目录面包屑、当前目录节点游标分页（**文件夹在前、文件在后**，组内采用确定排序）、新建文件夹、重命名、移动、复制、删除、单文件下载、ZIP 打包下载与复用。可变文件夹与文件写操作均受乐观锁 `revision`/`baseRevision` 保护。

**目录层级、唯一性与子树单事务操作**

- **目录产品层级**：以“我的资产”虚拟根目录计**产品第 1 层**，根下直接创建的用户文件夹为**第 2 层**，最多允许 **10 层**（第 10 层文件夹禁止再新建子文件夹，也禁止移入/复制入包含后代的子树导致任意节点超过第 10 层）。数据库可采用内部偏移计数，但服务端边界响应字段 `displayDepth` 及客户端提示统一映射到本口径。
- **命名唯一性**：同父目录下**活动文件夹名**按“去首尾空白 + 忽略大小写”规范化后强制唯一（由数据库部分唯一索引保证）；**同级文件允许同名**。重命名与移动遇到同级文件夹同名冲突时直接返回 `409` 拒绝，绝不覆盖或静默合并。
- **移动防环与子树单事务提交**：禁止将目录移动或复制到自身或任意后代；并发移动在数据库事务内对相关祖先链/子树范围加锁协调，防止两次各自合法的预检在提交时形成环，并同步更新整棵子树深度。复制文件生成全新 `libraryItemId`（共享底层 `assetId`，来源追溯不受首次上传绑定唯一约束阻断）；复制文件夹创建完整独立子树（全部子目录与文件重新分配逻辑 ID），若目标目录发生文件夹同名冲突，由服务端并发安全分配“名称 副本”“名称 副本 2”等最终名称。请求数组条目数超限返回 `400`，展开后的子树总节点数超过单次硬上限直接返回 `409` 拒绝；文件夹移动、复制、删除与恢复**一律在单个数据库事务内原子提交，禁止引入不可见中间状态列或异步拆批状态机**。

**全库文件名搜索**

- **只搜索我的资产中当前活动文件的文件名**（忽略大小写子串匹配），**不搜索**提示词、文件内容或文件夹名称；搜索范围覆盖整个当前个人空间的我的资产，不受当前浏览目录限制。
- 严格排除回收站条目、Seedance 认证素材、生成历史、未主动保存的项目素材以及其他账号数据。
- 返回文件稳定 `libraryItemId`、所属完整目录路径及文件元数据；支持对搜索结果直接执行文件有效动作，以及“打开所在文件夹并按 `libraryItemId` 精准定位”（不得按同名文件或 URL 猜测定位）。

**我的资产专用本地上传（20 MiB + 5 后缀 + 私有 COS 直传底线）**

- **适用范围与准入边界**：仅约束“我的资产本地上传”入口——仅允许 `jpg`、`jpeg`、`png`、`mp4`、`mp3` 五种扩展名，单文件大小精确为 **`1..20,971,520` 字节**（`20 × 1024 × 1024 = 20 MiB`，恰好 20 MiB 允许，0 字节空文件与超出 1 字节均拒绝）。支持批量多选；不支持拖拽上传、文件夹上传与断点续传。
- **私有 COS 直传与域间上限隔离**：**严格沿用 Mio 私有 COS 浏览器直传底座**（批量申请上传绑定与预签名 PUT → 浏览器直传私有 COS `mio/staging/<assetId>` → 调用完成确认并条件复制至 `mio/raw/<assetId>/<attemptId>` 后登记 ready 与首次 `libraryItemId`），**严禁把文件二进制改为经应用后端代理转发**。同时**绝不下调 `mio_assets` 通用 1 GiB 上限**，不限制保存平台已生成的超 20 MiB 媒体，不干扰对话视觉 10 MiB 上限，也不替代 Seedance 认证素材准入（JPEG/PNG/WEBP、`<= 20 MiB`、`300..6000` 宽高，见[素材 HTTP 契约](../../apis/materials.md)）。
- **两段边界单次校验（音视频只读文件头前缀，禁整份拉入内存）**：
  1. `POST /api/v1/personal-library/uploads` 申请阶段：按请求数组顺序一一返回预签名结果（不收不存客户端临时文件键）；必填精确允许的标准 `contentType`（`image/jpeg`、`image/png`、`video/mp4`、`audio/mpeg`；若客户端环境 `File.type` 为空，由前端按 5 种允许扩展名补齐后再提交），服务端单次校验 5 种允许扩展名、扩展名与 `contentType` 严格配对（缺省或不匹配直接返回 `400` 拒绝）、声明字节范围（`1..20,971,520`）以及目标目录当前活动态（目录不存在/非本人返回 `404`，已移入回收站返回 `409`），不签发无效 COS PUT（MP3 按现行 COS 契约签入 `x-cos-acl: private`）。
  2. `POST /api/v1/personal-library/uploads/{id}/complete` 确认阶段：复核目标目录仍为活动态（目录已删直接返回 `409` 拒绝，**严禁暗中改存根目录**），执行 `HEAD` 核对真实字节长度（`1..20,971,520`）；图片走有界条件读取送纯 `sharp` 轻量解码校验，**MP4/MP3 仅执行 `readPrefix`（前几 KB 范围条件读）核验文件头魔数同已声明 `contentType` 一致，严禁将整份 20 MiB 音视频拉入应用服务器内存**，且绝不反向猜测或改写 `contentType`。**明确不做深度的 MP4/MP3 编解码媒体轨探测，禁止预留空壳探测钩子或配置开关**。
- **状态语义、取消竞争与异步衍生**：用户可见上传任务状态仅区分上传中与上传失败（成功后进入文件列表）；缩略图、预览图或播放转码异步执行，**衍生失败降级类型占位并保持原文件可下载，绝不误报为上传失败**（MP4 容器不承诺全部浏览器编解码器均原生可播）。视频原件上传确认同事务自动建立的 `ordinary` 派生意图（preview MP4、poster、私有 HLS，见[通用媒体处理设计](../compute-service/media-compute.md)）属于内部附属派生物，不进入生成历史、不自动进入我的资产，且派生排队或失败绝不回滚原件 `ready` 状态。上传中可取消、失败项可移除；刷新页面后不恢复未完成或失败队列，但服务端已完成的文件持久保留。取消与完成并发时按上传绑定行锁裁决唯一终态：已完成则返回正式 `libraryItemId` 事实，**绝不删除已完成文件冒充取消**；已取消则返回 `409` 拒绝完成。临时上传取消、失败或 24 小时到期清理均**不进入资产回收站**。

## 5. 素材选择器与添加到新画布

**跨模块素材选择器**

- 创作、漫剧项目与画布复用统一素材选择器，提供「生成历史」「我的资产」两个通用来源；需要认证素材的模型/场景额外提供「Seedance 认证素材库」来源（仅有效认证状态允许提交新生成，失效项禁止选用并引导重新认证）。
- 已有生成结果无需先保存到我的资产即可在选择器中直接选用；生成历史来源仅按调用方允许的媒体类型过滤（不附带全局项目/来源/名称搜索）；确认选择返回稳定 `assetId`、来源身份及元数据，绝不仅仅返回临时 URL。
- 预览、批量解析、勾选或未提交草稿**不建立持久引用**；仅在所属业务接口明确保存或登记结果时写入持久引用。同一媒体在不同明确操作中可重复使用并建立独立引用；除目录树“父子同选展开”按子树归并外，单次扁平请求数组（如批量删除、批量恢复、批量保存、添加到新画布或节点选材列表）内**严禁传入重复逻辑条目 ID，出现重复 ID 直接在入口返回 `400 BODY_INVALID` 拒绝，不静默吞并**；共享同一底层 `assetId` 的不同逻辑副本不得按 URL 静默合并。

**添加到新画布**

- 在「生成历史」和「我的资产」均支持对单选或多选合法媒体条目执行「添加到新画布」，固定执行流程：**新建一个真实画布项目 → 在其中建立“画布1” → 为每个选中素材各创建一个对应媒体类型的独立节点并建立画布持久引用与初始版本**。不弹出已有项目选择器，不把多素材合并为单个节点，不把普通漫剧项目 ID 充当画布项目，也不返回前端临时 ID。
- 一次请求按客户端稳定 `requestId` 保证幂等：网络超时或响应丢失重试回放同一 `projectId`、`canvasId`（画布1）与 `inputToNode` 映射，绝不重复创建第二个画布项目。
- **单事务同步原子创建**：在单个数据库事务内完成全部选中项归属、活动状态与媒体类型核验，并原子写入画布项目、`画布1`、独立节点结果与持久引用；任一项无效或写入异常直接回滚整笔事务并返回明确错误，天然无可见半成品画布项目，**禁止引入异步导入队列或回滚补偿状态机**。
- 导入操作只是复用已有媒体建立新画布节点引用，**不新增生成历史，不篡改原历史的来源上下文**；后续在该新画布中实际执行生成或保存新编辑结果时，才登记新的生成历史。节点结果与保存契约衔接[画布第 2 期](../canvas-integration/prd.md#第-2-期--私有资产手工文本与当前输出)。

**项目归档边界（已冻结）**

- 对齐[画布接口承接 PRD](../canvas-integration/prd.md)与[漫剧工作流 PRD](../drama-workflow/prd.md)：已确认现阶段漫剧项目与画布项目/画布的删除操作（`DELETE`）固定为**归档**——退出活动列表、停止新执行，但**继续持有全部有效媒体引用以支持重开与已受理任务回看**；“彻底粉碎/销毁项目”暂不提供。
- 现阶段只有**明确的业务位置移除**（例如画布删除媒体节点或清除独立输入槽并成功 `PATCH` 保存、漫剧取消定稿/移除候选/删除主体或镜头、删除项目直接上传素材）才解除对应的业务引用；即便远期引入项目彻底销毁，已产生的生成历史（含 `sourceDeleted = true` 来源快照）与用户主动保存的我的资产副本仍须继续保留。

**引用建立、释放与统一解析规则**

- **建立与释放精度**：预览、批量解析、取签名、选择器勾选或未提交草稿不改变持久引用；节点/候选结果登记成功即保护该结果所用 `assetId`（无需等待整图保存）；文档或业务保存只增删该版本实际变化的使用位置，版本冲突（409）、校验失败、保存回滚或本地撤销均维持已提交引用。同一 `assetId` 在同一画布或项目中被多节点、多保留版本或多槽位复用时，按具体位置独立计数与释放；切换画布 `currentResultId`、隐藏历史或断开未删源结果的连线不释放仍可重开的源结果引用。
- **历史恢复不反写业务**：从回收站恢复历史仅恢复列表可见性，绝不复活已删除的节点、角色或项目，也不覆盖当前已更换的新定稿或新选择。
- **上下文鉴权解析**：统一解析入口严格区分两类路径——从素材选择器发起的新选材须核实存在活动历史、活动个人库条目或服务端确认的业务复用授权（仅存在于回收站的条目**不可**作为新选材来源）；重开已保存作品或刷新到期地址时，须核实作品归属及该作品已保存的有效持久引用，不要求来源历史或我的资产条目仍存活。缺失与无权对外统一不可访问；绝不接受客户端仅凭旧 URL 或自报上下文越权解析。

## 7. 回收站与物理媒体清理

**回收站范围与 30 天固定到期**

- 回收站仅接收**生成历史、我的资产文件、我的资产文件夹**三类逻辑对象。展示名称、对象类型、原路径/来源快照、`deletedAt` 删除时间、固定 `expiresAt = deletedAt + 30 天` 与剩余天数，支持单项/批量恢复、彻底删除与清空。
- 删除活动对象时在同一事务中创建回收批次、冻结成员明细并写入 `deletedAt` 与固定 `expiresAt`。同一活动根对象同时只允许存在一个开放批次（由部分唯一索引保证，并发重复删除即使使用不同 `requestId` 也不产生双批次）。

**文件夹冻结批次恢复、回根与并发互斥**

- **整树单批且不复活更早单删项**：删除文件夹在回收站只展示一条顶层记录，事务内冻结删除时刻的活动子树成员集并整体隐藏/恢复，不展开为散项。若用户先单独删除某文件（批次 A），随后再删除其父文件夹（批次 B），两者属于两个独立回收批次；恢复父文件夹（批次 B）时严格按批次 B 的冻结成员集恢复，**绝不复活更早被单独删除的文件（批次 A）**。
- **恢复落点与冲突处理**：恢复生成历史仅将该行恢复为 `state = 'active'` 并保留原 `completedAt`（不置顶），源项目/角色/画布已不存在时仍可恢复到全局历史。恢复文件或文件夹优先放回原父目录；若原父目录已被删或不存在，则自动恢复至**我的资产根目录**（不自动复活原父目录）。文件允许同名；文件夹若遇同级同名冲突，由服务端并发安全自动追加“副本”及编号（不覆盖、不合并），响应逐项返回 `actualParentId`、`actualPath`、`actualName`、`renamed`、`fallbackToRoot` 供界面清晰告知。
- **到期、彻底删除与单事务清空**：满 30 天（以数据库当前时刻为准）后立即返回 `409` 拒绝恢复；后台按固定周期有界扫描到期批次（按小时批处理，目标 24 小时内收敛）。恢复、彻底删除、清空与到期清理采用数据库行锁互斥状态转换，仅允许一方胜出。彻底删除与清空**仅使回收站逻辑批次及对应逻辑记录永久不可恢复**（生成历史原位转为 `state = 'purged'` 保留防重放唯一键），不在此接口内同步调 COS 删除文件。`POST /api/v1/recycle-bin/empty` 在**单个数据库事务内**将当前时刻本人全部 `state = 'open'` 的回收批次原子更新为 `purged` 并同步返回 `200 { purgedBatchCount }`（事务语句快照天然不包含并发晚到的新删除批次，**不设异步 `operationId` 轮询表，也不伪造“因引用保留数/待核实”统计**）。

**物理媒体 GC（7 类持有全释放、单次锁认领与先干跑门槛）**

一份已登记的底层受控媒体（`mio_assets` ready 原件及关联派生对象）仅当以下 **7 类有效持有关系同时为零** 时，才具备物理清理资格：

1. 活动生成历史（`state = 'active'`）；
2. 活动我的资产文件条目；
3. 漫剧、项目与个人资料/会话有效业务引用（漫剧全部 9 类持有位置：项目封面、剧本/分镜源文件、主体候选与参考图、全部可恢复版本分镜候选、分镜 `creationForm` 草稿槽、镜头配音片段、剪辑草稿 `timeline` 与 `libraryAssetIds` 素材箱、历次导出成片及剪映工程 `.zip` 包；归档漫剧项目持有的全部可重开引用；以及 `auth` 库用户资料 `avatarAssetId` 与 `conversations` 库未归档对话中的视觉/工具资产引用）；
4. 画布有效引用（活动及归档画布上的节点当前结果、全部保留节点版本输出及独立输入槽）；
5. 有效认证素材与音色库本地原件持有（未解除且非删除态的 `mio_materials.source_asset_id`，以及跨库 `providers` 域持有的音色试听样本 `mio_provider_voices.preview_asset_id` 与配音记录 `mio_audio_records.asset_id`——跨库音频域经单向持久 outbox 向媒体库同步持有与 U1 生成历史登记，零分布式两阶段提交）；
6. 未到期且未彻底清理的回收站开放批次（`state = 'open'`，含冻结文件夹子树成员）；
7. 未终结的图片生成、视频生成、音频合成/复刻（含 `sampleAssetId`）、单路转码及已验收通用媒体处理（`/api/v1/compute/media`，含自动派生、抽帧、裁剪、波形、多轨渲染等，见[计算 API](../../apis/compute.md)）任务冻结输入/输出。

- **墓碑与持有分离**：处于 `state = 'purged'` 的生成历史墓碑仅保留唯一键防重放，绝不充当阻止物理 GC 的强引用。
- **单次事务认领与幂等删除协议**：引用新建与 GC 认领共享数据库行锁状态协议——GC 在**单次数据库认领事务**内加锁核验 7 类持有全为零、写入 GC 租约认领态并一并返回冻结的 `(assetId, ownerId, exactObjectKeys)`（一旦进入 GC 认领态，任何迟到并发绑定请求统一按资产不可访问返回 `404 ASSET_NOT_FOUND` 拒绝，**禁止暴露内部 GC 状态或重试绑定已认领待删资产**）；事务外直接拿该冻结精确对象键删除私有 COS 原件及受控关联附属派生对象（含通用媒体处理产生的 preview MP4、poster、私有 HLS 清单与分片等，**禁止删 COS 前二次重查 7 张业务表**）。COS 删除超时或回执丢失时保留清理记录并沿原冻结精确对象键幂等核实，确认云端对象已不存在后再更新数据库终态；**严禁无锁“先查无引用再删 COS”**。现行 `mio/staging` 24 小时清理与正式 `mio/raw`/`derived` 清理的凭据权限、范围和路径保持分离（见[COS 集成契约](../../integrations/cos.md)）。
- **受控启用门槛**：首次上线物理 GC 必须先启用**只扫描与记录（dry-run）模式**，核对全量消费方引用覆盖无漏项后，方可受控开启实际物理删除。

## 8. 单文件下载与前端流式 ZIP 打包

**单文件下载**：后端鉴权校验当前登录用户对目标逻辑对象（历史、我的资产文件或有效业务引用）的访问权后，为对应 `assetId` 签发私有 COS 短期下载签名 URL（`attachment`，默认 5 分钟有效，过期按稳定身份重签），浏览器直连 COS 下载，**文件字节绝不经应用服务器代理**；下载文件名使用逻辑文件名，且扩展名与真实媒体内容一致。

**多文件 / 文件夹 / 混合选择前端流式 ZIP 打包**：明确采用**前端浏览器直连私有 COS 流式组装 ZIP**，**禁止由应用服务器或计算服务拉取、打包或中转文件字节**；撤销异步 `download-jobs` 队列、重试、临时成品包存储与清理设计。前后端职责按以下边界划分：

1. **后端职责（轻量同步清单与签名，候选 `POST /api/v1/downloads/manifest` 及单文件/续签 `POST /api/v1/downloads/resolve`）**：
   - **前置全量校验**：逐项校验当前账号归属与活动状态；条目不存在或非本人统一返回 `404`，本人条目已移入回收站返回 `409` 拒绝整次清单生成，**绝不静默跳过缺项**。
   - **完整子树展开与独立副本不合并**：递归展开活动文件夹完整子树（保留空目录），目录树父子同选自动去重；不同位置的独立逻辑副本即使底层共享同一 `assetId` 也各自输出，**绝不按相同媒体内容静默合并**。
   - **安全规范包内路径**：服务端统一生成安全规范的包内相对路径，并对同路径重名文件及多根同名文件夹自动追加编号区分（仅修改包内路径名，不改资产原名），严格防范路径穿越、非法字符、超长路径与 Unicode 编码损坏。
   - **确定性清单、单次展开硬上限与单条目续签**：返回确定性打包清单（目录与空目录结构、文件条目、包内路径、预期字节数/摘要及私有 COS 短期直连读取签名 URL）；私有 COS 桶 CORS 须允许受控前端 Origin 执行 `GET`；大目录流式拉取期间若个别文件短期签名临期，前端按清单条目调用 `POST /api/v1/downloads/resolve` 续签单文件 URL。后端不建立 ZIP 媒体持有租约，不套用我的资产本地上传 20 MiB 限制到 ZIP 总量；请求选择数组长度超限返回 `400`，展开后的总条目数超过单次硬上限（在 U4 C0 定值）直接返回 `409` 拒绝，**绝不静默截断目录**。
2. **外部前端职责（`miioo` 承接）**：
   - **逐文件流式组装**：按后端返回的 manifest 从私有 COS 逐文件流式读取并流式写入本地 ZIP，**禁止将全部原文件一次性读入浏览器内存**。
   - **真实进度与绝不交付残包**：基于真实已处理文件数/字节展示进度（不伪造百分比）；签名临期经 `POST /api/v1/downloads/resolve` 续签，单文件读取遇临时网络错误有限重试后仍失败则立即中止打包并明确报错，**绝不落地或交付残缺不全的压缩包**。

## 9. 存量归位边界

原“全部资产 + 收藏夹”草案未上线，不存在新库兼容存量。真实旧线上系统存量按新业务模型**各归各位**，抽数、转换与停机切换框架由[旧后端数据迁移 PRD](../legacy-migration/prd.md)统筹，资产域在 U5 对接核验：

| 旧线上数据类别                     | 归位规则                                                                                                                                                  | 明确禁止事项                                                                       |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 可确认来源的生成/编辑/成片结果     | 迁入统一生成历史，保留真实完成时间、稳定输出顺序、来源上下文快照与原删除事实；缺失完成时间的记录显式标为 `completedAt = null`（未知），排在已知时间之后。 | 禁止用 `createdAt` 或当前时间伪造完成时间；禁止复活曾删除项；禁止按 URL 猜测去重。 |
| 漫剧项目内直接上传与旧画布本地上传 | 留在原项目/画布业务关系内，经 `assetId` 纳入业务引用保护。                                                                                                | 不进入生成历史；不自动塞入我的资产。                                               |
| 旧 Seedance 真人/AIGC 素材         | 迁入认证素材库并保留原远端组/素材映射（旧视频素材按素材库条件单元与迁移归档规则处理）。                                                                   | 不混入普通我的资产目录或资产回收站。                                               |
| 旧星标与旧隐藏画布目录             | 随旧方案退役，**我的资产初始为空库**。                                                                                                                    | 不为旧隐藏目录构建兼容网盘迁移；不把旧素材全量自动塞入我的资产。                   |
| 无法确认来源或无引用残留数据       | 研发在迁移演练期导出精确文件数、体积与明细清单；仍有业务可读关系的保持原引用，无主孤儿交负责人在正式切换前拍板全删或保留。                                | 禁止静默丢弃仍被引用的原件，禁止伪造归属或带入运行时免清理脏标记。                 |

## 10. 本期开发单元与 C0/C1 安排

### 跨模块联合验收

以下跨模块场景须在真实登录会话下通过真实请求、关页刷新、重登与后端持久状态/COS 原件核对共同取证（不以浏览器缓存展示或模拟数据充当证据）：

1. **全入口历史同源与删除不毁作品**：账号甲覆盖角色定稿、跨角色引用、分镜当前图/视频/配音、剪辑草稿、两版导出成片及一次四图画布节点版本。分别从全局生成历史和角色/分镜/画布上下文历史删除记录，核对全局与上下文同步隐藏并入回收站；随后刷新、重登并令旧签名到期，核对角色定稿、分镜当前媒体、剪辑草稿、两版成片、项目总览与画布四图节点均能经服务端重签地址读回与原文件一致的字节。删除角色、画布节点或归档项目后，生成历史与来源快照仍保留且不提供失效跳转。
2. **资产库 U1/U2 与画布第 2 期联合验收**：用户从生成历史或我的资产选图确认到本人画布已保存节点，核对节点结果 `POST` 成功即已建立持久引用，移动节点并 `PATCH` 保存后记录 `assetId`、`canvasId`、`nodeId`、`resultId` 与画布 `revision`。随后删除来源历史及我的资产副本并令旧签名到期，在无缓存会话重开原画布，核对服务端依据 `canvasId` 与已存绑定重签地址读回一致原件。用同账号另一张无绑定画布仅凭旧 `assetId` 尝试解析或登记新结果，在无其他合法选材授权时两条路径均被拒绝且无新绑定。同 `requestId` 重放写入不重复生成结果或引用，旧 `baseRevision` 提交删节点返回 `409` 且维持原引用，批量解析混入合法 ID、缺失 ID 与他人 ID 时仅合法项返回地址。[画布第 2 期](../canvas-integration/prd.md#第-2-期--私有资产手工文本与当前输出)

## 12. 开发反防御硬约束

供后续 U1–U5 编码实现严格遵守：

- **边界单次解析（Parse, Don't Validate）**：外部 HTTP 输入（登录 Cookie、精确 `Origin`、`src/http-request.ts` JSON 正文读取与额外字段拒绝、`isUuidV4` 校验、查询参数白名单、扁平数组无重复 ID 校验、分页 `cursor`/`limit`、个人库上传 5 种后缀与必填配对 `contentType` 及 `1..20,971,520` 字节边界）仅在对应模块路由层 `http.ts` 完成**唯一一次**合法性解析并转换为 `contracts.ts` 中的只读强类型；旧库历史存量差异（仅限 `completedAt = null`）只在迁移写入与 `store.ts` 读取映射层单点处理。内部 `service.ts` 与 `store.ts` 直接信任已收窄的强类型，**严禁**二次执行 `isUuidV4`、`typeof`、`Array.isArray`、重复后缀正则、重复去重或防御性判空。
- **实体精简与只读下传（禁冗余拆表／禁全量拉流／禁重查／禁深拷贝）**：生成历史、回收状态与防复活墓碑合并为单表生命周期（`active`/`recycled`/`purged`），严禁额外拆建独立 `generatedOutput` 表或独立墓碑表，严禁在只读历史上添加 `revision` 列；个人库上传绑定仅按 `assetId` 薄关联 `mio_assets`，严禁冗余 `staging_key`/字节数/MIME 或接收客户端临时键；MP4/MP3 上传确认仅调 `HEAD` + `readPrefix` 核验文件头魔数，**严禁将整份 20 MiB 音视频拉入应用服务器内存**。路由层核实的 `AssetPrincipal`、同库事务 `PoolClient`、目录祖先链及 GC 冻结的 `(assetId, ownerId, exactObjectKeys)` 必须顺着只读参数往下传，**严禁**内部子函数重查数据库、删 COS 前二次重扫 7 类业务表或无原地修改需求时执行 `structuredClone` 深拷贝。
- **快速失败与单一状态码（Fail Fast，复用 `@mio/foundation/http-status`）**：严禁引入仓库未定义的 `422` 或二选一模糊状态码——入参格式/单批数组超长/重复 ID 统一返 `400`；目录重名、本人条目已入回收站、展开后子树或清单总节点超硬上限、满 30 天恢复统一返 `409`；资源不存在、非本人或已进入 GC 认领态统一返 `404`。**严禁**在 `service.ts`/`store.ts` 用宽泛 `try/catch` 吞错后返回 `[]`、`null` 或静默跳过失败项；**严禁**用 `||` 或无依据 `??` 篡改合法的 `0`、`false` 或存量 `completedAt = null`（严禁用 `?? createdAt` 或 `?? now()` 伪造时间）。
- **零无证兼容、零备胎状态机与零预留抽象（对齐 `DESIGN-OVER-001`）**：仅实现本文确认的单一契约——生成历史 `mediaType` 锁死 `'image' | 'video' | 'audio'`；个人库子树操作、回收站清空与「添加到新画布」一律走单事务同步原子提交（禁止私造不可见中间态列、异步轮询操作表或回滚补偿状态机）；同驻 `MIO_ASSETS_DATABASE_URL` 的跨领域引用登记直接传事务调用（禁止抽通用回调总线或工厂层）；个人库上传不做音视频编解码媒体轨探测（禁止预留探测钩子或配置开关）；严禁兼容旧版 `module`/`project_id`/`category` 或下划线参数别名。
