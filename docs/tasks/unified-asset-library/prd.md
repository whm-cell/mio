# Mio 统一资产库 PRD

**状态**　待评审。本文基于 2026-11-23 资产模块产品交接要求及已确认的各项收口决策，重写个人空间下的统一资产库业务规则、领域模型、引用保护与 U1–U5 后端开发安排，替代原“全部资产 + 收藏夹 + 仅清空回收站”草案。文中全部新增接口与存储模型均为候选，不在规划阶段提前改写现行 API 契约或已接受开发成果。本仓库为纯 TypeScript 后端插件服务，正式产品前端 UI 位于外部独立前端仓库（`miioo`），由跨仓联调承接；后端单元完成条件与前后端联合业务验收分别判定。任务状态与规划交付遵循[当前任务的生命周期](../../coordination.md#当前任务的生命周期)与[规划交付要求](../../coordination.md#规划交付要求)。[任务资料入口](../index.md) · [画布接口承接 PRD](../canvas-integration/prd.md) · [漫剧工作流 PRD](../drama-workflow/prd.md) · [旧数据迁移 PRD](../legacy-migration/prd.md) · [万联素材库 PRD](../onelink-material-library/prd.md)

## 1. 目标、四菜单与角色分工

统一资产库面向个人空间登录用户，集中解决**媒体结果回看、个人目录文件整理、认证素材管理与误删恢复**四类诉求。仅纳入**图片、视频、音频**三类媒体，**排除生成文本**。团队成员与权限、团队回收站、团队审计查询、存储配额与计费策略均不纳入本期；平台既有登录鉴权、精确 Origin 与安全校验保持不变。

一级入口由四个并列菜单组成，撤销原草案“全部资产 + 收藏夹”及按上传自然日统一筛选与分组的规定，并取消资产页内角色/场景/道具等项目资产分类及独立的项目资产、画布资产入口：

| 一级入口（路由键建议）            | 业务定位与允许操作                                                                                                                                                       | 明确边界                                                                                                                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 生成历史（`history`）             | 回看本人在各生成、保存编辑与成片导出入口产出的全部有效媒体结果；支持单项/批量保存到我的资产、添加到新画布、下载与删除。                                                  | **首期仅提供媒体类型（全部/图片/视频/音频）筛选**，不提供名称、提示词、项目、来源或日期筛选；不提供历史改名；不展示排队/生成中/失败占位。                                                  |
| 我的资产（`library`）             | 个人逻辑目录与文件库，收录主动本地上传文件、从生成历史或项目主动保存的独立副本及其逻辑副本；支持目录整理、重命名、移动、复制、删除、全库文件名搜索、添加到新画布与下载。 | 全部生成结果与项目直接上传均**不自动进入**；本地上传专享 `jpg/jpeg/png/mp4/mp3` 与单文件 20 MiB 限制，保存平台已有媒体不受此限制。                                                         |
| Seedance 认证素材库（`seedance`） | 保留真人/AIGC 分组、手机扫码录入、专用图片上传、审核与模型联动；支持从生成历史或我的资产提交本人合法 `assetId` 导入建立独立认证关联。                                    | 导入不产生生成历史；删除互不连带；认证对象不进普通回收站；**严禁向客户端暴露上游 `supplier_asset_id`**；失效展示与重新认证归[万联素材库 PRD](../onelink-material-library/prd.md)条件单元。 |
| 回收站（`recycle`）               | 收容本人从生成历史与我的资产删除的逻辑对象（历史条目、个人库文件、顶层文件夹批次），固定保留 30 天；支持单项/批量恢复、彻底删除与清空。                                  | **不接收**项目直接上传素材、角色/分镜/项目/画布/节点、认证素材与临时失败上传；彻底删除与清空不破坏任何已有作品引用。                                                                       |

**跨模块角色分工**

- **统一资产库（本 PRD）**：负责底层媒体身份协调与统一解析、统一生成历史汇总索引层、我的资产个人目录库、回收站生命周期、全量持久引用保护、物理媒体 GC、添加到新画布导入入口，以及单文件下载签名与多文件/文件夹前端流式 ZIP 打包所需的目录清单展开与签名（严禁应用服务器拉取、打包或中转文件字节）。
- **漫剧与画布模块**：漫剧与画布继续各自维护独立项目表、业务对象与业务结果台账，**不合并漫剧与画布业务表**；角色、场景、道具、分镜当前图/视频、音频与全部成功导出成片的项目业务视图由[漫剧工作流 PRD](../drama-workflow/prd.md)的项目总览承接（总览只提供预览/试听、下载、保存到我的资产与跳转业务位置，不提供直接替换、取消定稿或删除项目内容）。旧资产深链（如 `module`、`project_id`、`category`）须逐一收口到新入口或项目总览，不得借旧参数在全局历史中恢复项目筛选控件或保留旧级联删除语义。
- **前后端职责边界**：本仓库交付后端存储、领域服务、HTTP 契约、引用保护、后台回收/清理任务、轻量同步下载清单与私有 COS 短期签名，以及自动化/常驻环境实证；外部前端仓库（`miioo`）按正式冻结契约实现四 Tab 交互、素材选择器、项目总览扩展、浏览器直连私有 COS 流式 ZIP 组装、任务刷新恢复与前端工程检查，双方按第 10、11 节约定完成联合业务验收。

## 2. 对象、身份与持久关系

存储继续复用现有媒体数据库（`MIO_ASSETS_DATABASE_URL`）与 `mio_assets` 承载底层受控文件对象，遵循[资产 HTTP 契约](../../apis/assets.md)、[COS 集成契约](../../integrations/cos.md)与[PostgreSQL 使用契约](../../integrations/postgres.md)。**不新建不互通的第二套底层文件表，不侵入修改 `mio_assets` 核心列，绝不下调 `mio_assets` 通用 1 GiB 资产上限**。资产扩展表在媒体数据库独立持池并采用显式迁移。[资产表](../../../src/assets/schema.ts) · [图片结果登记](../../../src/generations/store.ts) · [转码结果登记](../../../src/compute/store.ts)

| 逻辑实体                              | 核心字段与职责                                                                                                                                                             | 独立性与约束                                                                                                                                          |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 底层媒体（`assetId`）                 | 复用 `mio_assets` 的稳定 UUID、`owner_id`、私有 COS `raw_key`/`derived` 对象键、真实媒体类型、字节数、校验摘要、宽高/时长元数据及可选异步缩略图/预览派生物。               | 临时预览/下载签名 URL 只是短期凭证，绝非稳定身份；存在任一有效持有关系时禁止物理清理。                                                                |
| 生产任务与输出（`generatedOutputId`） | 业务生产/编辑/导出任务的单条稳定媒体产出，保存 `(businessTaskId, outputIndex)`、独立成功态、`completedAt`、`assetId`。                                                     | 单个输出持久化成功后即独立成立，不因同批其他输出失败而撤销；作为溯源实体可只保留最小元数据，不充当永不退出的强引用阻碍物理 GC。                       |
| 生成历史（`historyId`）               | 面向用户的单输出可见记录，一对一关联 `generatedOutputId` 与 `assetId`，保存 `completedAt`（可空）、来源上下文快照、`revision`、删除批次与彻底删除后的不可复活去重墓碑。    | 全局与项目/角色/分镜/画布上下文共用同一 `historyId` 与删除状态；历史删除只改变可见性，绝不使底层 `assetId` 或已建立作品引用失效。                     |
| 我的资产文件（`libraryItemId`）       | 个人空间独立逻辑条目，含 `folderId`（空为虚拟根）、显示名、`assetId`、来源追溯、`revision` 与删除批次。                                                                    | 每次主动保存或复制均创建新 `libraryItemId`，共享底层 `assetId` 但名称、目录与删除态独立；来源追溯**不得设唯一约束阻碍重复保存或复制**。               |
| 我的资产文件夹（`folderId`）          | 个人空间逻辑目录，含 `parentId`、显示名、规范化名称（去首尾空白 + 忽略大小写）、映射深度、`revision` 与删除批次。                                                          | 同父目录下活动文件夹规范化名称唯一；支持子树整体移动、复制、回收与批次恢复。                                                                          |
| 作品业务引用（`businessReferenceId`） | 显式登记各消费方对 `assetId` 的使用位置（角色定稿/候选/参考图、分镜当前图/视频/音频、项目直接上传、剪辑草稿、成片、画布节点及全部保留版本输出/输入槽等）。                 | 作品通过自身有效引用解析媒体并重签短期地址，**不依赖来源历史或个人库条目存活**；来源追溯字段不是强引用。                                              |
| 认证素材（`materialId`/`groupId`）    | 归属素材域，维护本地稳定身份、认证生命周期、内部服务端供应商映射及本地 `sourceAssetId` 持有关联。                                                                          | 严禁向客户端返回上游 `supplier_asset_id`；与生成历史、我的资产双向独立，不进入普通资产回收站。                                                        |
| 回收批次（`recycleBatchId`）          | 记录顶层被删根对象（历史/文件/文件夹）、冻结子树成员明细、原路径/来源快照、`deletedAt`、固定 `expiresAt = deletedAt + 30 天` 及互斥状态机。                                | 同一活动根对象同时最多一个开放批次；文件夹删除按冻结成员整体恢复，不吞并或复活更早单独删除的子项。                                                    |
| 上传会话与异步操作                    | 上传会话绑定客户端临时文件键、目标目录、声明信息、staging/完成态与首次 `libraryItemId`；异步操作（如回收站清空快照、大子树操作或新画布导入补偿）记录真实进度与可查询结果。 | 上传会话仅约束首次完成幂等绑定，不阻塞后续复制；多文件/文件夹 ZIP 打包由前端直连私有 COS 流式完成，后端不维护服务端异步 ZIP 任务与 ZIP 媒体持有租约。 |

**身份与鉴权铁律**：`historyId`、`libraryItemId`、`folderId`、`assetId`、`projectId`、`canvasId`、`nodeId`、`materialId`/`groupId` 与 `operationId` 严禁互换。所有接口的 `owner` 仅来自服务端核实的 Mio 登录 Cookie；客户端提交的上下文 ID、对象键或临时 URL 均不能代替服务端归属与引用校验。

## 3. 生成历史

**纳入与排除规则**

| 来源场景                                                                                                                                                            | 是否纳入 | 关键语义                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 创作、角色/场景/道具、故事板、画布生成的图片、视频、音频                                                                                                            | 是       | 每个成功持久化且可解析的有效输出记一条历史，按 `(businessTaskId, outputIndex)` 唯一去重。                                                                                |
| 成功保存的裁剪、重绘、消除、扩图、超清、视频剪辑、抽帧等二次编辑独立结果                                                                                            | 是       | 每次保存的新结果记一条新历史，原结果与原历史继续保留。                                                                                                                   |
| 故事板合成、剪辑成功导出的成片                                                                                                                                      | 是       | 每次成功导出的独立成片记一条历史，失败或导出中不收录，新版本不替换旧版本。                                                                                               |
| 一批多输出部分成功（例如一次 4 图中有 3 张成功、1 张失败）                                                                                                          | 部分纳入 | 已确认成功的 3 个输出分别纳入历史，失败项不纳入；已确认成功的输出不因同批后续失败而被撤销。                                                                              |
| 生成文本；失败或取消而未产出有效结果的任务项                                                                                                                        | 否       | 不进入资产模块或生成历史。                                                                                                                                               |
| 本地上传（我的资产或项目直传）、素材选择器选用、保存到我的资产、复制文件、添加到新画布                                                                              | 否       | 仅产生目录条目或业务引用，不发生产成功事件，不新增生成历史。                                                                                                             |
| 未保存的编辑预览、缩略图、播放转码、视频封面，以及视频原件上传确认同事务自动建立的 `ordinary` 派生物（preview MP4、poster、私有 HLS）和画布播放派生等内部附属派生物 | 否       | 仅作为媒体展示附属内容，不作为独立历史条目、不自动进入我的资产；派生排队或失败绝不影响原件 `ready` 与下载（见[通用媒体处理设计](../compute-service/media-compute.md)）。 |

**画布多输出与防重墓碑**

- 服务端在单个输出落库并核实私有 COS 原件后，在同一业务确认链路上事务性登记输出与生成历史，不依赖前端页面处于打开状态才保存历史。
- 画布一次生成四图属于一个节点版本（包含四条输出），在生成历史中展示四条独立记录。删除其中一条历史仅隐藏该历史条目，**绝不把画布节点版本从四图改为三图**；平台不新增删除单个生成版本的能力，画布不新增导出视频能力。
- 生成历史彻底删除或到期清理后，保留最小不可复活去重墓碑（独立于短期请求幂等键），即使 24 小时后再次收到延迟回调或对账重放，已永久删除的历史也绝不复活。

**全局视图、上下文同源视图与排序分页**

- **全局生成历史筛选边界**：首期**仅提供媒体类型（全部 / 图片 / 视频 / 音频）筛选**；明确不提供名称搜索、提示词搜索、项目筛选、来源筛选或日期范围筛选。
- **展示字段、默认命名与只读约束**：底层唯一性由稳定 UUID `historyId` 保证；展示与下载名称沿用既有业务命名规则，无既定业务命名的入口正式采用 **`<prompt前4个有效字符>_<YYYYMMDD>_<原子递增序号>.<ext>`**（过滤控制字符与路径分隔符，不足 4 字按实际有效字符截取；抽帧、成片导出等无提示词入口则采用 `<来源简称>_<YYYYMMDD>_<原子递增序号>.<ext>`），不使用提示词全文充当名称，且**不提供历史改名**；同时返回缩略信息（原文件与缩略图地址分离，缩略图失败不判原文件失效）、媒体类型、`completedAt` 完成时间及来源名称/项目/画布/角色等上下文说明（仅作只读展示，不构成筛选控件）。未知媒体类型兼容只读展示，禁止按错误类型强行创建画布节点。
- **排序与未知完成时间处理**：按单输出 `completedAt DESC` 加稳定唯一序列（输出顺序/历史序列）倒序分页，使用绑定当前账号与媒体类型条件的不透明游标；列表仅呈现已存在的有效媒体结果，不显示排队、生成中、失败或取消占位。恢复、存量补录或事件重放均**保留原 `completedAt`（不置顶）**。**存量中完成时间未知（`completedAt = null`）的记录统一排在所有已知完成时间记录之后，内部按稳定入库身份倒序，绝不用 `createdAt` 或当前时间伪造完成时间**。
- **上下文同源视图与来源快照**：项目、角色、分镜、画布内部的历史是同一批生成历史按服务端核实的业务归属范围过滤出的同源视图，共享同一 `historyId` 与删除状态（非复制记录）。任一入口删除或恢复均同步影响全局与对应上下文视图。当源角色、节点、画布或项目被删除或归档后，历史记录与来源名称快照仍完整保留，服务端返回 `sourceDeleted = true` 且前端不提供失效跳转；历史查询绝不得以存活项目内连接过滤掉既有历史。

**允许操作**：单项与批量支持「保存到我的资产」「添加到新画布」「下载（单文件或 ZIP）」「删除（移入回收站）」。保存时可选目标文件夹（默认根目录），每次明确保存创建独立逻辑副本（同 `requestId` 网络重试幂等回放不重复创建），且**保存平台已有生成媒体不受我的资产本地上传 20 MiB 限制**。

## 4. 我的资产（个人目录文件库）

**内容范围与目录浏览**

- 收录三类条目：在我的资产本地上传的文件、从生成历史主动保存的独立副本、从漫剧项目/总览主动保存的独立副本（覆盖项目生成结果与项目直接上传，经服务端按稳定 `assetId`/有效引用核验后创建逻辑副本，严禁下载缩略图重传冒充原件）及其后续复制产生的逻辑副本。生成结果、项目直接上传均不自动进入我的资产；认证素材维持独立入口，不混入普通目录。
- 浏览支持目录面包屑、当前目录节点游标分页（**文件夹在前、文件在后**，组内采用确定排序）、新建文件夹、重命名、移动、复制、删除、单文件下载、ZIP 打包下载与复用。可变文件夹与文件写操作均受乐观锁 `revision`/`baseRevision` 保护。

**目录层级、唯一性与子树原子操作**

- **目录产品层级**：以“我的资产”虚拟根目录计**产品第 1 层**，根下直接创建的用户文件夹为**第 2 层**，最多允许 **10 层**（第 10 层文件夹禁止再新建子文件夹，也禁止移入/复制入包含后代的子树导致任意节点超过第 10 层）。数据库可采用内部偏移计数，但服务端校验、响应字段 `displayDepth` 及客户端提示必须统一映射到本口径。
- **命名唯一性**：同父目录下**活动文件夹名**按“去首尾空白 + 忽略大小写”规范化后强制唯一（由数据库部分唯一索引保证）；**同级文件允许同名**。重命名与移动遇到同级文件夹同名冲突时直接阻止并提示修改，绝不覆盖或静默合并。
- **移动防环与子树复制**：禁止将目录移动或复制到自身或任意后代；并发移动须对相关祖先链/子树范围加锁或串行协调，防止两次各自合法的预检在提交时形成环，并同步更新整棵子树深度。复制文件生成全新 `libraryItemId`（共享底层 `assetId`，来源追溯不受首次上传会话唯一约束阻断）；复制文件夹创建完整独立子树（全部子目录与文件重新分配逻辑 ID），若目标目录发生文件夹同名冲突，由服务端并发安全分配“名称 副本”“名称 副本 2”等最终名称。文件夹移动、复制、删除与恢复以单棵子树为原子单元（或通过不可见中间态提交），绝不对外暴露半棵树。

**全库文件名搜索**

- **只搜索我的资产中当前活动文件的文件名**（忽略大小写子串匹配），**不搜索**提示词、文件内容或文件夹名称；搜索范围覆盖整个当前个人空间的我的资产，不受当前浏览目录限制。
- 严格排除回收站条目、Seedance 认证素材、生成历史、未主动保存的项目素材以及其他账号数据。
- 返回文件稳定 `libraryItemId`、所属完整目录路径及文件元数据；支持对搜索结果直接执行文件有效动作，以及“打开所在文件夹并按 `libraryItemId` 精准定位”（不得按同名文件或 URL 猜测定位）。

**我的资产专用本地上传（20 MiB + 5 后缀 + 私有 COS 直传底线）**

- **适用范围与准入边界**：仅约束“我的资产本地上传”入口——仅允许 `jpg`、`jpeg`、`png`、`mp4`、`mp3` 五种扩展名，单文件大小精确为 **`1..20,971,520` 字节**（`20 × 1024 × 1024 = 20 MiB`，恰好 20 MiB 允许，0 字节空文件与超出 1 字节均拒绝）。支持批量多选；不支持拖拽上传、文件夹上传与断点续传。
- **私有 COS 直传与域间上限隔离**：**严格沿用 Mio 私有 COS 浏览器直传底座**（批量申请上传会话与预签名 PUT → 浏览器直传私有 COS `mio/staging/<assetId>` → 调用完成确认，由服务端有界条件读取复核并条件复制至 `mio/raw/<assetId>/<attemptId>` 后登记 ready 与首次 `libraryItemId`），**严禁把文件二进制改为经应用后端代理转发**。同时**绝不下调 `mio_assets` 通用 1 GiB 上限**，不限制保存平台已生成的超 20 MiB 媒体，不干扰对话视觉 10 MiB 上限，也不替代 Seedance 认证素材准入（JPEG/PNG/WEBP、`<= 20 MiB`、`300..6000` 宽高，见[素材 HTTP 契约](../../apis/materials.md)）。
- **服务端轻量基础校验（音视频深度探测置后）**：前端预校验仅用于体验提示，服务端在确认阶段通过有界条件流执行**轻量基础校验**——核对真实字节长度（`1..20,971,520` 字节精确边界）、5 种允许扩展名、合理 MIME 映射与文件头魔数（图片复用纯 `sharp` 轻量校验；浏览器未报 MIME 时允许服务端按文件头魔数识别，不误判为伪造）；**深度的 MP4/MP3 编解码媒体轨探测“安检仪”明确置后**（不纳入 U2 首期阻塞，后续仅在出现真实线上坏件问题时按 `DESIGN-OVER-001` 评估补充）。完成提交时复核目标目录仍为活动状态，目录已删则明确失败，绝不暗中改存根目录或其他目录。
- **状态语义、取消竞争与异步衍生**：用户可见上传任务状态仅区分上传中与上传失败（成功后进入文件列表）；缩略图、预览图或播放转码异步执行，**衍生失败降级类型占位并保持原文件可下载，绝不误报为上传失败**（MP4 容器不承诺全部浏览器编解码器均原生可播）。视频原件上传确认同事务自动建立的 `ordinary` 派生意图（preview MP4、poster、私有 HLS，见[通用媒体处理设计](../compute-service/media-compute.md)）属于内部附属派生物，不进入生成历史、不自动进入我的资产，且派生排队或失败绝不回滚原件 `ready` 状态。上传中可取消、失败项可移除；刷新页面后不恢复未完成或失败队列，但服务端已完成的文件持久保留。取消与完成并发时按上传会话锁裁决唯一终态：已完成则返回正式 `libraryItemId` 事实，**绝不删除已完成文件冒充取消**；已取消则拒绝完成。临时上传取消、失败或 24 小时到期清理均**不进入资产回收站**。

## 5. 素材选择器与添加到新画布

**跨模块素材选择器**

- 创作、漫剧项目与画布复用统一素材选择器，提供「生成历史」「我的资产」两个通用来源；需要认证素材的模型/场景额外提供「Seedance 认证素材库」来源（仅有效认证状态允许提交新生成，失效项禁止选用并引导重新认证）。
- 已有生成结果无需先保存到我的资产即可在选择器中直接选用；生成历史来源仅按调用方允许的媒体类型过滤（不附带全局项目/来源/名称搜索）；确认选择返回稳定 `assetId`、来源身份及元数据，绝不仅仅返回临时 URL。
- 预览、批量解析、勾选或未提交草稿**不建立持久引用**；仅在所属业务接口明确保存或登记结果时写入持久引用。同一媒体在不同明确操作中可重复使用并建立独立引用；同一提交内重复选中同一逻辑条目只处理一次；共享同一底层 `assetId` 的不同逻辑副本不得未经约定按 URL 静默合并。

**添加到新画布**

- 在「生成历史」和「我的资产」均支持对单选或多选合法媒体条目执行「添加到新画布」，固定执行流程：**新建一个真实画布项目 → 在其中建立“画布1” → 为每个选中素材各创建一个对应媒体类型的独立节点并建立画布持久引用与初始版本**。不弹出已有项目选择器，不把多素材合并为单个节点，不把普通漫剧项目 ID 充当画布项目，也不返回前端临时 ID。
- 一次请求按客户端稳定 `requestId` 保证幂等：网络超时或响应丢失重试回放同一 `projectId`、`canvasId`（画布1）与 `inputToNode` 映射，绝不重复创建第二个画布项目。
- 受理前全量校验每个选中项的归属、活动状态与支持媒体类型，任一项无效则整体阻止；创建过程采用原子提交或可查询异步 `operationId` 加失败补偿，确保失败时**无可见半成品画布项目**。
- 导入操作只是复用已有媒体建立新画布节点引用，**不新增生成历史，不篡改原历史的来源上下文**；后续在该新画布中实际执行生成或保存新编辑结果时，才登记新的生成历史。节点结果与保存契约衔接[画布第 2 期](../canvas-integration/prd.md#第-2-期--私有资产手工文本与当前输出)。

**引用建立、释放与统一解析规则**

- **建立与释放精度**：预览、批量解析、取签名、选择器勾选或未提交草稿不改变持久引用；节点/候选结果登记成功即保护该结果所用 `assetId`（无需等待整图保存）；文档或业务保存只增删该版本实际变化的使用位置，版本冲突（409）、校验失败、保存回滚或本地撤销均维持已提交引用。同一 `assetId` 在同一画布或项目中被多节点、多保留版本或多槽位复用时，按具体位置独立计数与释放；切换画布 `currentResultId`、隐藏历史或断开未删源结果的连线不释放仍可重开的源结果引用。
- **历史恢复不反写业务**：从回收站恢复历史仅恢复列表可见性，绝不复活已删除的节点、角色或项目，也不覆盖当前已更换的新定稿或新选择。

## 7. 回收站与物理媒体清理

**回收站范围与 30 天固定到期**

- 回收站仅接收**生成历史、我的资产文件、我的资产文件夹**三类逻辑对象。展示名称、对象类型、原路径/来源快照、`deletedAt` 删除时间、固定 `expiresAt = deletedAt + 30 天` 与剩余天数，支持单项/批量恢复、彻底删除与清空。
- 删除活动对象时在同一事务中创建回收批次、冻结成员明细并写入 `deletedAt` 与固定 `expiresAt`。同一活动根对象同时只允许存在一个开放批次（并发重复删除即使使用不同 `requestId` 也不得产生双批次）。

**文件夹冻结批次恢复、回根与并发互斥**

- **整树单批且不复活更早单删项**：删除文件夹在回收站只展示一条顶层记录，事务内冻结删除时刻的活动子树成员集并整体隐藏/恢复，不展开为散项。若用户先单独删除某文件（批次 A），随后再删除其父文件夹（批次 B），两者属于两个独立回收批次；恢复父文件夹（批次 B）时严格按批次 B 的冻结成员集恢复，**绝不复活更早被单独删除的文件（批次 A）**。
- **恢复落点与冲突处理**：恢复生成历史仅恢复原 `historyId` 可见性并保留原 `completedAt`（不置顶），源项目/角色/画布已不存在时仍可恢复到全局历史。恢复文件或文件夹优先放回原父目录；若原父目录已被删或不存在，则自动恢复至**我的资产根目录**（不自动复活原父目录）。文件允许同名；文件夹若遇同级同名冲突，由服务端并发安全自动追加“副本”及编号（不覆盖、不合并），响应逐项返回 `actualParentId`、`actualPath`、`actualName`、`renamed`、`fallbackToRoot` 供界面清晰告知。
- **到期、彻底删除与清空快照**：满 30 天（以数据库当前时刻为准）后立即拒绝恢复；后台按周期扫描到期批次（建议按小时批处理，目标 24 小时内收敛并监控积压）。恢复、彻底删除与到期清理采用行锁互斥状态转换，仅允许一方胜出。彻底删除仅使逻辑记录永久不可恢复（生成历史保留不可复活墓碑）。清空受理时在事务内冻结当时本人全部开放回收批次快照，返回 `202 + operationId` 供刷新续查；清空期间新删除的条目留待下次，绝不无提示扩大本次清空范围。

**物理媒体 GC（7 类持有全释放、事务并发协议与先干跑门槛）**

一份已登记的底层受控媒体（`mio_assets` ready 原件及关联派生对象）仅当以下 **7 类有效持有关系同时为零** 时，才具备物理清理资格：

1. 活动生成历史；
2. 活动我的资产文件条目；
3. 漫剧与项目类有效业务引用（主体定稿/候选/参考图、分镜当前图/视频/音频与保留版本候选、项目直接上传有效条目、剪辑草稿、已导出成片关联，以及归档项目持有的全部可重开引用）；
4. 画布有效引用（活动及归档画布上的节点当前结果、全部保留节点版本输出及独立输入槽）；
5. 有效认证素材本地原件持有（未解除且非删除态的 `mio_materials.source_asset_id`）；
6. 未到期且未彻底清理的回收站开放批次（含冻结文件夹子树成员）；
7. 未终结的生成、编辑、转码、通用媒体处理（候选 `/api/v1/compute/media`，含自动派生、抽帧、裁剪、渲染等，见[通用媒体处理设计](../compute-service/media-compute.md)）或导入任务冻结输入/输出。

- **溯源与持有分离**：`generatedOutput` 等溯源实体与历史不可复活墓碑在逻辑记录彻底移除后仅保留最小元数据，绝不充当阻止物理 GC 的强引用。
- **并发与恢复安全**：引用新建与 GC 认领共享数据库事务状态协议——GC 先对零引用媒体执行候选标记与租约认领（进入清理窗口后拒绝或冲突重试新绑定），执行 COS 删除前再次核验所有者、精确对象键与 7 类引用均为零；COS 删除超时或回执丢失时保留清理记录并沿原精确对象键幂等核实，确认云端原件及受控关联附属派生对象（含通用媒体处理产生的 preview MP4、poster、私有 HLS 清单与分片等）已按精确对象键删除后再更新数据库终态，**严禁无锁“先查无引用再删 COS”**，也不得在仍有有效引用时为清缓存导致作品断链。现行 `mio/staging` 24 小时清理与正式 `mio/raw`/`derived` 清理的凭据权限、范围和路径保持分离（见[COS 集成契约](../../integrations/cos.md)）。
- **受控启用门槛**：首次上线物理 GC 必须先启用**只扫描与记录（dry-run）模式**，核对全量消费方引用覆盖无漏项后，方可受控开启实际物理删除。

## 8. 单文件下载与前端流式 ZIP 打包

**单文件下载**：后端鉴权校验当前登录用户对目标逻辑对象（历史、我的资产文件或有效业务引用）的访问权后，为对应 `assetId` 签发私有 COS 短期下载签名 URL（`attachment`，默认短期有效如 5–10 分钟，过期按稳定身份重签），浏览器直连 COS 下载，**文件字节绝不经应用服务器代理**；下载文件名使用逻辑文件名，且扩展名与真实媒体内容合理一致。

**多文件 / 文件夹 / 混合选择前端流式 ZIP 打包**：明确采用**前端浏览器直连私有 COS 流式组装 ZIP**，**禁止由应用服务器或计算服务拉取、打包或中转文件字节**（避免服务端双倍网络与存储 I/O）；撤销原异步 `download-jobs` 队列、重试、临时成品包存储与清理设计。前后端职责按以下边界划分：

1. **后端职责（轻量同步清单与签名，候选 `POST /api/v1/downloads/manifest` 及单文件/续签 `POST /api/v1/downloads/resolve`）**：
   - **前置全量校验**：逐项校验当前账号归属与活动状态；若所选条目已被删除或无权访问，直接返回 `409` 提示调整选择，**绝不静默跳过缺项**。
   - **完整子树展开与独立副本不合并**：递归展开活动文件夹完整子树（保留空目录），父子同选自动去重；不同位置的独立逻辑副本即使底层共享同一 `assetId` 也各自输出，**绝不按相同媒体内容静默合并**。
   - **安全规范包内路径**：服务端统一生成安全规范的包内相对路径，并对同路径重名文件及多根同名文件夹自动追加编号区分（仅修改包内路径名，不改资产原名），严格防范路径穿越、非法字符、超长路径与 Unicode 编码损坏。
   - **确定性清单、COS CORS 与单条目续签**：返回确定性打包清单（目录与空目录结构、文件条目、包内路径、预期字节数/摘要及私有 COS 短期直连读取签名 URL）；要求私有 COS 桶 CORS 允许受控前端 Origin 执行 `GET`；大目录流式拉取期间若个别文件短期签名临期，前端可按清单条目调用 `POST /api/v1/downloads/resolve` 续签单文件 URL（后端不建立 ZIP 媒体持有租约，绝不隐式套用我的资产本地上传 20 MiB 限制到 ZIP 总量，也不静默截断目录；仅在 U4 C0 对单次 `manifest` 展开条目数设置安全软保护，超限时明确提示）。
2. **外部前端职责（`miioo` 承接）**：
   - **逐文件流式组装**：按后端返回的 manifest 从私有 COS 逐文件流式读取并流式写入本地 ZIP，**禁止将全部原文件一次性读入浏览器内存**。
   - **真实进度、有限重试与绝不交付残包**：基于真实已处理文件数/字节展示进度（不伪造百分比）；单文件读取遇临时网络故障执行有限自动重试（临期自动经 `POST /api/v1/downloads/resolve` 续签），**任一条目最终读取失败则中止打包并明确报错提供重试，绝不落地或交付残缺不全的压缩包**。

## 9. 存量归位边界

原“全部资产 + 收藏夹”草案未上线，不存在新库兼容存量。真实旧线上系统存量按新业务模型**各归各位**，抽数、转换与停机切换框架由[旧后端数据迁移 PRD](../legacy-migration/prd.md)统筹，资产域在 U5 对接核验：

| 旧线上数据类别                     | 归位规则                                                                                                                                                  | 明确禁止事项                                                                       |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 可确认来源的生成/编辑/成片结果     | 迁入统一生成历史，保留真实完成时间、稳定输出顺序、来源上下文快照与原删除事实；缺失完成时间的记录显式标为 `completedAt = null`（未知），排在已知时间之后。 | 禁止用 `createdAt` 或当前时间伪造完成时间；禁止复活曾删除项；禁止按 URL 猜测去重。 |
| 漫剧项目内直接上传与旧画布本地上传 | 留在原项目/画布业务关系内，经 `assetId` 纳入业务引用保护。                                                                                                | 不进入生成历史；不自动塞入我的资产。                                               |
| 旧 Seedance 真人/AIGC 素材         | 迁入认证素材库并保留原远端组/素材映射（旧视频素材按素材库条件单元与迁移归档规则处理）。                                                                   | 不混入普通我的资产目录或资产回收站。                                               |
| 旧星标与旧隐藏画布目录             | 随旧方案退役，**我的资产初始为空库**。                                                                                                                    | 不为旧隐藏目录构建兼容网盘迁移；不把旧素材全量自动塞入我的资产。                   |
| 无法确认来源或无引用残留数据       | 研发导出可核对数量与明细清单，保持安全可读的原关系，仅对确实无法映射的残留交产品评审处置。                                                                | 禁止静默丢弃仍被引用的原件，也不强行伪造归属。                                     |

## 10. 本期开发单元与 C0/C1 安排

1. **全入口历史同源与删除不毁作品**：账号甲覆盖角色定稿、跨角色引用、分镜当前图/视频/配音、剪辑草稿、两版导出成片及一次四图画布节点版本。分别从全局生成历史和角色/分镜/画布上下文历史删除记录，核对全局与上下文同步隐藏并入回收站；随后刷新、重登并令旧签名到期，核对角色定稿、分镜当前媒体、剪辑草稿、两版成片、项目总览与画布四图节点均能经服务端重签地址读回与原文件一致的字节。删除角色、画布节点或归档项目后，生成历史与来源快照仍保留且不提供失效跳转。
2. **资产库 U1/U2 与画布第 2 期联合验收**：用户从生成历史或我的资产选图确认到本人画布已保存节点，核对节点结果 `POST` 成功即已建立持久引用，移动节点并 `PATCH` 保存后记录 `assetId`、`canvasId`、`nodeId`、`resultId` 与画布 `revision`。随后删除来源历史及我的资产副本并令旧签名到期，在无缓存会话重开原画布，核对服务端依据 `canvasId` 与已存绑定重签地址读回一致原件。用同账号另一张无绑定画布仅凭旧 `assetId` 尝试解析或登记新结果，在无其他合法选材授权时两条路径均被拒绝且无新绑定。同 `requestId` 重放写入不重复生成结果或引用，旧 `baseRevision` 提交删节点返回 `409` 且维持原引用，批量解析混入合法 ID、缺失 ID 与他人 ID 时仅合法项返回地址。[画布第 2 期](../canvas-integration/prd.md#第-2-期--私有资产手工文本与当前输出)
3. **添加到新画布与前端流式 ZIP 完整解压**：从生成历史和我的资产多选媒体（含超 20 MiB 平台生成视频）执行添加到新画布，核对新建真实画布项目、画布1、逐项独立类型节点及同 `requestId` 重试幂等，且历史列表无新增导入假历史、原来源快照未篡改。对嵌套目录（含空目录）、不同位置共享同一 `assetId` 的同名独立副本及父子重叠选择发起 ZIP 下载，核对后端仅返回确定性 `manifest` 与私有 COS 短期签名（应用服务器不代理或打包文件字节，所选含已删或无权条目时直接返回 `409` 拒绝）；外部前端（`miioo`）直连私有 COS 流式写入本地 ZIP（禁止一次性全量读入浏览器内存）并核验临期条目经 `POST /api/v1/downloads/resolve` 续签，实际解压逐项比对 manifest 文件数、空目录结构与内容摘要，模拟单文件读取重试耗尽后确认中止报错且不落地残缺压缩包。
4. **项目总览与认证素材库隔离**：核对项目总览（归[漫剧工作流 PRD](../drama-workflow/prd.md)）仅提供预览/试听、下载、保存到我的资产与跳转，无直接删除/替换；删除项目直接上传素材不进入资产回收站，若为当前采用则清空当前位置，已保存的我的资产副本及其他独立引用保留。从历史/我的资产提交本人 `assetId` 导入认证素材不产生生成历史，删除来源与删除认证素材互不连带且认证对象不进入普通回收站；认证失效与重新认证随[万联素材库 PRD](../onelink-material-library/prd.md)条件单元就绪后单独联合验收。

### 清空与到期后的引用验收

各例均使用独立、可丢弃的私有 COS 最终对象。实验前确认可读回原件，记录 `assetId`、精确 COS 对象键、SHA-256 摘要及全部有效持有位置；清空或到期后按 `operationId` 或批次状态核对逻辑关系已移除且受保护计数准确；验证保留时须关页并以新签名读回相同字节摘要；验证清理时须核对数据库终态并以有权检查对象的身份确认同一 COS 对象键已不存在（旧签名过期或返回 403 **不能**作为物理删除凭据）。

| 用例                | 操作顺序                                                                                                                                                                            | 通过条件                                                                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 个人库副本最后解除  | 媒体 5 仅由一条生成历史、一条我的资产副本和一个画布手工媒体节点持有。删除历史并清空回收站；在画布删除该节点并成功保存；打开个人库副本读回原件；再删除并彻底清理该副本（最后持有）。 | 清空历史后副本与节点均可读 5；删节点保存后该画布引用归零，个人库副本仍可读且不新建作品引用；彻底清理最后副本后，5 自动进入 GC 并确认 COS 对象已删除。 |
| 同画布多处引用释放  | 同画布节点甲、乙各确认一个使用媒体 X 的结果，乙再改选媒体 Y 使 X 留在乙的可重开历史；X 无副本及其他持有。删除 X 的历史并清空回收站；先删甲并保存；关页重开乙读回 X；再删乙并保存。  | 清空后甲、乙均能读回 X；删甲仅释放甲的位置，乙仍能从历史读回 X；删乙并保存后最后一处引用解除，X 进入 GC 并确认 COS 原件已删除；Y 仍完好可读。         |
| 跨画布与归档保护    | 两张画布（或一个已归档项目与一张活动画布）持有同一 `assetId`，删除历史并清空回收站。仅在活动画布删节点并保存，保留另一张或归档项目。                                                | 活动画布释放位置后，另一张画布与已归档项目仍持有有效引用，原件**不得**被 GC 清理，重开仍可读回原件。                                                  |
| 30 天到期与冻结快照 | 批内放入无引用与有作品引用各一对象；可控时间推进至 29 天验证恢复，再推进至满 30 天验证到期收敛；另测清空受理瞬间并发新删第三对象。                                                  | 29 天恢复成功、满 30 天不可恢复且仅无引用项进入 GC；清空只处理受理时冻结快照，并发新删第三对象保留在回收站。                                          |
| 并发竞争与故障恢复  | 构造 GC 认领与新绑定竞争；分别模拟 COS 删除超时、云端已删但数据库确认中断。                                                                                                         | 绑定先提交则保留原件，清理先认领则拒绝新绑定；异常中断后沿原清理身份按精确对象键幂等核实恢复，重试绝不扩大删除范围。                                  |
