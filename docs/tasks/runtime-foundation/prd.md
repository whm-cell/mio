# 共享运行时底座

## 本期结果与范围

为服务 A 和计算服务 B 提供一个可独立构建和部署的 `@mio/foundation`，只公开 `logging`、`errors`、`http-status`、`time`、`identifiers` 和 `hash` 六个子路径；不提供根级工具箱。现有业务 HTTP、身份、状态、持久化、消息和恢复语义保持不变。该计划已获实施授权；当前文档和源码本身不代表能力已验收。

本期不修改协议 v1、上游 DSH 或生产环境，不引入第三方运行时依赖、全局领域错误枚举、额外业务入口或付费外部调用；不提交、推送或部署。已有领域错误代码、流式媒体摘要、MD5、加密和持久时间责任保留在原领域。DSH 宿主日志及原认证遥测开关保留。

## C0 条件与依赖

用户已确认六入口、服务及护栏边界、行为保持与本地实施授权。起点为隔离 worktree 中固定提交；现有 API、认证、对话、计算服务及基础护栏规范是实施约束。依赖锁文件和本机隔离 PostgreSQL/Redis 测试能力；不依赖生产数据、真实模型或外部收费服务。当前没有阻止已授权实施的范围决定；实现后的行为、独立审查和人类接受需要在 C1 取证，不能预先视为通过。

对照基线与最终候选，分别演练新增一项安全日志字段、新增一个领域错误码及修复一次正文读取行为，记录实际改动位置、验证和维护代价。对照只说明所选场景，不把小样本推广为整体效率提升或生产质量结论。

## 设计取舍

两服务存在重复的日志、标识、摘要、错误和时间原语，且跨服务复制会导致脱敏或语义漂移；单包和明确子入口以少量构建与边界维护成本换取可共享的有限契约。最小替代是继续各自维护重复代码；本期只提取已有共性与实际消费者，不新增通用框架或全局业务模型。日志仅接受事件名及允许的关联字段，避免原始请求、凭据、cookie、签名 URL 和任意异常序列化；sink 隔离针对输出故障改变业务结果的具体风险。HTTP 读取只在 A 内合并已有实现，保留原超时、上限与授权复核，避免把领域协议或存储耦合进基础包。墙钟与单调钟分离用于避免跨重启恢复误用进程相对时间；不引入新持久状态、重试或配置开关。
