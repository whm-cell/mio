# Mio 画布接口承接 PRD

**状态**　待评审。本文规划 `miioo` 画布接入 Mio 的产品行为、接口与验收。第 1–4 期是建议的本期开发单元，第 5–8 期是可独立排期的扩展。各期新增接口均为候选，当前仅交付规划。开发授权、候选验证和业务接受沿项目的[协调协议](../../coordination.md#规划交付要求)分别记录。[任务资料入口](../index.md)

## 用户目标与首个里程碑

登录用户创建一个项目，在其中打开多张画布，连接文本和媒体节点，明确选择本节点的当前输出。关闭页面后，用户能重新看到布局、选择和在途任务，并能查明一次生成用了哪些输入。首期面向用 Mio 账号新建个人画布的创作者。剧本、分集、协同编辑、整图自动调度和全站账号迁移分别有不同的权限或执行要求，留在本规划范围外。

**第 3 期的首个业务验收点**是“手写文本 → 图片节点生成 → 选中结果 → 刷新 → 下游再次使用所选图片”。第 4 期再用模型生成的文本走通同一条链。这样在文本上下文策略确定前，也可以验收真实的画布创作流程。

| ---------------------- | -------------------------------------------------- | ------------------------------------ |

## 跨期接口约定

下面表格中的业务路径均省略 `/api/v1`。以 `/api/auth/` 开头的路径为完整路径。**复用**沿现行契约，**新增**与**扩展**在对应开发单元采纳后再纳入现行 API 文档。私有请求使用 Mio 登录 Cookie，写请求沿允许的精确 Origin 和 JSON 约定。服务端从会话取得 owner。跨用户资源按不可访问处理，错误沿 `{error:{code,message,requestId}}`。错误体里的 `requestId` 用于 HTTP 追踪，客户端写请求里的 `requestId` 标记一次用户操作。存储事务、私有对象签名与供应商提交分别遵循既有集成约束。[PostgreSQL](../../integrations/postgres.md) · [COS](../../integrations/cos.md) · [OneLink](../../integrations/onelink.md)

- **保存和重试。** 有幂等要求的创建、保存、结果写入、生成、复制和批量操作使用客户端稳定 UUID。同一用户在同一操作作用域重试相同输入时，先返回原操作或原回执，再处理新写入的版本校验。同键异参返回 409。独立编辑产生新键。客户端仅在明确知道原操作结果后更新本地版本。
- **文档与结果。** PostgreSQL 保存项目、画布文档及其 `revision`。节点以 `(canvasId,nodeId)` 定位，`nodeId` 支持前端已有的字符串标识。画布文档保存节点、草稿、参数、有序输入关系、分组与视口。可信结果由节点结果记录保存，生成来源由执行服务写入。节点另有 `currentResultId` 和 `outputVersion`。当前输出改变才推进该版本，单纯追加历史保留当前选择。GET 画布可一并投影各节点当前输出摘要，历史按需分页。布局撤销/重做只修改可编辑文档。
- **受理与结算。** 前端先完成草稿保存和所选输出登记，再发起执行。A 在短事务中核对画布、节点、`baseRevision` 与目标 `expectedOutputVersion`，冻结当时直接上游的顺序、槽位、正文或 `resultId/assetId`、版本，以及本次操作、模型和参数。上游引用只取自已保存的图。本次模型选项以受理请求为准，服务器按模型能力白名单校验。持久保存执行身份后才调用底层服务。页面刷新按原执行查询。服务在受理、下游回执、结果入库之间中断时，按原身份对账。
- **归档与删除。** 归档使项目/画布退出活动列表并停止新执行，已受理任务和本人已有资产保留。迟到结果可从原执行查询，已删除的节点不会重新出现。隐藏历史、移除目录引用、归档画布分别有独立作用域。物理删除 COS 原件需要另行定义授权与引用检查。

## 第 1 期 · 项目、多画布与保存

**C0**　确认首发是否只接新建个人画布。建议保留前端“活动项目至少有一张画布”的规则，归档项目时整体退出活动列表。用代表性图文样本确定画布写入的字节、节点及连线边界。本地序列化样例含 32 个短文本和图片节点、16 条连线，文档已有 10,266 字节，应能正常保存。Mio 默认 JSON 读取上限为 8,192 字节，需要给此入口单独设限。[文档序列化](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/canvas/CanvasDocument.js#L253) · [请求读取器](../../../src/http-request.ts)

| 接口                                                                                            | 输入、返回与副作用                                                                                                                                                                       |
| ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增 `POST /canvas-projects`、`GET /canvas-projects`                                            | 创建传 `requestId` 和名称，一个事务建立项目与首张画布，返回 `projectId, firstCanvasId`。列表按本人、搜索词和游标返回 `items, nextCursor`。                                               |
| 新增 `GET /canvas-projects/{id}`、`PATCH /canvas-projects/{id}`、`DELETE /canvas-projects/{id}` | 返回项目元信息与有效入口画布。改名和整体归档针对该项目。归档后本人可按原执行身份查询已经受理的工作。                                                                                     |
| 新增 `POST /canvases`、`GET /canvases?projectId=…`                                              | 在本人项目创建画布，返回画布 ID 和初始版本。项目内列表支持分页和搜索。                                                                                                                   |
| 新增 `GET /canvases/{id}`、`PATCH /canvases/{id}`、`DELETE /canvases/{id}`                      | 详情返回 `id, projectId, title, revision, document`。PATCH 传 `requestId, baseRevision` 和文档或标题，返回已保存版本。过期写入返回 409，告知当前版本。归档最后一张活动画布由服务端拒绝。 |

**C1 与前端**　先接 `CanvasProjects.js`、`UseCanvasProjects.js` 和 `CanvasPage.jsx` 的正式登录、建项目、打开入口，再接 `api/canvas.js`、`CanvasSaveSession.js` 的保存队列。由画布请求层把 camelCase 转为页面使用的字段，并读取 Mio 的错误体。替换 token/refresh 前置判断。把旧 `client_save_id/base_revision` 映射为稳定的 `requestId/baseRevision`。账号切换清理旧缓存和订阅。服务端校验节点唯一、父组存在且无环、有序来源指向本画布节点。新建文档为空。第 1 期保存仅接受已开放的字段，提前传入资产或结果引用时拒绝整次写入。第 2 期开放后按引用归属校验。以节点有序来源及槽位为准，按序列化规则校核重复表达的 `businessBindings`，不一致时保留原稿并报错。拖动、框选、连线、折叠与撤销沿已有本地交互，保存时统一提交。[前端保存队列](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/canvas/CanvasSaveSession.js)

**验收**　登录后建项目并模拟丢失创建响应，同键重试只得到原项目和首张画布。添加第二张，移动节点、连线、分组、缩放，关页重开后逐项一致。两个标签页从同一版本保存不同修改，后到者看到冲突并保留本地草稿。两个并发归档请求不能删空活动项目。验证确立的大小边界，超出时返回 413，原版仍能打开。另一账号读取或修改该画布不能取得内容。

## 第 2 期 · 私有资产、手工文本与当前输出

**C0**　确认面板提供的媒体类型、可预览类型和批量上限，区分本人未就绪、不可访问及暂时读取失败。建议沿用前端每批最多 200 个 ID 的行为。明确手工编辑何时成为已选输出，建议在用户提交正文或确认选材时登记。自动保存仍可保留未定稿文字。

| 接口                                                                                           | 输入、返回与副作用                                                                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 复用 `POST /assets/uploads`、`POST /assets/{id}/complete`、`GET /assets/{id}`                  | 浏览器申请上传，按签名 PUT 到 COS 后以空对象确认。持久引用为 `assetId`。现有 ready 文件下载地址有效五分钟，具有 attachment 语义。                                                                                                                                        |
| 新增 `GET /assets`、`POST /assets/resolve`                                                     | 扁平选择器按本人、媒体类型、搜索词和游标读取。批量解析传 `assetIds`，每个请求 ID 返回可用性和已知媒体元数据。对可展示文件分别返回短期 `previewUrl`、`downloadUrl` 与有效期。无权和不存在对客户端同样不可访问，服务故障返回可识别的临时错误。与素材库复用同一个资产列表。 |

| 新增 `PUT /canvases/{id}/nodes/{nodeId}/current-result`                                        | 接收 `requestId, expectedOutputVersion, resultId`，只允许选择本节点已有结果。旧版本返回 409。                                                                                                                                                                            |

**C1 与前端**　先替换 `canvasAssets.js` 的旧媒体中转上传，再调整 `CanvasAssetResolver.js` 和资产选择器，展示优先用预览地址，到期按 ID 重取。接入手工正文和选图动作后，`CanvasResultMutations.js` 依据服务端结果更新视图。文档写入剥离签名地址、任务身份和客户端自报的生成历史。对允许持久化的引用，创建和 PATCH 在写入前核实每个资产属于本人、每个结果属于该画布内声明的来源节点。任一校验失败时整次写入被拒绝，原文档和 revision 保持可读。新建节点从空结果开始，旧 `migrate-legacy` 调用退出新建路径。[媒体解析](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/canvas/CanvasAssetResolver.js) · [已有素材登记契约](../../apis/materials.md)

**验收**　用户直传一张图，确认后等待预览地址失效或用受控时钟模拟，重开仍显示同一 `assetId`。登记 A、B 两个文本结果并选 A，刷新后保留 A，旧标签页的选择请求收到 409。批量读取混入无权 ID 时，其余本人结果仍可展示。暂时读取失败可重试，原文档引用仍在。用 A 的会话保存含 B 的资产或结果 ID 的文档，再用 A 的同画布其他节点结果冒充指定来源，两种请求均被拒绝。重新 GET 的 revision 和正文与请求前一致。通过保存入口自报生成成功不能产生可信结果。同一手工写入重放只生成一条。

## 第 3 期 · 图片节点执行与恢复

**C0**　在已有图片路由中选定一个可验收的 `image.generate` 模型。若纳入 `image.edit`，单独确定精确路由、参考图/蒙版和操作范围。多图和下游参考图分别选择确实支持该操作的路由，可用不同模型。沿用已声明的张数、尺寸、参考图字节与异步约束。核对原任务对账身份及可恢复的条件。[图片 PRD 与已接受范围](../onelink-image-generation/prd.md)

| 接口                                                                                | 输入、返回与副作用                                                                                                                                                                                                            |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增 `POST /canvases/{id}/executions`                                               | 接收 `requestId, nodeId, baseRevision, expectedOutputVersion, operation, modelRef, parameters`。冻结输入后受理，返回 `executionId, nodeId, status, canCancel, canRecover`。同键重试得到原执行，版本不符时不产生新的生成任务。 |
| 新增 `GET /canvases/{id}/executions`、`GET /canvases/{id}/executions/{executionId}` | 按节点、状态和游标列出记录或查询单次执行。返回请求张数、已登记的 `index, resultId, assetId`、错误及可用动作。新开页面据此恢复任务和结果。                                                                                     |
| 新增 `POST /canvases/{id}/executions/{executionId}/recover`                         | 对可恢复的原执行继续限次查询或从已保存文件恢复结果登记。未知提交且无上游查询身份时保持 unknown。当前图片能力返回 `canCancel=false`。                                                                                          |
| 复用 `GET /providers/onelink/models?category=image` 与图片任务服务                  | 面板由 `image.runnable/parameters` 渲染。A 内部复用与 `POST /compute/images`、查询和恢复相同的应用服务。每个画布执行关联唯一底层请求身份和 `jobId`。                                                                          |

**C1 与前端**　把 `UseCanvasImageGeneration.js` 对 `creation_session_id`、`apiGenerateCreation` 和浏览器回写生成结果的依赖替换为“保存 → 受理 → 轮询 → 读取结果”。先落执行意图，再按稳定身份受理图片任务。回执丢失可找回原任务。服务器按 `(executionId, index)` 去重登记。成功张数不足时展示 partial 和原始序号，物化失败保留已有输出并标明能否恢复。只有节点仍存在且当前输出版本符合受理时预期，才自动选中该批首个可用结果。画布运行中仍能保存布局，编辑不会改变已冻结输入。[前端生图路径](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/canvas/UseCanvasImageGeneration.js)

执行详情保留底层阶段，便于前端决定如何提示。图片 `accepted` 表示已受理，`submitted/processing/materializing` 向用户显示处理中，`completed/partial` 展示已持久化的输出。`rejected/failed` 携带明确原因，`materialization_failed` 显示结果登记失败和已有文件，`unknown` 显示结果待核实。能否恢复由服务端按持久检查点、原上游任务及剩余查询条件判定。

**验收**　从手工文本节点连线生图，取得候选，选中第二张并刷新。在支持参考图的路由上，下一次执行的输入记录和实际送入的参考图都对应第二张。受理后改选不会影响这次输入。关页、重开或重复提交只能找到一个底层任务。隔离验证部分成功时保留原索引，迟到回填保留用户的新选择，unknown 恢复不新增供应商生成 POST。用真实开发环境的有界生成和已登记资产验证主流程。

## 第 4 期 · 文本节点执行

**C0**　决定文本按单轮输入还是继承上下文，以及切换画布时是否继续生成。建议一次点击使用独立文本轮次，按连接顺序读取直接上游的已选正文。未另填提示词时沿用前端的有序正文拼接，另填提示词时把指令和参考正文分别传入。生成可在用户离页后继续，取消由用户触发。现有会话创建由服务端分配 ID。实施前确定如何在中断后找回原会话、定位该轮正文，并限制画布文本轮次的生图工具权限。这些决定只影响文本切片。

| 接口                                                          | 输入、返回与副作用                                                                                                                                                                       |

| 扩展第 3 期执行入口、列表及详情                               | 增加 `text.generate`，复用第 2 期的结果登记与选择。Mio 内部关联 `conversationId + requestId`，按此轮回执和持久正文结算。界面按 `executionId` 恢复。                                      |

## 扩展分期

以下各期在相应用户功能排期时进入 C0。可以按直接依赖单独开发，核心创作验收止于前四期。

### 第 5 期 · 历史面板、本人复制与排序

- **C0 与接口。** 新增 `GET /canvases/{id}/generation-history`（媒体、节点、游标）和 `DELETE /canvases/{id}/generation-history/{entryId}`（隐藏条目）。读取只需源画布，加入目标时校验目标归属。新增 `POST /canvas-projects/{id}/copies`、`POST /canvases/{id}/copies`，限定本人目标项目，确定复制时的已保存版本与结果范围，建议复制结构和当前合法输出。复制受理返回 `operationId`。`GET /operations/{operationId}` 返回阶段，成功时给出新项目或画布 ID，失败时给出可核对的原因，后续打包与导入共用该入口。启用同项目排序交互时新增 `PUT /canvas-projects/{id}/canvas-order`，提交有版本条件的完整活动画布顺序。
- **C1 与前端。** 调整 `CanvasGenerationHistory.jsx` 的 `target_canvas_id` 必填逻辑。放回画布时登记已有资产引用。项目/画布复制从“响应立即含新 ID”改为等待 operation 完成后跳转，失败可查原操作。副本使用新节点/结果身份，保留合法来源，排除在途执行。归档与排序并发时提示刷新。
- **验收。** 将源画布的结果放入本人另一画布，隐藏源历史后两个画布的文件仍可打开。复制期间断线后查回同一副本，供应商调用数不增加。另一账号不能查询操作。陈旧排序返回冲突并保留当前顺序。

### 第 6 期 · 画布资产目录与批量操作

**C0**　确定项目共享集合、绑定单张画布的集合及既有项目初始化方式。就跨页选取、移除目录条目、打包的数量和字节上限、确认凭证有效期分别给出边界。

| 新增接口                                                                                                                          | 资产面板动作                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `GET /asset-collections`、`GET/PATCH /asset-collections/{id}`、`GET /asset-collections/{id}/items`                                | 按项目浏览两类集合，读取和修改名称，分页读取目录内容。                         |
| `POST /asset-folders`、`GET/PATCH /asset-folders/{id}`、`POST /asset-collections/{id}/entries`、`PATCH /assets/{id}`              | 新建文件夹，读取祖先与版本，改名，把本人已有资产加入目录，更新资产名称或收藏。 |
| `POST /asset-moves`、`POST /asset-selections`                                                                                     | 移动指定条目。按本人、集合、筛选条件建立跨分页选择快照。                       |
| `POST /asset-deletions/preview`、`POST /asset-deletions`                                                                          | 先读取拟移除范围、影响和确认凭证，确认后按原范围移除目录引用。                 |

- **C1 与前端。** 替换 `CanvasAssetLibrary.js` 与项目树的接口适配，按集合和文件夹读取游标页、祖先与版本。保留项目共享资产、各画布集合两级语义。目录条目只引用资产，真人/AIGC 素材管理继续归 `materials`。[前端集合分组](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/utils/CanvasLibraryProjects.js)
- **验收。** 同一项目两张画布和共享集合可分别浏览。移动到自身后代、跨归属移动均被拒绝。预检后范围改变或凭证过期，提交要求重新确认。移除目录引用后节点原件仍可用。跨页打包可在重新登录同一账号后查回终态，包内条目、数量和字节范围与已确认范围一致。

### 第 7 期 · 公开分享、授权复制与本地文件

- **C0 与接口。** 确定分享当前已保存版本的可见字段、媒体范围、撤销后的短链有效期和跨账号导入后的资产归属。新增 `GET/PUT /canvases/{id}/share` 管理状态与令牌，`GET /canvas-shares/{token}` 返回公开投影，`GET /canvas-shares/{token}/assets/{assetId}` 只解析该分享内可见媒体。`POST /canvas-shares/{token}/imports` 由登录用户指定本人目标并返回操作 ID。建议为获准导入的媒体建立接收者可独立使用的合法资产，再发布副本。
- **C1 与前端。** `SharedCanvasPage.jsx` 匿名读公开接口，忽略登录刷新流程，展示可公开文档与当前媒体。服务端剥离私有结果历史、执行输入快照和凭据。现有 `.miioo.json` 由浏览器导出，可内嵌本地媒体。导入合并到当前画布并重分配节点 ID。内嵌媒体先走上传，已有资产重新校验归属，再用第 1 期保存。只有将来要求“上传文件创建新画布”时再定义 `POST /canvases/imports`。[文件交换实现](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/canvas/UseCanvasFileActions.js)
- **验收。** 匿名访客可读分享媒体，无法读取作者的其他资产或历史。关闭或轮换令牌后旧入口停止签发地址，已签地址按约定到期。同一导入请求只产生一个副本，撤销来源分享后按已选归属策略核对接收者权限。本地文件合并保留原画布和内部连线，无法取得的媒体有明确提示，不创建可信生成记录。

### 第 8 期 · 视频、音频、认证素材与扩展编辑

- **C0 与接口。** 以精确操作、模型、输入规格及真实可用的结果/取消/恢复能力为单位选片。视频、音频和高级编辑扩展第 3 期 `POST /canvases/{id}/executions` 的操作白名单，继续复用查询、结果和选择。认证素材浏览复用 `GET /materials/groups`、`GET /materials/groups/{id}/materials`。用于视频执行须由后端验证本地 `materialId` 并解析上游身份。普通转码仍沿 `POST /compute/jobs`。扩图、超清、剪辑等仅在确定具体业务服务后排入相应切片。[视频 PRD](../onelink-video-generation/prd.md) · [音频 PRD](../onelink-audio-generation/prd.md) · [认证素材 Unit 4](../onelink-material-library/prd.md)
- **C1 与前端。** `UseCanvasVideoGeneration.js`、`UseCanvasAudioGeneration.js` 和编辑面板按已就绪操作接入执行接口，提供该模式要求的槽位、限制和恢复动作。已上传视频/音频可以先作节点资产。普通生成与认证素材联动独立验收。
- **验收。** 为每个开放模式用真实支持的最小规格完成一次受理、状态查询、持久资产登记和重开展示。对不支持的输入返回明确原因。认证素材的归属或状态不符时在提交前拒绝，未知状态不重发。一个模式通过只承认该模式。[素材库已接受范围](../onelink-material-library/complete/report.md)

## 验收环境与首发决策

业务联调使用正式前端入口和真实画布 ID，联调时设置 `VITE_CANVAS_DEV_MOCK=false`，资产库 mock 开关保持关闭。选两个不同账号和同一账号的两个标签页，记录前后端候选、请求/执行/资产 ID、版本、操作前后的可见状态及必要的脱敏回执。重复、并发、故障与部分成功优先在隔离回归环境用可控响应验证。模型与 COS 的业务闭环在常驻开发环境逐次执行已授权的最小规格调用，保存原请求身份、实际产物与结论。外部结果未知时保留原记录，只沿支持的原身份核对。[常驻环境与回归边界](../../local-environments.md) · [验证与接受](../../coordination.md#验证与接受)

各期接受以该期用户入口跑通、适用的归属/冲突/恢复场景通过、持久事实与用户所见一致为条件。UI 模拟、单项已有服务成果和静态检查分别说明其覆盖。已采纳的 HTTP 契约随对应实现进入所属 API 域。当前画布端到端场景均待开发和验证。

首发优先决定三件事。第一，个人新建画布能否独立上线。若要无感承接存量，先以获准样本核对旧账号到 Mio 用户、旧文档到新节点/结果、旧文件到本人资产的映射，以及在途任务的查询依据，再单独规划迁移验收。第二，按第 1 期样本确定文档容量和归档规则。第三，在第 4 期前确定文本上下文与离页行为。分享授权、打包范围与视频模式的决定分别留在对应扩展期。
