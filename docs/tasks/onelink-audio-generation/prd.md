# 万联语音、音色、音乐与翻唱 PRD

状态：原 W5 的独立需求规划，尚未启动或接受。声音样本和外部资源授权仍须按本页收口。返回[任务资料与成果](../index.md)。

## 1. 结果与范围

覆盖旧 WL-08/09：同步/异步 TTS、分段情绪/适用字幕、音色查询/设计/复刻、音乐/歌词/翻唱预处理与生成；用户可查询音色、任务和持久音频资产。非目标为配音工作台 UI、平台音色市场、未授权真人声音和 Agent 工具。

旧仓库 `backend/app/services/tts.py`、`minimax_voice_runtime.py` 的 speech-* 使用 `/minimax/v1/t2a_v2`，还包括异步长配音、文件上传/取回及音色能力；`services/music_runtime.py`、`routers/music.py` 包括 `/minimax/v1/music_generation`、lyrics_generation 和 music_cover_preprocess。这些是迁移目标依据，不表示当前账号或所有旧型号可用；原生 MiniMax 路径和业务返回须独立适配，不以普通 chat 协议代替。

## 2. 直接依赖与 C0 缺口

本人凭据、动态目录/模型身份和有来源声明沿[供应商规范](../../providers.md)，必要基线为已接受 `onelink-user-provider-catalog`（[成果入口](../onelink-integration/complete/report.md)）；任务/资产直接引用[共享候选设计](../onelink-image-generation/design.md)，核对首个消费者实际提供的接口与代码，不默认读整份图片 PRD。

C0 收口本音频切片实施范围与调用授权（O1）、`user_id` 与文件/音色关系（O2）、COS/处理环境/保留清理（O4）及精确模型/操作清单（O5）。O6 另确认合成或已获授权的复刻/翻唱样本、外部文件与音色创建/删除权限及资源保留；未授权样本不用于验证。音色和上游文件以系统 `user_id`、供应商/模型和上游 ID/来源关联；`providerConfigId`/`credentialVersion` 若保留仅作提交审计，Key 轮换不改变同一 `user_id` 资源的查询与归属；上游账号身份和删除副作用未定只阻塞相关操作。

W5 可消费已核验的共同异步机制；若先于视频相应机制实施，就在本单元交付所需最小步骤，由 W4 复用同一维护实现，不复制调度，也不等待全部视频能力完成。必要 FFmpeg/分段环境只随真实消费者接入并明确超时、关闭和制品条件，不能预设本机工具已是部署契约。

## 3. C1 实施顺序

沿[统一生命周期](../../coordination.md#当前任务的生命周期)，先完成原生 MiniMax 适配和 HTTP 200 内业务错误检查，再处理文件上传/音色 owner；同步配音与解码后扩展异步长配音查询/取回、分段合成/字幕，最后按实际依赖接音乐、歌词及翻唱。每项保存任务、外部文件和音色来源，局部失败只恢复相应步骤，不重新提交复刻或生成。

缺当前用户配置不回退其他供应商或管理员 Key；音色查询、设计、复刻及外部文件清理分别表达副作用。音频/外部资源规范、HTTP 和集成契约随对应切片在 verify 前进入候选，不把原始音色 ID 变成跨用户通用资源。

## 4. 验收与接受

共同原 A1/A2/A5/A7、真实批次与接受条件沿[共同验证约定](../onelink-image-generation/design.md#6-共同验证约定)，原 A8 要求另逐项取证：

- 两种配音模型、异步长文、支持的情绪/字幕、音色设计/复刻、音乐、歌词、翻唱各有对应结果。实施者按当前账户和操作选精确代表，不用一个音频文件代替全部能力，也不用旧模型数充当可用名单。
- 实际音频可解码，时长/格式与资产可读；歌词按文本操作断言。覆盖 hex/URL 响应、HTTP 200 内业务失败、分段部分失败和临时文件过期，不能仅验 HTTP 200。
- 跨用户音色/文件、换 Key、轮询中断、取消、复刻/生成成功后的落库失败及资源异常/清理分别验证，断言不重复供应商执行和可恢复身份。

无权限/不支持项如实登记，完整音频接受须覆盖本页全部目标或获明确处置并披露；局部切片只接受自身范围，恢复、安全和审查随切片交付。

### 5.1 数据库取舍

以实施时最新 `origin/main` 的迁移和读写代码定义目标结构，以各域实际连接的数据库及 schema 确认升级起点。`A` 分支提供语音专属 DDL、实际调用和回归样例。遇到源码不能解释的语音字段或约束，再用同事提供的定向结构交叉核实。两份资料冲突时记录字段、出处、读写路径及影响，仅暂缓依赖该含义的变更。共用表由当前拥有该表的域做增量迁移。 遇到同名异形表，先核对存量行对新约束的兼容性，再按需要分步加列、回填、验证和收紧约束。`CREATE TABLE IF NOT EXISTS` 只能处理表缺失。

2026-11-23 提供的 PostgreSQL 文件定义了 38 张表，只含结构。它能说明资产、会话和供应商共用表的形状，以及模型分类里的 `voice`。文件没有下列四张语音专表、音色条目或模型路由实例。重建语音专表时，从 A 的迁移逐项对照对应 store 的读写路径。[音色迁移](https://github.com/whm-cell/mio/blob/7002715cdcf948292adb6edc9f437d8dea3145b4/src/audio/voices/schema.ts) · [任务与作品迁移](https://github.com/whm-cell/mio/blob/7002715cdcf948292adb6edc9f437d8dea3145b4/src/audio/jobs/schema.ts)

| 对象                                                 | 由谁维护，迁入时核对什么                                                                                                                                                                                                                                 |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mio_provider_voices`、`mio_provider_voice_catalogs` | 放在供应商库。前者保存稳定 `voiceRef`、来源、上游 ID、可见性、收藏和试听资产，按 `(provider_id, source, upstream_id)` 唯一。后者是 A 的目录状态，核对私有音色资格查询仍用到的版本和快照。列表与刷新读取本地数据。                                        |

### 5.2 开发单元与接受条件

以下 C0 指开工前须定下的输入和边界，C1 指实施及其行为验收。按依赖推进，每个阶段均可单独核对。[项目协调协议](../../coordination.md#当前任务的生命周期)

**1．对齐主干和数据库起点**

- **C0** 固定最新 `main` 与参照用的 A 提交。从配置解析供应商、会话、资产和计算的实际库及 `search_path`，只读核对 `pg_catalog`。对相关表登记主干目标、现场结构、A 的消费者、附件旁证及处理决定。列类型、默认值、非空性、约束和索引分别比对。
- **C1** 从最新主干开工作分支。先预览主干已有迁移，例如 `pnpm migrate:dev conversations`。在回归库的独立 schema 演练从旧结构升级及重复执行，核实存量会话仍能读取、归档、分叉。应用到开发库前备份两个相关库并验证可恢复性，只执行目标域所需的迁移。资产库中已有的表继续在原库工作。接受条件是现行服务可通过启动结构检查，相关旧数据可读，并能指出每项语音增量将落到哪个库。[迁移入口与分库约定](../../local-environments.md)

**2．让用户能找到可用模型并选到音色**

- **C0** 确定当前账号可见的精确 TTS／复刻模型、操作及路由来源。核实初始化音色的可用清单和系统／私有音色的归属。缺少真实清单时，可用隔离样例完成开发，真实音色选择和试听保留待验。
- **C1** 复用 A 的协议适配和参数校验，接入主干的受控路由管理、验证与修订。通过 providers 显式增量迁移建齐采用的语音表和查询依赖。A 的音色查询已引用 `mio_audio_jobs`、`local_clone_job_id` 与 `preview_asset_id`，这些依赖须在开放列表时可读。实现模型发现、本地音色搜索／分页／收藏和试听引用。若导入已有试听，按来源清单校验摘要及格式，用既有资产接口绑定，可重复执行。
- **接受** 空目录可用，刷新产生零次供应商调用。有来源的系统音色可选，换 Key 后同一用户可保留标识和收藏，重新发现后的可用性按当前路由判断。私有音色跨用户无法读取，已导入的试听可通过本人资产接口播放。原有路由照常导入、修订、回退。[供应商规则](../../providers.md)

**3．用标准音色完成一次可恢复的配音**

- **C0** 以 `requestId`、`modelRef`、`voiceRef`、正文、速度、音量、声调、格式为标准输入，固定样例、模型实际限制及私有资产读取方式。采用本地排队调用同步 TTS，固定执行端和结果端的队列、消息身份及权限。
- **C1** 先保存幂等身份、已选音色和提交意图，再调用 OneLink。分别处理 HTTP 成功但业务失败、明确拒绝和提交结果未知。保存供应商输出后，经私有 COS 和计算服务完整解码、校验摘要与时长，先按固定 ID 登记本人资产，再发布作品与 `ready`。开放任务查询、取消、恢复、作品列表及详情，播放或下载时重新签发短期地址。[A 的任务实现](https://github.com/whm-cell/mio/blob/7002715cdcf948292adb6edc9f437d8dea3145b4/src/audio/jobs/service.ts) · [资产读取契约](../../apis/assets.md)
- **接受** 一段文本得到一个可解码、可从历史重新打开的作品。相同请求返回原任务，改参复用同一请求 ID 返回冲突。模拟 COS、检测、资产登记或作品发布失败后，从已知结果恢复且供应商 POST 次数仍为一。结果未知保留待核对，取消如实表达已提交的副作用。缺凭据、越权和非法输入在产生外部调用前阻止。

**4．用授权样本复刻，并通过新音色再次配音**

- **C0** 复用上一单元的任务与检测链，确认精确复刻路由及合成或已授权样本。收口样本归属、格式、时长和当次明确授权。按 A 的本地上限与模型约束取较严者，A 的参考范围为 MP3／WAV／M4A、20 MiB、实测 10–300 秒。
- **C1** 从本人已就绪资产读取样本，解码确认格式、时长及内容摘要，再走 OneLink 专用 multipart 复刻。保存上游音色身份，处理试听缺失或保存失败，随后绑定稳定 `voiceRef` 和试听资产。
- **接受** 先听复刻试听，再用这个 `voiceRef` 合成另一段正文。拒绝他人的样本、授权缺失和已变化的文件，供应商调用次数均为零。已确认创建后出现故障，只恢复后续保存。没有可用的授权样本只影响真实复刻验收。

**5．将配音接入当前会话和产品页面**

- **C0** 在 `miioo` 核对实际页面、API 请求、播放与重连行为。建议将独立音频会话表示为主干的一种 `purpose`，用现有会话机制限定工具。若前端依赖 A 的 `workspace`，先确定映射及历史兼容。确定旧会话默认行为、分叉点上的音色设置和每轮样本授权。这个决定只影响会话与页面接入。
- **C1** 将持久音色选择与逐轮快照接入主干会话、鉴权、SSE 及 DSH 单轮工具授权。页面和对话共用服务端确认后的选择。只在音频会话开放模型／音色查询、选音色、标准配音、复刻和任务查询。页面按 `jobId` 查结果，正文流式显示，音频完成后播放。沿现有分叉、归档、推理和历史重连协议联调。[现行会话契约](../../apis/conversations.md)
- **接受** “换成 B”产生零个生成任务，“用 B 重配上一条”产生一个任务。送达供应商的音色与作品快照均为 B。刷新、断线重连、切换或分叉会话不会重复提交或泄露授权。停止回复与取消音频任务可分别操作。已有普通、剧本及图片会话的工具、进度和历史回归通过。后端接口验收与实际页面联调分别记录。

### 5.3 验证、启用与回退

1. 在 `mio_regression_test` 的随机 schema 及隔离 RabbitMQ 通道运行自动化。用独立连接池和 schema 覆盖分库路径，验证空库、主干旧结构升级、重复迁移、跨用户、换 Key、重复消息与发布中断。固定视频计算的路由及确认顺序，以及已有图片和会话用例一并回归。将当前候选的代码审查、规范审阅和覆盖 `pnpm check` 的结论分别记录。
2. 在开发环境核对目标库、备份、增量预览和 Worker 就绪情况，先迁移，再部署能读取新旧记录的服务与 Worker，最后启用目标账号所需路由并接入页面。用最小规格执行一次标准 TTS，再用获授权样本完成一次复刻及复用。记录脱敏任务、资产、时长、试听及恢复结果。后台改写影响其他人的全局路由、旧历史数据迁移和生产发布另按对应范围授权。
3. 异常时暂停新的音频提交，排空或登记在途任务，保留未知提交、已创建音色及输出检查点。验证旧版本能读取现场结构与既有记录后再退服务版本，否则在保留数据的版本上前向修复。备份恢复先在隔离现场演练，跨库按同一业务时点核对资产与作品的关联。
4. 交付分别列出通过的后端单元、真实模型结果、页面联合验收和部署状态。真实供应商未验证、音色资料未到或前端未联调时，保留对应单元待验。
