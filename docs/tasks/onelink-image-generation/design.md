# 万联生成任务与受管资产候选设计

状态：承接原万联 PRD 的共同候选方案，尚未整体实现或采纳为运行契约。资产底座由[私有资产与计算服务](../compute-service/prd.md)先行；[W3 图片需求](prd.md)按实际已接受能力复用并补齐图片所需行为。视频、音频和素材需求直接引用本页所需部分，不依赖整份图片需求或原万联 PRD。各 PRD 独立执行和接受，共享设计变更仍须核对实际消费者。

## 1. 现行依赖与采用边界

身份复用[认证底座](../../auth.md)，凭据、稳定模型身份和当前目录资格沿[供应商规范](../../providers.md)及[供应商 HTTP](../../apis/providers.md)；查询/配置成功不授予生成权限。先获取当前用户 Key 的完整成功目录，再由显式 `sourceKind=protocol-reference`（协议/文档依据）或 `runtime-observation`（对应运行观察）为已发现成员补充适配；没有目录快照就保持 pending，官方文档、运行观察、旧 92 项和静态清单不能创建或替代成员。Seedream 使用同一用户的 OneLink 凭据。非文本 operation/profile、协议路径和参数尚未装配，须随首个实现切片补齐有依据的适配、准入与回归，不能把当前仅支持文本的声明入口当作媒体能力。

W1/W2 的文本验收不依赖 Seedream 目录权限、图片 profile 或 COS 现场配置。W3 首个真实切片才需要当前 OneLink Key 的图片权限和私有 A/B COS 配置；缺少这些条件时保留对应真实证据 pending，不改变 W1/W2 已接受范围。

现行[万联契约](../../integrations/onelink.md)中的固定目标、凭据隔离和脱敏原则可复用，目录/文本专属端点及限额不能直接套到媒体。持池、迁移、释放和隔离测试沿[PostgreSQL 契约](../../integrations/postgres.md)；业务不能借认证内部池或建立跨库事务承诺。HTTP 复用[共同响应原语](../../apis/index.md#运行时公共能力)，入口沿可信 Cookie、精确 Origin、输入白名单、有界正文与脱敏响应；W3 不新增图片容量策略，现有 API/COS/供应商的必要传输约束仍按各自契约执行。

候选职责为插件入口装配、生成 HTTP → 任务/资产应用服务 → 分协议客户端及受管存储；供应商服务提供一次冻结的可信配置。`src/integrations/onelink/`、`src/generations/`、`src/media/` 仅为落点建议，不预建空框架。普通业务不依赖 DSH 类型，框架边界与工具全拒绝沿[DSH 契约](../../integrations/dsh.md)；DSH Session 不是生成任务事实表，也不另建 Agent loop。新增源码/PG 所有者随消费者进入类型、构建和导入检查；只有第二个真实消费者或明确公共契约需要才引入跨供应商抽象。

## 2. 请求身份、状态与外部资源状态

任务建议持久保存系统 `user_id`、requestId、规范化输入摘要、稳定模型与精确上游 ID、operation/profile、providerConfigId、提交时的目录/适配/凭据版本、上游任务 ID/协议查询上下文和状态。`providerConfigId` 与版本只记录提交上下文，不作为外部资源归属或查询的唯一依据；外部资源始终按系统 `user_id` 关联。可信 owner/config 查询产生本地任务绑定；准入冻结同一次一致读取的资格和版本，轮换、目录移除或偏好变化不改已受理任务。已有同 owner/requestId 先核对输入：同输入返回原任务，异输入冲突，不因新资格失效重发。数据库唯一性/事务控制本地重复，不声称外部 exactly once。

候选阶段为 accepted、submitting、submitted、processing、materializing、completed、failed、unknown；cancelRequested 与 cancellationOutcome 分开表达。HTTP 接收、上游完成、资产持久和本地完成分别可观察。同步生成也建立本地任务；产物已返回而下载/落库失败，只重试取回或落库。多输出保留逐项状态与资产引用，不能用 completed 隐藏缺项。

提交前持久记录意图。POST 可能已到上游但未拿到 ID 时记 unknown，停止自动重提；已知 ID 在检查取消/执行租约之前尽力保存。恢复按系统 `user_id`、原供应商/模型和上游资源 ID 查询；Key 版本是提交上下文，不改变资源归属、查询身份或 COS 资产。供应商访问若需要当前有效 Key，只作为传输鉴权，不重新认领或删除同一 `user_id` 的既有资源。上游幂等键或按外部 ID 查询须有真实依据和验证，本地 requestId 不自动成为上游幂等保证。没有可查询身份的未知请求交用户核对，不换 ID 自动重跑。

查询、下载仅在明确总期限和次数内安全重试；生成 POST、流中断重发、创建外部资源等不能套同一重试。SDK 重试若采用须核对并限制，避免与本地策略叠乘；Profile 不自动装载全局 llm-retry。区分 429、线路未绑定、参数不支持、内容拒绝、断连/超时，保留脱敏 request ID 和事实。取消只先表示已记录请求，上游确认及不支持单列；断开 SSE 不取消任务。登录失效拒绝新操作，已受理任务和 `user_id` 资源不因 Key 轮换或撤销而改归属。Mio 不记录费用、余额、预算或退款结算。

## 3. 最小调度与资源生命周期

第一个异步消费者建立所需最小持久机制：PG 保存下次查询时间、次数和执行所有者，一次执行仅做一个有界 submit/poll/落库步骤。W3 异步图片可先提供短步骤；W4 与 W5 按实际需要扩展同一实现，W5 不等待全部视频协议完成，也不复制第二套调度。

图片和结果统一存项目私有 COS；本期不新增图片容量、本地目录或费用预算策略，也不把对象大小作为 W3 图片准入条件。不能把对话 advisory lock 当成生成跨进程 fencing；不默认加入 Redis 队列、分布式 worker、缓存或通用工作流。停止新接收、在途步骤/查询的有界收敛和资源释放随首个消费者验证；依赖按实际关系关闭，失败仍释放其他资源。FFmpeg 仅在分段音频、字幕或必要媒体检查的真实消费者出现时接入，明确超时、关闭和制品环境。

## 4. 受管资产与上游输入

先建立 owner 所属 Asset ID，调用方提交引用，服务端检查类型、格式、归属，再在供应商请求边界按协议转换为 Base64、multipart 或受限公开 URL；该转换只是出站编码，输入与结果仍以私有 COS/Asset ID 持久化。`asset://` 的素材状态与解析由素材需求提供。外部拉取限制协议、地址/重定向目标和时间；供应商鉴权头只发核准上游，不能随重定向流向任意结果地址。W3 不另设图片大小策略，输入与结果沿现有 COS/HTTP/供应商契约处理。

图片输入与结果统一使用[私有资产与计算服务](../compute-service/prd.md)的私有 COS 资产底座和稳定 Asset ID；图片输入与上游可达方式仍须在 W3 的 C0 按实际能力核对。localhost、临时 blob URL 或依赖个人隧道的地址不能当生产契约。Base64/临时 URL 结果归一持久后才登记稳定资产。下载成功、元数据提交失败仍保留可对账身份；同 task/output 唯一性防重复 Asset，孤儿临时文件有界清理。删除资产不能暗中取消外部任务或删除外部资源，已有引用不可悬空。

外部资源保存本地系统 `user_id`、供应商/模型和上游 ID；`providerConfigId`/`credentialVersion` 如保留仅作提交审计，不参与 owner、查询或认领。Key 轮换、撤销或重存不改变同一 `user_id` 的既有资源查询、归属、COS 资产或上游记录。声音、认证和素材专属生命周期分别由音频/素材 PRD 规定。

## 5. 仍须收口的共同决定

| 原项                    | 当前缺口与最小解决动作                                                                                                                                                                           | 影响范围                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| O1 实施范围与调用授权   | 文档拆分不启动业务；启动具体能力时核对本期实现范围、用户动作和调用入口。已有文本授权不自动扩大为媒体或工具授权；Mio 不实现费用、计费、预算或余额逻辑。                                           | 相应实施与真实调用入口           |
| O2 `user_id` 与在途资源 | 外部任务和资源以系统 `user_id`、供应商/模型及上游 ID 关联；Key 版本只作提交上下文。轮换、撤销或重存不改变同一用户资源的查询、COS 资产或归属；unknown 仍按原上游 ID 对账，不换 ID 重跑。          | 使用用户身份查询/恢复既有资源    |
| O4 COS 与上游可达输入   | 图片及结果统一存项目私有 COS，W3 不新增图片大小、容量或本地目录策略；仅核对稳定 Asset ID、类型/格式/归属、上游可达方式，以及异步切片需要的轮询/停机恢复。                                        | 图片输入、结果资产及必要异步执行 |
| O5 动态目录与上游变化   | 通过当前用户 Key 及时显式刷新 `/v1/models`，模型信息、成员状态和数量以最新成功快照为准；旧 92 项仅迁移参考，不作白名单、数量或适配依据。无权/无代表项保持 pending 或经用户明确处置，不删掉目标。 | 对应协议/操作的完整接受          |

这些决定不因规划交回而自动解决。必要公共规范在首个实际采用切片的 verify 前进入 `docs/integrations/`、`docs/apis/` 及业务权威页并链接消费者；目录成员和数量先由当前 Key 成功 `/v1/models` 快照确定，文档只作为协议/字段参考，运行观察只绑定已发现成员的适配。E2 候选补充多参考数组、geometry capability gate 和重复 multipart image 边界；E3 增加协议中立 async submit/query/recovery、有界状态推进和受限 Vidu 适配。真实供应商/COS 闭环与接受状态以所属成果和任务证据为准，本页仍是共同候选设计。

W1/W2 的文本验收不依赖 Seedream 目录权限、图片 profile 或 COS 现场配置。W3 首个真实切片才需要当前 OneLink Key 的图片权限和私有 A/B COS 配置；缺少这些条件时保留对应真实证据 pending，不改变 W1/W2 已接受范围。

## 6. 共同验证约定

原 A1/A2/A5/A6/A7 在各消费者核验适用部分：两个真实测试账号经公开入口，未登录、服务 token、猜 ID、伪 owner 和跨配置引用拒绝；当前目录/声明资格与版本冻结成立；解密/主密钥恢复、脱敏、目标限制和有界传输不退化。任务恢复、取消与资产失败随能力交付，不留成可跳过的尾项；断言实际出站 POST 次数，未知不自动重发。

确定性协议替身/负向测试用于精确故障和竞态，真实隔离 PG/文件与正式 Profile 验证持久化和装配，经授权供应商调用验证协议和产物；生产性能基准、容量和压测属于本期 non-goal，不由本切片给出生产性能结论。真实同步与异步 OneLink/COS 及远端 CI 按各自接受边界另报，状态以实际证据为准。普通 `pnpm check`/CI 不因机器上有 Key 自动联网，真实入口缺配置不能退回模拟后声称通过。测试资料不进入生产依赖。按“当前动态集合 → 声明的协议/能力差异 → 目标操作”维护覆盖，发现、已实现适配、真实验证分别记录，代表模型不证明全部别名/高级操作。模型选择已委托实施者，无需逐型号重复确认，不以旧目录数量限制目标。

每次真实批次绑定候选、脱敏账号、精确模型/操作、输入、上游 request/task ID、凭据/目录/适配版本、发现事实、起止、输出资产和失败/未知；Key、个人素材、原始敏感内容不进公共报告。记录调用数、并发、总时限和停止条件。迁移参考、动态目录、请求构造和真实覆盖分列；版本/网关语义变化重验受影响组合，不只改哈希迁移旧通过。不用模型自评或一次自由文本答案代替断言、回执和持久化事实；失败区分模型输出、供应商可用性/协议和 Mio 内核，不无限重试。

各独立能力的完整接受须逐项覆盖其目标清单，未验/无权/下线获得明确处置并披露；完整 `pnpm check`、源码任务的 quality-review（算法成本、未使用公共项、已有实现复用）、norms-review 及适用独立审查齐备，真实人类接受绑定候选。只完成最小切片就只交付该切片，不能声称全媒体或“万联全部完成”。Agent 工具和生产部署另行判断。

## 7. 复杂度依据

| 机制              | 具体失败与最小方案/代价                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 请求/用户身份绑定 | 并发轮换不能改变同一用户的任务和资源归属；保留 `user_id`、上游 ID 与有界恢复事实，不先造通用密钥平台。                  |
| 持久任务/短步骤   | 断连、重启和下载失败会丢失外部结果；PG 身份+状态+有界查询保留 unknown，承担生命周期责任，不先造分布式队列。             |
| 受管资产          | 临时 URL 过期和越权引用会使结果丢失；稳定 ID、owner、受限 COS 与下载，承担清理责任。                                    |
| 协议差异          | MiniMax、视频状态等无法统一成 chat；复用已有能力并补有依据的最小差异。旧 TLS 补链、地址回退和重试逐项复核，不默认迁移。 |

共同工程取舍沿[底座 DESIGN-OVER-001](../../foundation.md#已采用规则与验证)；旧 WL-11/12 的主要协议依据分别为旧仓库 `backend/app/services/asset_task_handlers/creation_video.py`、`routers/creation.py::_run_creation_video_server_step` 以及 `utils/onelink_base_url.py`、`services/onelink_error_mapper.py`、`services/http_client.py`。它们只是 2026-11-09 的迁移调查参考，不是当前可用性或上游幂等/取消保证，公共构建与测试不得依赖本机相邻旧仓库。
