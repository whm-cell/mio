# 万联异步视频与恢复 PRD

状态：实施中，2026-11-24。原详细规划候选保留为 V1–V5 的范围依据；当前已授权并实施对话入口、持久视频执行与媒体物化切片。开发库已新增18条当前目录匹配的精确路由，Vega 1.5 文生视频完成一次真实闭环；这不代表全部型号、模式、Veo、认证素材、历史联动或正式接受已完成。返回[任务资料与成果](../index.md)；完整迁移方案见[视频生成迁移与路由设计](design.md)，本地已实施切片的候选设计见[V1 实施候选设计](design-v1-implementation.md)。

## 1. 结果与范围

让独立客户端的登录用户选择本人可用视频模型与模式，引用本人媒体或已审核素材，提交一次视频生成，断线或服务重启后沿原任务继续查询，最终取得可预览、下载和再次引用的私有视频资产。Mio 是 TypeScript 服务，移植的是可供客户端消费的业务能力，不复制旧 React 创作页、Python 服务或桌面执行环境。

## 2. 直接依赖与 C0 缺口

## 3. C1 实施顺序

阶段含义沿[任务生命周期](../../coordination.md#当前任务的生命周期)。下列是被规划开发单元，均未因本次文档 C1 进入实施；仅在实际启动时建档/复用 `.work`，不预建全套执行记录。

### V1：基础契约与最小支撑

**结果/非目标**：本人视频能力投影、严格请求/回执类型、视频任务/输出/执行检查点、B 检测桥最小契约；不完成全部驱动、不开放工具/前端、不重命名全部图片表。

**C0**：取得 providers、A generations、assets、B 固定版本，确认候选 API、首个 Seedance 精确代表、输入/结果归属及资源政策。当前缺视频 driver/operation 与检测协议核实；通过源码和隔离契约调查解决，不要求预先生成成功。

**C1**：先冻结[请求/状态/数据](design.md)，再增量迁移、启动只读检查，扩展真实复用点；测双用户、唯一键、同 ID 异输入、未知字段、错误媒体、版本竞态。B 只补必要检测，输入/输出关联 owner、job、output 与摘要；原图片/转码兼容，新增源码进 harness/typecheck/build。

**DoD/接受**：F01/F03/F06/F10 契约部分及 A01/A02/A12 通过；迁移重跑/失败原子性可见，原消费者回归通过；实际规范在 verify 前采纳。可独立接受内部基础，但无生成证据不能称“视频可用”。

### V2：Seedance/Vega 普通生成与恢复

**结果/非目标**：CAP-01–03 普通输入、提交/查询、核验、COS/Asset、恢复及受支持取消；认证素材留 V5。

**C0**：V1 所需接口已冻结并可取得实现，当前精确成员有可靠路由及合法输入，私有 COS/B 检测可用。核对 1.5/2.0/2.5/Vega 的实际参数，不能共用错误上限。缺路由依据先调查，缺真实回执属于 C1。

**C1**：文生 → 首/尾/首尾帧 → 混合/视频参考接同一执行器，冻结有效声音/水印；测意图到上游 ID 落库、取回/检测、逐项 Asset 故障窗口，再经正式用户 HTTP 做短时长小规格真实闭环。覆盖轮换/禁用、目录移除、停止/重启，不重发 POST；回归图片和相关 assets/providers。

**DoD/接受**：本切片目标组合和 A01–A10/A12/A13 有证据；未验版本/模式单列，一个样例不代表全 Seedance/Vega。普通切片与认证/历史分开接受。

### V3：其余协议与基础模式全量对账

**结果/非目标**：CAP-04–09 的 Kling、Vidu、Veo、HappyHorse 和多镜头/多帧可达性对账；不含数字人、动作控制及非 OneLink 直连。

**C0**：复用 V2 提交/物化机制，每族有精确目标清单，确认状态、查询身份、取消和下载方式。Vidu multiframe 无开放代表时记“分支存在/入口未开放”，可靠依据具备后才启动该组合。

**C1**：逐族窄驱动与载荷/回包夹具；保留 Kling 2.5T 尾帧/声音禁用、Vidu q2/q3 与主体命名差异，验证 Veo operation/受保护下载和 HappyHorse 精确 ID/音轨。每族经用户入口真实闭环与差异验证，加入共享恢复回归；公共文件由唯一写入者串行集成。

**DoD/接受**：A01–A10/A12/A13 与目标矩阵逐格收口，未知/冲突 ID 不进入成功，鉴权不泄露。无权/无代表/失败继续 pending 或经用户明确调整目标，不能删行后宣称全量。协议族可独立接受，不抹去 V2 结果。

### V4：结果消费、历史和旧数据交接

**结果/非目标**：任务结果列表/详情、脱敏输入快照、私有预览/原件下载、再次引用，接统一历史/持有，形成 M7 规格；不含客户端 UI、个人库目录/收藏、旧库导入及镜头 CRUD。

**C0**：稳定 task/output/Asset 已具备，核对 U1 幂等写入、墓碑及引用入口的真实就绪/接受。未就绪仅推进任务消费和交接，历史完整接受阻塞，不创建替代历史表。

**C1**：按 `(businessTaskId,outputIndex)` 登记有效输出，失败/进行中不入历史；故障补写先查墓碑，来源与真实完成时间可追溯。任务索引与全局历史筛选分开，预览与原件分别表达，回填重验已失效输入。定义旧 owner/UUID、源删除/完成时间、在途归档及数量闭合映射。

**DoD/接受**：A08/A09/A11–A13 和 U1 交集通过；删历史不破坏作品持有、不复活墓碑、不自动进个人库，M7 去向/计数可执行。U1 未就绪只接受明确任务消费切片，历史保持 pending。

### V5：认证素材与联合接受

**结果/非目标**：CAP-10 的认证图片接对应 Seedance 模式，分别验普通与认证输入，最终矩阵对账；视频/音频认证等 ML-09，不重建认证服务。

**C0**：相应模式、ML-06、本人 Active 解析/持有就绪，核对 U1/素材删除竞态；仅认证图片就绪时只启图片联动，需真人扫码的输入按本人配合处理，不编造审核。

**C1**：提交前核对并建立在途持有，以本地 Material ID 解析冻结 `asset://`；处理中删除/撤销和完成释放按材料契约协调。完成匹配模式有界真实生成/同 ID 恢复，联合回归普通图/素材生命周期；越权、拒绝、过期输入为 0 POST。

**DoD/接受**：A01/A02/A05–A13 的适用部分、ML-06 与 CAP-10 有证据；普通、认证图片及后续认证音视频分别报告。本期目标全收口、检查/质量/规范与真实接受齐全后才声明完整本期能力，不推导工具/生产上线。

## 6. 范围处置与工程保护

旧页的 5 并发、18 条分页、localStorage/SSE、session/shot 回绑及失败删除占位卡仅为源行为。目标保留真实任务/失败，不依赖这些前端实现；有界 GET 支持观察恢复，不为复刻旧页另建 SSE/通知平台。清历史、删除 Asset 与取消任务互不替代。

生成 POST 不自动重试，查询/下载各自有界。Key 轮换/禁用/目录移除不改系统用户资源归属；缺当前可用鉴权时保留访问受阻，不偷用旧 Key 或自动换供应商。错误不按原始文字猜费用/余额，不复制网关回退。

视频生成结果须有真实媒体核验；这是模型输出责任，不改变统一资产库 U2 对人工 MP4/MP3 上传“轻量校验、深度探测置后”的边界。B 仅对原媒体重试，不触发生成 POST。

## 7. 旧数据迁移交接

M7 在旧快照上确定 owner、GenTask/Asset/会话镜头、精确模型/模式、输出索引、文件身份、真实完成时间和删除状态，建立稳定映射；未知时间为 null，缺文件/无法映射列残留，不能猜测补齐。

有效成功输出写统一历史与必要业务持有；已删历史写不可复活墓碑；失败/文本/封面不入成功历史；在途/未知旧任务仅可追踪归档，禁止自动提交。对账满足“源成功输出 = 新历史 + 已删墓碑 + 无法映射残留”，任务/媒体/引用数量分别核对。旧创作会话/镜头表另由业务需求决定，视频引擎不将它们设为生成前置，也不代替 M7 完成。
