## 1. 结果与范围

覆盖旧 WL-08/09：同步/异步 TTS、分段情绪/适用字幕、音色查询/设计/复刻、音乐/歌词/翻唱预处理与生成；用户可查询音色、任务和持久音频资产。非目标为配音工作台 UI、平台音色市场、未授权真人声音和 Agent 工具。

旧仓库 `backend/app/services/tts.py`、`minimax_voice_runtime.py` 的 speech-* 使用 `/minimax/v1/t2a_v2`，还包括异步长配音、文件上传/取回及音色能力；`services/music_runtime.py`、`routers/music.py` 包括 `/minimax/v1/music_generation`、lyrics_generation 和 music_cover_preprocess。这些是迁移目标依据，不表示当前账号或所有旧型号可用；原生 MiniMax 路径和业务返回须独立适配，不以普通 chat 协议代替。

### 5.2 开发单元与接受条件

开发顺序为主干基线、数据库与路由、音色目录、标准配音、声音复刻、音频会话、前端联调。前端可在接口确定后开始适配。C0 明确该单元的输入、边界和待决项，C1 实施并验证用户可观察的结果。真实音色或样本暂缺时，隔离开发可以继续，受影响的真实验收保留待验。[项目协调协议](../../coordination.md#当前任务的生命周期)

**1．从最新主干建立开发起点**

- **C0** 固定主干与 A 的提交，列出要移植的音频专属模块，以及要按主干接入的供应商路由、资产、RabbitMQ、插件装配、会话和前端接口。核对供应商／会话库、资产／计算库的实际连接和相关旧记录形状。
- **C1 与验收** 从最新主干建工作分支。预览主干现有迁移，例如 `pnpm migrate:dev conversations`。在隔离 schema 上演练旧库升级和重跑，核验主干启动、旧会话读取、归档和分叉，并列明每张语音表的归属。开发库实迁前备份对应库，恢复演练使用隔离现场。[分库与迁移入口](../../local-environments.md)

**2．落语音四表，打通模型路由**

- **C0** 确认四表复用供应商库，成品与样本复用资产库。核对 `audio.tts`、`audio.clone` 和目录操作 `audio.voices.list` 的路由语义。运行时按本人配置和精确模型声明准入。模型可见、路由启用和真实验证分别记录。
- **C1** 把 A 的 `src/audio/voices/schema.ts`、`src/audio/jobs/schema.ts` 接入主干 providers 的迁移与启动检查。同步修订路由导入校验、类型、路由表、验证表和修订记录。落实 CLI 导入及当前后台对所选操作的读写路径。单独移植 A 的两处路由约束会让 `mio_provider_model_route_revisions` 在写入 `audio.tts` 时触发 `23514`。目录查询还依赖 `mio_audio_jobs`、`local_clone_job_id`、`preview_asset_id`，开放目录前须有这些表列。

**3．初始化音色并开放本地音色库**

- **C0** 音色清单可以从现有材料起步。`miioo` 收录了 603 条 MiniMax 展示条目，对应 592 个不同的上游音色 ID。优先选用当前账号已有可核实依据的一项。若只有展示资料，先在受控测试用户下取一个候选 ID，待第 4 单元用精确模型实际合成后，再按核验结果启用。试听文件单独验证来源和使用权。仅有名称、标签或上游 ID 时，真实可用性仍待核实。[前端音色清单](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/docs/minimax-official-voices.md) · [展示字段的用途](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/creation/MinimaxOfficialVoiceMetadata.js#L1-L7)
- **C1** 将选定音色按本人供应商配置、`source` 和上游 ID 幂等登记为稳定 `voiceRef`。为当前模型、本人音色列表／详情／搜索／收藏／刷新装配 `/api/v1/audio` 接口。刷新只重读本地库。有已核实的试听时，导入私有 COS 并绑定本人预览资产。A 的试听导入脚本要求音色及匹配的目录状态已存在，须按采用的目录规则核对或适配。缺试听时显示无预览。
- **验收** 空库返回空列表，有来源的测试音色可查可选，重跑不重复建音色，刷新产生零次供应商调用。换 Key 后保留本人标识和收藏，按当前路由重新判断可用性。他人不能读取私有音色。若真实系统音色暂不可用，保留此项待验，可先用第 5 单元产生的授权音色验证配音。

**4．完成标准配音、资产发布及故障恢复**

- **C0** 确定一个受支持的 OneLink TTS 操作、媒体格式和测试输入。短文、长文都走 `POST /api/v1/audio/jobs`，使用 `requestId`、`modelRef`、`voiceRef`、`text`、`mode=standard` 和可选参数。校验速度、音量、声调、格式和正文预算，取本地与模型较严限制。
- **C1** 先接 A 的 `contracts/compute/src/audio.ts`、独立音频队列和 Worker 的 `audio.inspect.v1`。Worker 核对对象身份并完整解码，发布结果获确认后再确认消费。再接 `src/audio/jobs`、OneLink 适配和插件 HTTP 入口。先持久化幂等身份、输入快照和提交意图，再发一次供应商 POST。拿到输出后保存检查点，写入私有 COS，核对摘要和实测时长，按固定 `assetId` 向资产库登记，最后在供应商库提交作品和 `ready`。
- **验收** 查询 `jobs/{jobId}` 及 `records/{recordId}`，用本人资产接口取得短期地址。关闭页面再打开历史仍能播放。相同请求复用原任务，同 ID 异输入冲突。覆盖 HTTP 200 内业务错误、提交结果未知、取消、重复消息，以及 COS、媒体检测、资产或作品登记失败后的恢复。未知提交不重发，已有输出只补后续步骤，成功作品和资产各一份。[A 的任务实现](https://github.com/whm-cell/mio/blob/7002715cdcf948292adb6edc9f437d8dea3145b4/src/audio/jobs/service.ts) · [资产读取契约](../../apis/assets.md)

**5．完成授权声音复刻与后续配音**

- **C0** 确认复刻路由和合成或已授权样本。复用现有资产上传、完成接口和第 4 单元的检测链。参考 A 的 MP3／WAV／M4A、20 MiB、实测 10–300 秒限制，按实际模型取更严边界。
- **C1** 调用 `POST /api/v1/audio/voices/clone`。提交前核查当次授权、样本归属、就绪状态、格式、时长及摘要，再走 OneLink 的 multipart 复刻。上游确认创建后，先保存其音色身份，后续据此继续发布试听、音色和作品。试听缺失时保留确定的创建事实。
- **验收** 用户能听到试听，并用新 `voiceRef` 再生成另一段正文。无授权、跨用户或内容已变化的样本触发零次上游提交。已确认复刻后发生存储故障，恢复不会重复创建音色。

- **C0** 建议用现有 `purpose` 表达独立音频会话。先定创建与列表契约、旧会话默认值、分叉时音色选择的取值，再判断是否有实际客户端需要 A 的 `workspace=audio` 映射。当轮的样本授权限定在该轮。

- **验收** “换成 B”产生零个任务，“用 B 重配上一条”产生一个任务，供应商收到的音色与作品快照均为 B。刷新、断线重连、分叉不会重复提交或继承样本授权。停止回复和取消音频任务可独立操作。回归已有普通、剧本和图片会话的历史、推理与工具进度。[现行会话契约](../../apis/conversations.md)

### 5.3 验证、启用与回退

1. **随单元回归。** 将 A 的语音用例按主干接口迁入，在 `mio_regression_test` 的随机 schema 和隔离 RabbitMQ 通道运行。供应商、COS 使用受控替身，媒体检测使用实际解码。用独立连接池和 schema 覆盖分库发布，验证旧结构升级、重复迁移、越权、换 Key、消息重投、停机和恢复。同步回归固定视频计算、图片及会话。对干净候选完成代码质量审查、规范审阅和覆盖 `pnpm check` 的验证。
2. **开发环境真实联调。** 核对两个目标库、备份、迁移预览和 Worker 权限。先执行相应域的增量迁移，再部署兼容新旧记录的服务与 Worker，最后受控启用相应语音路由、接入页面。用最小规格做一次标准 TTS，再做一次获授权复刻并用新音色再配音。保留脱敏的任务、资产、实际时长、播放及上游调用次数。
3. **启用与回退。** 新提交异常时先暂停语音准入，核对在途、未知及已返回结果的任务。保留音色、音频文件和输出检查点。核实旧服务能读取现场记录后方可退版本，否则保留数据做前向修复。需要恢复备份时先在隔离环境演练，按一致业务时点核对两个库中的作品和资产。
4. **交付。** 分别报告结构迁移、静态／隔离回归、真实供应商、产品页面和部署状态。对已验证的单元登记实际候选与接受结果。某个模型、试听或客户端仍待验时，单列对应缺口。生产发布按其部署范围安排。
