# Worker 视频探测分发与占槽

```mio-change
{"version":1,"type":"fix","section":"目标与边界"}
```

开启观测的 Worker 要能消费独立 `video.probe` 消息并按真实占用向管理台报告。隔离 RabbitMQ 验证发现，共用命令通道时 32 条等待编码的命令可占满预取额度。即使探测槽可用，后续探测也无法送达。用户确认采用独立探测命令队列和专属命令死信，探测结果仍使用现有视频结果队列。本轮候选待验证及接受。

## 行为

- 普通与开启观测的 Worker 分别使用独立探测命令通道与严格解析，旧通道保留已路由探测的排空处理。
- 探测通过共享总槽与 probe 槽准入。分别核验编码暂停、探测 HOLD、等待后恢复与停机。下载前核验字节与工作目录空间，保留每条命令的独立临时文件。
- 同一进程并行收到相同消息时共用一次探测和结果确认。内容冲突进入拒收路径，结果未确认时由 broker 重投。回执绑定命令、任务、输出、attempt 和源快照。
- 遥测使用独立的 `video.probe.v1` 执行身份，记录实际槽位和阶段。A 严格验证包含任务和 attempt 的探测身份。独立管理台从现有管理 API 展示快照、执行列表与时间线。

## 验证

用隔离 RabbitMQ 验证普通和观测路径、32 条编码待槽时探测仍送达、旧消息重投排空、严格消息拒收与结果确认后 ACK。用本机 FFmpeg 及临时存储验证探测、占槽、重投和清理，通过 A 遥测解析、历史查询及独立管理台检查展示。验证迁移的绑定顺序、撤销边界及角色权限。以绑定本轮候选的验证与接受材料为准。
