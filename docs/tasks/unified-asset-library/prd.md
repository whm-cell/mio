# Mio 统一资产库 PRD

**状态**　产品已确认四个菜单及清空后的引用保留规则。本文为待评审的开发安排，四期接口和前端联调均待实施。资产库服务整个账号，画布、创作和漫剧工作流按各自排期接入。[任务资料入口](../index.md) · [画布接口承接 PRD](../canvas-integration/prd.md)

## 用户能做什么

| 菜单     | 内容与操作                                                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 全部资产 | 浏览本人各业务成功保存到 COS 的持久文件，包括手动上传、生成和转码成品。可收藏、取消收藏、移入回收站。                                                              |
| 我的资产 | 浏览本人收藏，可选用和取消收藏。原文件移入回收站或回收站已清空，已有收藏仍能打开，也能从收藏选入新作品。                                                           |
| 回收站   | 浏览本人从全部资产删除的条目，可清空。每张卡片保留原上传日期，可另显示移入时间。恢复、自动过期和单项永久删除另行排期。                                             |
| 认证菜单 | 保留现有真人及 AIGC 素材的分组、认证和操作入口。存在本人 COS 原件时，通过 `sourceAssetId` 关联普通资产。仅在供应商侧存在的素材仍通过 `materialId` 在认证菜单读取。 |

前三个菜单统一按**首次成功登记持久文件的上传时间**筛选、倒序分页、逐日展示。同一文件在 11 月 1 日上传、5 日收藏、8 日删除，三个列表都归在 11 月 1 日。首版按北京时间（`Asia/Shanghai`）计算自然日，服务端保存带时区的时间点。筛选首尾日期均包含在内，查询至结束日期次日零点之前。

## 文件、列表条目与作品引用

现有 `mio_assets` 已登记所有者、稳定的 `assetId`、对象键、类型、大小和上传状态。生图与转码也会把已核实的成品登记到这张表。它承担方案中 `mio-cos` 的源资源职责，保留已有 `assetId` 和业务外键。COS 保存字节，数据库保存受控对象定位信息，前端按需取得短期签名地址。[资产表](../../../src/assets/schema.ts) · [图片结果登记](../../../src/generations/store.ts) · [转码结果登记](../../../src/compute/store.ts) · [资产 HTTP 契约](../../apis/assets.md)

| 数据                 | 拟议持久关系与约束                                                                                                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 源文件               | 每个归属明确的最终文件登记一次 `owner + assetId`、上传时间和业务来源。同一任务输出或同一上传确认重试都复用原身份。临时上传与其正式副本合为一项。每次独立成功上传可有自己的身份。                         |
| 全部资产及回收站条目 | 同一列表条目保留 `entryId、owner、assetId、上传时间`，状态依次为在库、已移入回收站、已清空，另记删除时间。清空移除本人的可见回收关系。仍有外键需要时可留不可见的来源记录。                               |
| 我的资产             | 单独记录 `owner、assetId、来源 entryId、收藏时间`。同一用户对同一文件最多一条收藏。来源与文件、用户必须匹配。读取与选用直接验证收藏和文件，无需来源条目仍在全部列表。                                    |
| 业务引用             | 保存作品、可信节点结果、仍可重开的历史或在途任务时，由所属服务登记作品身份、使用位置和 `assetId`。替换或解除该处绑定只释放这一处。仍有效的认证素材与本地文件的绑定也计入保护。纯审计用历史可只保留身份。 |

数据库按实际读法建索引。列表按用户、条目状态、上传时间和稳定 ID 查一页，收藏唯一键覆盖用户及文件，业务引用可由源文件反查。收藏页同样按原上传时间排序。C0 用代表性账号的常见和稀疏收藏量、跨日翻页和引用反查核对执行计划，再决定是否需要额外索引。[PostgreSQL 集成约定](../../integrations/postgres.md)

### 清空与最后一个引用

以全部条目 **3** 指向源文件 **5** 为例。用户收藏了 5，并把它选入海报画布的一个手工媒体节点。该节点是这份文件在作品中的唯一使用位置。

| 操作完成后                   | 全部资产 | 我的资产 | 回收站 | 海报及 COS 原件                         |
| ---------------------------- | -------- | -------- | ------ | --------------------------------------- |
| 从全部资产删除 3             | 隐藏     | 可选用 5 | 有 3   | 海报可重开，保留 5                      |
| 清空回收站                   | 隐藏     | 可选用 5 | 空     | 收藏与海报各自保留 5                    |
| 取消收藏                     | 隐藏     | 隐藏     | 空     | 海报仍引用 5，保留原件                  |
| 在海报中删除该节点并保存成功 | 隐藏     | 隐藏     | 空     | 5 进入清理，核实 COS 结果后才记为已清理 |

只要条目仍在全部资产或回收站，原件就应保留。清空时已经没有有效引用的文件可直接进入清理。清空后受保护的原件在最后一个有效引用解除时重新检查，即使回收站条目早已消失。本人清空回收站不会撤销真人认证、远端素材、其他账号的权利或其他作品的绑定。[现行认证素材契约](../../apis/materials.md)

| ------- | -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 第 1 期 | 全部资产按上传日浏览，已有认证菜单可用       | 私有上传、成品登记、存量归属和时间口径                                                       |

以下业务路径统一省略 `/api/v1`。标为**复用**的接口已有契约，其余属于规划。身份取 Mio 登录 Cookie，用户只能访问自己的文件。写操作遵循允许的 Origin 和相应方法的输入校验。`entryId` 标识列表条目。收藏、移入回收站以及作品引用都使用卡片返回的 `assetId`，临时预览或下载地址只用于展示。[现行资产接口](../../apis/assets.md)

### 第 1 期 · 统一入库与全部资产

**C0**　盘点全部为用户写 COS 的入口，逐一标明归属、最终文件和成功登记点，首批覆盖手动上传、图片生成、视频转码。手工上传的现有 `created_at` 是申请时间。存量优先从可核实的完成事实回填上传日，只有申请时间的记录评审替代口径并注明来源。不能确定 owner 的对象单列对账。回填可重跑，并与新写入按 `assetId` 去重。[现有上传与成品流程](../../integrations/cos.md)

| 接口                                                                                | 行为                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 复用 `POST /assets/uploads`、`POST /assets/{id}/complete`、`GET /assets/{id}`       | 申请取得 `assetId, uploadUrl`，浏览器签名 PUT 后提交空对象确认。核实原件并转为 ready 后才进列表。任务成品在原业务成功登记时入库。既有上传状态查询及短期下载沿现行契约。                                                                             |
| 新增 `GET /assets?view=all`                                                         | 接收 `from、to`（自然日）、`cursor、limit`，以及供选材的可选 `mediaType、q`。返回 `items, nextCursor`，每项含 `entryId, assetId, filename, contentType, size, uploadedAt, uploadDay`。按 `uploadedAt、assetId` 双键倒序，游标绑定账号、视图及筛选。 |
| 复用 `GET /materials/groups`、`GET /materials/groups/{id}/materials` 及现行认证操作 | 保留真人和 AIGC 菜单。有本地来源时按素材服务关系和权限展示标记。`sourceAssetId` 为空的远端素材保留在认证菜单，认证状态由素材服务判定。                                                                                                              |

**C1 与前端**　把登记接入所有已确认的业务写入点，成功产物与列表条目一致落库。在 `miioo` 的 `AssetsPage.jsx` 接入全部资产面板，保留认证面板。第 2 期补齐其余两个菜单，用四个新入口替换原来按项目、创作和画布分类的入口。旧数据按已核实的用户及资产映射接入。日期范围或账号改变时清除旧游标、结果和在途响应。按 `uploadDay` 合并相邻页的同日组，区分加载失败、空结果和末页。[现有资产页](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/pages/AssetsPage.jsx)

**验收**　同一测试用户上传一张图、生成一张图、完成一个转码，全部资产各出现一项，分别能追溯到原 `assetId`。重复确认、成品回执重放、重复回填均保持一项，失败上传和 staging 对象不出现在列表。用两个账号、北京时间午夜前后和相同时间戳的文件验证归属与日期，缩小页长连续翻页，同日标题合并且无重漏。核对真实认证菜单仍可读取已有组，远端独有条目没有虚构的本地下载。

### 第 2 期 · 收藏与回收站

**C0**　使用“条目 3／文件 5”的例子对齐三个菜单的权利。确认新收藏只能来自本人仍在全部列表的文件，从已有收藏选用或取消不依赖来源是否仍可见。软删除只更改列表归属。前三个菜单均以 `uploadedAt` 筛选及分组。

| 接口                                                                       | 行为                                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 扩展 `GET /assets`                                                         | `view=favorites` 与 `view=trash` 复用第 1 期的筛选、排序、分页和卡片。列表增加收藏状态，回收站可带 `trashedAt`。仅有回收站条目的资源用于管理浏览，不能从该视图发起新选材。                                                                      |
| 新增 `PUT /assets/{assetId}/favorite`、`DELETE /assets/{assetId}/favorite` | 路径 ID 为 `assetId`。设置或取消本人的收藏，返回 `isFavorite`。每次独立意图使用新 `requestId`，同一键重试回放原动作，不能覆盖随后发生的相反动作。已有收藏在来源移入或清空回收站后均可取消。                                                     |
| 新增 `POST /assets/{assetId}/trash`                                        | 前端用卡片的 `assetId` 发起请求，正文传稳定 `requestId`。服务端按当前用户和源文件定位活动条目，返回 `entryId, assetId, trashedAt`。示例中传源文件 5，移入回收站的是条目 3。同一请求回放原回执，列表中只出现一条。保留原件、已有收藏和业务引用。 |

**C1 与前端**　四菜单分别保留自己的选中项和翻页状态。星标以服务端结果为准，收藏或取消后同步全部与我的列表。从全部删除成功后移出该卡并刷新回收站，允许同一资产同时出现在我的资产和回收站。取消收藏只移出我的列表。网络失败保留原卡和可重试动作。

**验收**　按顺序执行上传、连续收藏、移入回收站、关页重开、从收藏读取、取消收藏。逐步核对三列表的成员、原上传日与同一 `assetId`。只产生一条收藏和一条回收关系。回收站仍有条目时原件保留。取消后重放较早的收藏请求，刷新后仍是未收藏。另一账号用相同 ID 列举、收藏或删除均不可取得或修改该文件。

### 第 3 期 · 业务选材与持久引用

**C0**　资产库与画布共同确定 `assetId`、选材和重开的授权条件、可预览类型与批量上限，用一个节点和同图两个节点的例子约定使用位置何时建立、何时释放。梳理已上线消费者的现存引用，包括对话图片、生成或转码任务、仍有效的本地认证绑定。创作和漫剧工作流按各自保存入口另行接入。[计算契约](../../apis/compute.md) · [认证绑定](../../apis/materials.md)

| 接口或写入入口                                            | 行为                                                                                                                                                                                                                                                                                                                                                          |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 复用 `GET /assets?view=all`、`GET /assets?view=favorites` | 选择器按本人账号、日期和媒体类型找图，只提交稳定 `assetId`。取消收藏或更改列表不会改写作品里已经生效的绑定。                                                                                                                                                                                                                                                  |
| 新增 `POST /assets/resolve`                               | 接收 `assetIds`。重开作品时带已保存的业务上下文，例如 `canvasId`。逐项返回 `assetId, availability`、已知元数据，以及可展示文件的短期 `previewUrl, downloadUrl, expiresAt`。先校验文件属于本人。从选择器解析时核实活动条目或有效收藏，带作品上下文重开时核实作品归属及已保存的绑定。缺失和无权对外同为不可访问，临时故障可重试。客户端自报上下文不能取得权限。 |
| 各业务已有或规划中的保存、替换、移除入口                  | 所属后端在作品或可信结果保存成功时写入引用，只释放实际消失的使用位置。并发版本冲突、校验失败或保存回滚时保留旧引用。同一保存重试只产生一份绑定。冻结的任务输入独立持有至任务可安全释放。                                                                                                                                                                      |

**C1 开发顺序**

1. **资产库先交付服务端能力。** 复用第 1 期的稳定 `assetId` 和全部列表、第 2 期的收藏与回收关系，实现 `POST /assets/resolve` 的选材和作品重开两条路径。向作品服务提供随业务写入登记、释放、反查使用位置的能力。新选材须有活动条目、有效收藏或服务端核实的业务复用授权。单项状态查询、下载签名、上传确认回放和任务输入也须遵守对应授权。[现行资产接口](../../apis/assets.md)
2. **画布可并行开发。** 画布第 1 期已有真实 `canvasId` 和带版本的保存入口后，第 2 期可先做手工文本、结果历史、当前输出和选择器交互。资产服务可联调后，把选择器、节点结果登记和文档保存接到真实服务。地址到期按原 `assetId` 重取，临时失败时保留节点及其绑定。节点 `resultId` 和 `currentResultId` 由画布管理。[画布第 2 期](../canvas-integration/prd.md#第-2-期--私有资产手工文本与当前输出)
3. **共用一份验收记录。** 资产侧的解析与引用登记可用后，即可联调。两期的选材与持久引用能力以正式画布保存和重开均通过为接受点。原件物理清理留在资产库第 4 期，其他作品入口随对应业务验收。

#### 哪些操作会解除引用

| 用户操作或服务事件                                         | 对原件的影响                                                                                                                                                                                           |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 预览、批量解析、取得签名、在选择器勾选或拖入尚未提交的草稿 | 仅临时读取。刷新、关页和地址到期都不改变持久引用。                                                                                                                                                     |
| 确认节点媒体结果，或成功保存含资产位置的画布文档           | 节点结果 `POST` 成功时即保护该结果使用的文件，无需等待下一次整图保存。文档 `PATCH` 只提交该版本实际新增、移除或替换的位置。业务写入和对应引用同成同败，同键重试只生效一次。                            |
| 删除手工媒体节点并保存成功                                 | 解除该节点及仅能经它重开的手工结果对原件的引用。同一画布的其他节点、结果或槽位逐处保留。仍可独立重开的历史、其他作品和已冻结的任务输入各自保留引用。保存失败、版本冲突或仅在本地撤销均维持已提交状态。 |
| 切换当前输出、隐藏历史、断开下游连线、归档画布             | 仍可重开的源结果继续持有原件。若某个已保存的独立输入槽随断线实际移除，成功保存只释放该槽。                                                                                                             |
| 从全部资产移入回收站、清空回收站、取消收藏                 | 移入只变更列表位置。清空只移除受理时本人回收站快照中的关系。`DELETE /assets/{assetId}/favorite` 成功只释放本人的收藏。清空后，无论最后解除的是收藏还是作品位置，都触发同一套原件清理检查。             |

同一文件在同一画布出现两次，服务端须能按节点及具体结果或槽位分别释放。可独立重开的历史由所属业务保留，直到该结果按其规则正式移除。任务确认后续执行和恢复都不再需要原输入时，才释放冻结输入。认证素材成功解除与本地源文件的绑定时，只释放该认证引用。

#### 两期的联合验收

1. 在正式前端上传并收藏图片，将其移入回收站，暂留回收条目。先在本人画布保存一个空媒体节点，再从“我的资产”选图并确认。节点结果登记成功后、下一次整图保存前，应已能核对 `resultId` 对应的引用。移动节点并保存，记录 `assetId`、`canvasId`、`nodeId`、`resultId` 和画布版本。
2. 取消收藏，让旧签名到期，关页后在无缓存会话重开原画布。服务端以 `canvasId` 和已存绑定签发新地址，能读回与上传样本一致的原件内容。用同一账号的另一张无绑定画布和同一 `assetId` 尝试解析或登记新结果，在没有其他选材授权时，两条路径都应拒绝且无新绑定。
3. 用原 `requestId` 重放成功的写入，仍只有原结果和使用位置。用旧版本提交删节点，收到 409 后，服务端版本、结果和引用与冲突前一致。另用两张都已绑定同一文件的画布，从一张成功移除只影响该画布。批量解析混入本人合法 ID、缺失 ID 和他人 ID 时，仅合法项得到地址。

本轮回收条目仍保护原件。资产方和画布方共同核对页面、持久使用位置和新地址实际读到的内容，证明已保存作品可以按其权限重开。清空后的保留和最终物理删除按第 4 期另取证。

### 第 4 期 · 清空回收站与原件清理

**C0**　列明会继续读取原件的入口、在途任务、认证绑定、历史外键及存量对账结果。尚不能判定引用的文件暂缓物理清理。确定可清理的私有桶、最终对象键范围及最小删除权限。现行清理只针对到期 staging，正式 raw／derived 原件清理属于这一期新增的外部副作用。[COS 清理边界](../../integrations/cos.md)

| 接口                                              | 行为                                                                                                                                                                                            |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增 `POST /assets/trash/clear`                   | 传稳定 `requestId`。服务端首次受理时冻结本人当时全部回收站条目，返回 `202, operationId`。日期筛选只影响展示，确认框明确是清空整个回收站。响应丢失可用原键取回原操作，随后新删除的文件留给下次。 |
| 新增 `GET /assets/trash/operations/{operationId}` | 仅操作所有者可查。返回处理状态、已移除条目数、因引用保留数、已清理原件数，以及待核实或失败数。页面重开后可续查同一操作。清空条目成功与物理清理结果分别展示。                                    |

**C1 与前端**　确认后显示处理状态。回收关系移除时更新列表，受保护的文件继续在原收藏或作品中展示。服务端通过事务协调新增引用、解除引用与清理认领，复核所有者及当前有效引用后才按已登记的精确对象键删除。进入清理的资源停止建立新绑定。数据库保留可恢复的清理身份，COS 超时或回执丢失时按同一对象核实，可重试的失败继续原操作。确认对象已清理后再更新资源状态，按历史外键需要保留最小审计记录。对清空时受保护的文件，最后一次解除引用也能触发同样的检查。

#### 清空后的引用验收

各例使用独立、可丢弃的最终对象。清空前确认能读取原件，记录 `assetId`、对象键、内容摘要和每个有效使用位置。通过页面清空，按 `operationId` 核对回收关系已移除、受保护原件已计入保留数。验证保留时，关页并用新签名读回相同内容。验证清理时，核对数据库清理结果，并以有权检查原件的身份确认同一 COS 对象键已不存在。旧链接过期或返回 403 不能作为删除凭据。

| 用例             | 操作顺序                                                                                                                                                                                                 | 通过条件                                                                                                                                                                                        |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 收藏最后解除     | 文件 5 仅由本人收藏和一个手工媒体节点持有。移入并清空回收站。先在画布删除该节点，保存成功。从“我的资产”重新打开原件，再取消收藏并以同一 `requestId` 重试。                                               | 清空后收藏和节点都能打开 5。删节点后该画布对 5 的使用位置为零，收藏仍能读回原件，打开收藏不会新建作品引用。取消最后的收藏后，5 自动进入清理并确认原件已删除，全程只清空一次。重试只回放原动作。 |
| 同一画布多处引用 | 同一画布的节点甲、乙各确认一个使用文件 X 的手工结果。乙再确认并选中另一文件 Y，让 X 留在乙可重开的历史。X 无收藏或其他持有者。移入并清空 X，先删甲并成功保存。关页重开乙的历史读取 X，再删乙并成功保存。 | 清空后甲、乙均能读取 X。删甲后只释放甲的位置，乙仍能以自己的历史结果读回 X。删乙后最后一个位置解除，X 自动进入清理，最终确认该对象已删除。Y 仍在全部资产且原件可读。                            |

- **作品最后解除。** 按“条目 3／文件 5”的顺序，清空后先取消收藏。海报仍能读回原件。删除海报的唯一手工媒体节点并成功保存后，才清理原件。另用只有收藏的文件验证清空后仍能从“我的资产”选入新作品并保存。
- **清空范围。** 同一批放入一份无引用文件和一份有作品引用的文件。受理清空后再移入第三份。第一份原件已删除，第二份仍可读，第三份仍在回收站。另一账号的回收站、认证状态与对象保持原状。
- **并发与恢复。** 在清理与新绑定竞争时，绑定先提交则保留原件，清理先认领则拒绝新绑定。分别模拟 COS 删除超时、云端已删但数据库确认中断，沿原对象恢复。重试不扩大删除范围。

## 分期接受与衔接

每期先核对该期的 HTTP 行为和数据库事实，再从正式前端入口用真实登录账号读回用户可见结果。记录前后端版本、资产 ID、操作 ID、上传时间与前后状态，隔离验证跨账号、并发及失败恢复。资产库第 3 期与画布第 2 期共用选材、保存、重开的验收记录。第 4 期启用物理删除前须完成已上线消费者的存量引用核对，并用专建对象验收清空后的保留和释放。已接受的上传、计算和认证能力各有独立记录。[私有资产与计算成果](../compute-service/complete/report.md) · [图片成果](../onelink-image-generation/complete/report.md) · [认证素材成果](../onelink-material-library/complete/report.md) · [规划与验收约定](../../coordination.md#规划交付要求)
