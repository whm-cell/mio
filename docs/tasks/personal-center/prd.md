# Web 个人中心 PRD

**待产品评审。** 本需求面向已登录的 Web 用户和发布公告的平台管理员。六个单元分别交付资料与头像、登录方式管理、账号注销、系统公告、创作日志、存储用量与提醒。用户可以核对自己的身份与作品动态，并在个人空间不足时找到可以释放空间的操作。下文标为“候选”的 HTTP 行为随所属单元评审和实施，当前可调用的接口以 [API 领域导航](../../apis/index.md) 为准。

## 交付顺序与共同约定

| 单元              | 首个可验收结果                                 | 依赖与顺序                                             |
| ----------------- | ---------------------------------------------- | ------------------------------------------------------ |
| U1 资料与头像     | 用已有账号改资料，重登仍显示自己的昵称和头像   | 先接通 Cookie 会话、资料展示和私有资产读取。           |
| U2 登录方式管理   | 更换手机号或绑定微信后，仍可进入同一账号       | 复用 U1 资料回读。手机和微信可分别联调。               |
| U3 账号注销       | 本人确认注销，所有设备同时失去原账号访问权     | 复用现有会话与短信用途隔离，按 D3 核定数据和身份处置。 |
| U4 系统公告       | 管理员发布后，用户收到公告，阅读状态跨登录保留 | 可与 U1、U2 并行。两类身份分别鉴权。                   |
| U5 创作日志       | 一次真实创作产生本人可见、可读的消息           | 先接生图，再按 D5 确认的视频、音频范围扩展。           |
| U6 存储用量与提醒 | 用户看得懂占用、能收到提醒，清理后可继续写入   | 先交付计量和提醒，后接服务端限写与资产库清理。         |

- **身份与前端接入。** 普通用户用 Mio Cookie 恢复会话。`GET /api/auth/get-session` 的空会话返回 `null`，`GET /api/v1/me` 的未登录响应为 401。页面依据服务端身份决定是否请求资料、通知和用量。网络故障或 503 显示可重试状态。退出沿用 `POST /api/auth/sign-out`。切换账号后丢弃旧会话的在途回执和预览。前端适配现有错误码到中文提示。当前用户相关的操作由服务端取身份，写请求沿用本域的 Origin 校验。[认证 HTTP 契约](../../apis/auth.md)
- **账号菜单。** 展示头像、昵称、脱敏手机号、微信绑定情况和空间用量，提供编辑资料、管理资产及退出入口。管理入口由独立管理端核验 `GET /api/v1/admin/auth/me`。万联登录绑定状态 `onelinkBound`、用户凭据是否已配置、图像与视频水印分别取自各自契约。凭据和水印沿用 `/api/v1/providers/onelink`，菜单只消费所需展示状态。[管理员身份](../../apis/admin.md) · [万联用户配置](../../apis/providers.md)
- **接受方式。** C0 核对本单元的范围、决定与依赖，C1 在候选实现上验证下列场景。分别记录后端契约回归和目标 Web 客户端联调。需要真实微信或短信的场景注明实际环境、是否收到验证码或完成扫码。隔离替身、测试短信和真实用户操作分别留证。文档评审与各单元的业务接受各自登记。[规划交付要求](../../coordination.md#规划交付要求)

## U1 资料与头像

**复用与缺口。** `GET/PATCH /api/v1/me/profile` 已支持 `displayId`、昵称、`avatarAssetId`、手机号验证状态以及微信、万联绑定标志。默认资料返回手机号原值，头像用资产 ID 表示。`POST /api/v1/assets/uploads`、浏览器 PUT 和 `POST /api/v1/assets/{id}/complete` 已能完成私有直传。现行头像核验支持本人 ready 的 JPEG、PNG、WebP。通用资产下载地址为短期地址，头像还需要浏览器可直接展示的地址。[认证资料](../../apis/auth.md) · [资产上传与读取](../../apis/assets.md) · [对象存储约束](../../integrations/cos.md)

**C0 与候选接口。** 建议给现有 GET、PATCH 增加 `?view=display`，两种响应均只包含 `userId, displayId, name, avatarAssetId, avatarUrl, maskedPhoneNumber, phoneNumberVerified, wechatBound, wechatNickname, onelinkBound`。保留现有调用方的默认响应。`avatarUrl` 按本人当前资产签发短期可内联地址，持久身份仍用 `avatarAssetId`。微信展示名取自服务端已核实的微信授权资料，缺失时显示“已绑定”。开发前盘点默认资料的消费者，按 D1 确定 GIF 展示方式。

**C1 与验收。**

1. 旧账号缺 `displayId` 时展示 `userId`，未绑手机、未绑微信分别显示“未绑定”。检查资料 GET 和 PATCH 回执均仅带脱敏号。普通用户不获得管理权限。
2. 昵称失焦只提交有变化的 `name`。页面最多编辑 20 字，允许字母、数字、汉字、下划线、连字符、点和空格。连续相同符号合并，保存时去除首尾符号和空格。服务端默认契约继续支持 1–50 个 Unicode 字符。历史较长昵称在只改头像时完整保留。快速连续修改时以最近一次已确认保存的值为准，失败保留输入并允许重试。写请求已发出时，关闭弹窗提示操作仍可能生效，重新打开后用服务端资料核对。
3. 用户选择不超过 20 MiB 的头像后立即预览，完成直传和登记，再单独 PATCH `avatarAssetId`。绑定处复核资产大小、本人归属、ready 状态和图片类型。上传或保存失败恢复上次确认的头像。刷新、重新登录或短期地址到期后可重新取得头像。他人或未就绪资产均不能设成头像。

## U2 登录方式管理

**复用与缺口。** 无手机号时已有 `POST /api/auth/phone-binding/send-otp` 和 `POST /api/auth/phone-binding/confirm`。已有手机号时该流程返回冲突。微信已有 `POST /api/auth/link-social` 和 `GET /api/auth/callback/wechat`，要求近期原会话。现有 `/api/auth/wechat/qr-session` 服务于匿名登录。换绑手机、微信解绑以及资料弹窗内完成绑定的交互需要补齐。[手机与微信认证](../../auth.md) · [微信授权与回调](../../integrations/wechat.md) · [短信预算](../../integrations/tencent-sms.md)

**C0 与候选接口。** 手机号统一为认证域使用的规范格式，页面可接受中国大陆 11 位输入。换绑向**新号**验证，注销向**当前已验证号**验证。建议沿用近期原会话和分用途验证码，按 D2 确认更换登录方式后的会话处置与微信中间态要求。

| 操作               | 候选契约及副作用                                                                                                                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 发换绑码、确认换绑 | `POST /api/auth/phone-rebind/send-otp {phoneNumber}` 返回 `{status,expiresIn}`。`POST /api/auth/phone-rebind/confirm {phoneNumber,code}` 返回 `{status:true}`，随后回读 U1 资料。拒绝当前号、已占用号及失效会话。确认时在事务内复核原用户、会话、原号码和新号唯一性，一次性消费换绑挑战。  |
| 站内绑定微信       | 用 `link-social` 返回的授权地址渲染官方二维码，同源回调唤醒资料页并重新读取 `view=display`。以原 `userId` 且 `wechatBound=true` 确认成功。如果需要绑定票据，候选为 `POST /api/auth/wechat/bind-session` 和 `GET /api/auth/wechat/bind-session/{ticket}/poll`，票据仅对发起用户及会话有效。 |
| 解绑微信           | 新增 `DELETE /api/v1/me/wechat`。本人二次确认后解除关联、清除微信展示资料并返回展示视图。服务端先校验还有可实际登录的方式，包括当前可用的已验证手机短信登录、已启用且设置了真实密码的邮箱、或已绑定且当前可用的万联登录。                                                                  |

**C1 与验收。** 无号用户能首次绑定。已有号码的用户对新号发码，页面重发倒计时 60 秒，验证码有效期和频率以服务端为准。换绑后新号进入原 `userId`，旧号无法进入原账号。覆盖号码已占用、验证码过期、跨用途、另一会话及并发争用同一号码。新发码动作沿用短信预算和运行期开关，按本次用途、用户、会话和目标号码校验挑战。固定测试码不能绕过该校验。登录页和注销页发出的码均不能用于换绑。扫码取消、过期、已归他人或回调时已切换账号，资料页均保持真实绑定状态。采用轮询时每 2 秒发起一次串行查询，页面隐藏暂停，连续三次失败停止并可重新发起。扫码并回读确认后可解绑，唯一可用登录方式受保护。

## U3 账号注销

**复用与缺口。** 现有认证服务可在一个事务中禁用用户并删除其全部会话，各受保护入口会核验禁用状态。当前公开接口提供退出、撤销会话和首次绑号。自助注销还需要本人确认、专用发码和对数据、登录身份及在途作业的处置。[账号状态与会话](../../auth.md) · [账号控制与资料扩展](../ai-drama-foundation/changes/auth-account-controls-and-profile/change.md)

**C0 与候选接口。** D3 决定注销的保留、释放、恢复和在途任务规则。建议首版软注销，持久区分管理员停用与用户注销。`POST /api/auth/account-deletion/send-otp` 无号码入参，按当前已验证手机号和短信预算发送注销专用码，挑战绑定发起用户、会话和该号码，返回 `{status,expiresIn}`。扩展 `DELETE /api/v1/me`，已绑手机提交 `{code}`，无手机由近期原会话显式确认并提交 `{}`，成功响应 `{status:true}` 并清除当前 Cookie。手机号发码仅用于核验注销，本期手机号操作为首次绑定和换绑。

**C1 与验收。** 用户先看到与 D3 一致的注销后果，再确认操作。服务端复核当前号码、发起身份和验证码用途，将注销和全会话撤销原子提交。已绑号提交空码、发码后已换号或验证码来自登录/换绑时，账号继续可用。以两个设备、一个有手机号账号和一个无手机号账号验证成功和拒绝路径。成功后两端均不能访问原账号，原登录方式不能重新进入原 `userId`。按 D3 对账持有的数据、在途任务和登录标识再注册结果。

## U4 系统公告

**复用与缺口。** 管理员认证、管理端写入鉴权和操作审计已有实现。需要新增公告内容、草稿和发布状态、弹窗开关，以及每个用户独立的已读记录。沿用独立管理前端和普通 Web 客户端各自的身份。[管理 HTTP 契约](../../apis/admin.md) · [管理后台职责](../web-admin-console/prd.md)

**C0 与候选接口。** 建议采用 D4 的弹窗选择规则。用户可见条件为已发布、已生效且启用。公告卡片至少提供 ID、标题、正文、发布时间和本人已读状态。

| 使用方   | 候选接口                                                                                                                                                                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理员   | `GET/POST /api/v1/admin/announcements` 查询、创建草稿。`PATCH/DELETE /api/v1/admin/announcements/{id}` 编辑、启停或确认删除。`POST /api/v1/admin/announcements/{id}/publish` 发布。支持设定是否弹窗，写入保留管理员及操作记录。                         |
| 登录用户 | `GET /api/v1/announcements?page=1&pageSize=10` 按发布时间和 ID 倒序返回 `{items,page,pageSize,hasMore}`。`GET /api/v1/announcements/latest-popup` 在登录后返回 `{announcement: 对象或 null}`。`POST /api/v1/announcements/{id}/read` 幂等记录本人已读。 |

**C1 与验收。** 管理员保存一条草稿时 A、B 均不可见，发布启用后两人均可见。A 关闭弹窗、“我知道了”或打开公告详情后更新同一条已读记录，刷新或重登遵循 D4，B 仍能收到。写已读失败允许关闭并明确提示下次可能再提醒。“查看全部公告”进入消息中心系统通知页签。停用或删除后从用户列表和弹窗移除。验证普通用户不能发布、查草稿或替他人标记已读。

## U5 创作日志

**复用与缺口。** 生图已有持久任务 ID、归属用户、成功、部分成功、失败以及可恢复的保存状态。视频和音频各有独立任务语义。消息中心还需要由实际业务事件产生的用户通知，以及分页与已读状态。[生图和视频任务](../../apis/compute.md) · [音频任务与作品](../../apis/audio.md)

**C0 与候选接口。** 首个生产者建议选生图，由 D5 确认首发事件和媒体范围。新增 `GET /api/v1/notifications?type=creation_log&page=1&pageSize=10`，按时间和 ID 倒序返回 `{items,page,pageSize,hasMore}`。每项包含 ID、任务关联、标题、可向用户展示的摘要、时间和本人已读状态。`PATCH /api/v1/notifications/{id}/read` 幂等标记已读。系统通知页签由 U4 提供，团队协作维持待开放状态。未读总数、全部已读、单条删除随对应用户操作另排。

**C1 与验收。** 生图结果持久化后，依据同一用户、任务和业务事件去重产生消息，通知失败可从已保存的事实补记。用户无需再生成一次。在成功、部分成功和失败样例中核对日志内容，`unknown`、保存待恢复和后台重试不能提前报为确定失败。同一结果重复处理只出现一次。A 能按每页 10 条继续滚动、查看详情、标记已读，空列表和加载失败可区分。A 的操作不影响 B，切换账号后不混入 A 的迟到回执。视频、音频若纳入首发，须各自用真实生产入口验证发出与去重。

## U6 存储用量与提醒

**复用与缺口。** 资产层有本人归属、大小、就绪状态和私有对象身份。生图成品也会登记成 `derived`，只筛选 `original` 会漏算用户作品。统一资产库已有目录、回收站和引用保护规划，存储配额由本单元负责。旧数据迁移范围排除了旧通知及旧配额，首次用量需从 Mio 已持有的有效资产核对。[资产契约](../../apis/assets.md) · [生图产物登记](../../../src/generations/image/store.ts) · [统一资产库规划](../unified-asset-library/prd.md) · [迁移范围](../legacy-migration/prd.md)

**C0 与候选接口。** D6 确定云端配额、计量对象和释放时点，D7 决定强制限写范围及未知产物大小的处理。预留表示已经为在途写入占用、尚未转为已用的字节。

| 候选接口                                                        | 响应与规则                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/v1/me/storage-usage`                                  | 返回 `quotaBytes, usedBytes, reservedBytes, availableBytes, usageRatio, objectCount, status, accountingStatus, writeBlocked, reminderVersion, thresholdReminderPending, calculatedAt`。`availableBytes=max(0, quotaBytes-usedBytes-reservedBytes)`。`status` 为 `safe / warning / full`，`accountingStatus` 为 `ready / degraded`。`writeBlocked` 报告当前服务端对新增持久写入的实际限制。 |
| `POST /api/v1/me/storage-usage/reminders/ack {reminderVersion}` | 成功返回 204。以本人和提醒版本幂等确认已展示，同一版本重试安全，旧版本确认不能清除较新的提醒。                                                                                                                                                                                                                                                                                             |

**C1 与验收。**

1. **先交付用量与提醒。** 登录和资产写入成功后刷新菜单。按 D6 的候选值测量可用空间恰为 1 GiB、低于 1 GiB、用尽三种状态。满额提示优先，提醒展示后确认版本，确认失败留待重试。同一账号重登不重复弹已确认版本。从警告升级至满额、或清理回到安全区后再次跨阈值，均可收到新版本提醒。空间不足时可从菜单进入管理资产。实际写入遭限额拒绝时直接说明原因和清理入口。
2. **按可释放对象核对数字。** 同一用户的同一底层对象出现在多个目录、作品或素材引用中只计一次。按 D6 核对上传、生成成品、内部派生物和回收站。删除一处引用后，仍被作品或当前头像持有的文件继续可用。达到约定释放时点后同步更新用量。升级后的存量账号与全新账号分别对账，计量异常需显示统计状态。
3. **再交付服务端限写。** 对 D7 纳入的上传和生成入口核对并发预留、完成结算、取消或过期释放，同一请求重放只占一次。两个并发申请不能花掉同一份余量。用同一账号走通“满额 → 新写入被拒 → 管理资产释放空间 → 再次写入成功”。该项依赖可用的清理入口和当前头像等有效引用保护。读用量与提醒可先独立验收。

## 待产品负责人拍板

六个单元的划分已确认。下表是会改变用户体验、身份处置或数据规则的决定。建议值供评审，相应单元只等待与它有关的决定。

| 编号          | 需要决定的问题                                                                                                           | 建议与选择的影响                                                                                                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 · 头像     | 选择 GIF 后是否必须保留动画？                                                                                            | 建议接受 20 MiB 内的 GIF 输入并转静态 WebP。若要求保留动画，U1 增补动图上传、资料校验和浏览器回显验收。                                                                                                                                             |
| D2 · 登录方式 | 换绑、解绑后其他设备是否继续登录？微信是否必须报告“已扫码、待确认”？                                                     | 建议敏感变更保留当前近期会话、撤销其他会话。资料页保留站内二维码，根据授权结果回读资料。若中间态是硬性体验，U2 先验证微信能提供相应可信信号，再决定是否增加绑定票据与轮询。                                                                         |
| D3 · 注销     | 保留哪些数据及多久、何时释放手机号/微信/万联身份、能否恢复账号、如何处置在途任务和供应商凭据？无手机号时用什么确认身份？ | 建议立即关闭原账号并撤销全部会话，普通后台解禁不能恢复注销账号。无手机号用近期原会话二次确认。原身份先保留占用，在途作业停止新增外部提交，已提交结果按获批的保留或清除规则处理。具体保留期限、清除范围、身份释放时点及例外恢复规则须明确后开放 U3。 |
| D4 · 公告     | 最新有效弹窗公告已读后，要不要继续弹更老的未读公告？                                                                     | 建议每次登录只检查最新一条有效且开启弹窗的公告。该条已读即返回空，更早的公告仍可从列表阅读。此决定影响 U4 查询与多公告验收。                                                                                                                        |
| D5 · 创作日志 | 首发覆盖哪些业务、哪些结果需要通知？                                                                                     | 建议生图先交付成功、部分成功和确定失败三类。视频、音频可在明确各自状态和可恢复边界后加入。若要求三类媒体同日可用，U5 要同时接入三个生产者并逐项验收。                                                                                               |
| D6 · 容量计算 | 每人云端额度和提醒阈值是多少？哪些对象计量，删除到哪一步释放？                                                           | 建议默认 5 GiB，可用低于 1 GiB 提醒。计本人上传和持有的生成成品，同一底层对象去重。内部预览、HLS 分片、暂存及仅由供应商托管的对象排除。回收站与活跃引用继续占用，到最后一处有效持有释放时扣减。桌面本机空间和付费扩容另行规划。                     |
| D7 · 限写     | 首发只交付提醒，还是同时覆盖强制限写？生成前无法准确知道输出大小时如何处理？                                             | 建议先上线计量与提醒，再对可确定或可合理预留大小的上传和生成开启硬限制。对上游已受理的生成保留结果恢复途径。若首发要求全面限写，须先确定各生成入口的预留额度、超过预留时的处置及用户清理恢复路径。                                                  |
