# Worker 视频探测分发与占槽

```mio-change
{"version":1,"type":"fix","section":"目标与边界"}
```

开启观测的 Worker 要能消费独立 `video.probe` 消息并按真实占用向管理台报告。本轮候选待验证及接受，既有 Worker 观测交付记录针对当时的转码、音频检测和通用媒体范围。

## 行为

- 普通与开启观测的 Worker 通过同一套严格解析在现有视频队列分发转码和探测。相同预取、认证及消息拒收规则适用于各自消费模式。
- 探测通过共享总槽与 probe 槽准入。分别核验编码暂停、探测 HOLD、等待后恢复与停机。下载前核验字节与工作目录空间，保留每条命令的独立临时文件。
- 同一进程并行收到相同消息时共用一次探测和结果确认。内容冲突进入拒收路径，结果未确认时由 broker 重投。回执绑定命令、任务、输出、attempt 和源快照。
- 遥测使用独立的 `video.probe.v1` 执行身份，记录实际槽位和阶段。A 严格验证包含任务和 attempt 的探测身份。独立管理台从现有管理 API 展示快照、执行列表与时间线。

## 验证

先在基线隔离 RabbitMQ 复现观测路径拒收，随后以候选重新运行普通和观测路径。覆盖合法探测、无效消息、编码暂停及恢复、结果确认和 ACK。另用本机 FFmpeg 及临时存储验证探测、占槽、重投和清理，通过 A 遥测解析、历史查询及独立管理台检查展示。以绑定本轮候选的验证与接受材料为准。
