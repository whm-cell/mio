## 范围与实施安排

C0 已确认输出达到上限时保留已生成的正文，展示“已达输出上限”。沿用当前模型输出政策与单次运行边界。截断反馈随公开回执、事件和历史返回；诊断用量存于原请求的内部观察。依赖固定 DSH 的真实轮次终态与原生日志持久化接口。

C1 先让 PostgreSQL 只结算在途请求、保留各原终态与错误，再依据已持久的 DSH `max-tokens` 结算 completed 并保存截断原因。GET、重复提交和 SSE state/snapshot 使用同一回执投影，历史按原生日志的轮次末尾展示。兼容旧行的可空扩展随显式迁移执行。用量沿固定 DSH 的原值落库，记录仅有缓存的调用及失败时保留的部分用量。

## 验收与规范

经用户入口核对原助手正文、终态回执和实时 SSE，随后重连、翻页及重启复核；覆盖普通完成、真实截断、取消、中断及上游有结束观察但未持久结算的反例。隔离 PostgreSQL 核对四种终态、提交响应丢失、迟到写入与下一轮 busy，以及旧 schema 增量迁移前后的行值。固定 SDK 的协议替身验证纯缓存用量、失败但已有计数和全零／缺失，对账 PG 并核对上游调用次数。

现行行为见[对话持久化](../../../../conversations.md#归属接收与持久化)与[公开 HTTP 和 SSE](../../../../apis/conversations.md)。本次接受按新候选的验证和人类确认记录。
