# 对话图片输入与受控图片检查

```mio-change
{"version":1,"type":"feature","section":"D2：用户归属的对话 API 与完整运行验收"}
```

本变更在原 D2 已接受的文本范围之外，增加本人图片输入及对话中的只读图片检查。原 D1/D2 接受事实、旧回执和未验证限制保持不变；实现检查、真实供应商观察和人类接受分别以各自证据判断。

## 本期结果与边界

3A 的发送入口在非空文本之外接受 0–4 个有序、互异的小写 UUIDv4 `imageAssetIds`；空数组等同省略。历史对无图消息不输出该字段。有图输入使用 `vision:v1:` 加 `SHA256(JSON.stringify([text, orderedIds]))` 作为接收摘要，纯文本摘要保持兼容。先核对会话归属及旧回执，再检查新输入所需的当前模型和资产；失败请求不伪造受理。

3B 在活动视觉模型和资产桥均可用时，单轮授予只读 `inspect_image_asset({assetId})`。它独立于生图服务，继续受到现有总工具调用、图片提交和模型步骤预算限制；身份来自已受理轮次，不接受外部 owner、URL 或对象键。

仅显式声明 `inputModalities` 同时包含 text 和 image 的 chat 路由可使用图片；缺省仅文本。支持本人 ready 的 original 或 derived PNG、JPEG、WebP。源图最多 10 MiB、16,777,216 像素且每边不超过 8192；不修改原件，预览仅在内存准备。COS 按完整键与冻结 ETag 条件流式读取，核对实际长度、格式、尺寸和摘要；每次重读重新校验资源归属和 ready 状态。

图片请求默认最多 4 个 occurrence、Base64 总量 10 MiB、像素预算 4,194,304、单张预览软目标 5 MiB；配置上限分别为 16、20 MiB、16,777,216 和 10 MiB。只允许卸载本轮之前的旧图片 occurrence，仍无法满足预算则失败，不静默丢弃新图片。持久日志只保留受控身份，不保存原图、Base64、签名 URL 或 COS key。

## C0/C1 与验收

用户授权本变更在隔离资源中实施和验证。先接通领域契约、路由和资产/DSH 适配，再验证真实 DSH loop 与隔离 JSONL、受控对象替身及拦截的 OpenAI/Anthropic 出站；覆盖幂等并发、失败恢复、取消关闭、原图与派生图、非本人和不 ready、对象漂移、旧图卸载、重启及视觉能力撤回。保留既有生图工具和文本路径回归。

独立审阅、质量及规范三方对账、覆盖 `pnpm check` 的有效结论与真实人类接受分别判断。隔离替身验证不代表真实供应商、COS 或生产验收。现有 chat `verified` 不区分文本与视觉：文本成功不能证明视觉已实测。
