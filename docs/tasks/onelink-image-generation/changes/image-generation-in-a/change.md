# A 承接图片生成与持久恢复

## 目标与范围

本期作为一个完整的架构迁移单元，把现有云端图片生成及恢复迁到 A，B 保留 FFmpeg 转码、合成、抽帧等本地重媒体处理及其恢复。沿现有单 A 实例实施；图片执行改用 PostgreSQL 持久任务、A 后台执行器和 A 专属持久目录，不再经过 RabbitMQ。RabbitMQ 继续服务 A/B 重媒体通信，COS 继续保存持久媒体原件。

本变更按已确认的“暂停新生图提交、排空旧任务、切换执行端”方案实施。多副本接管、云端音频/视频生成和生成完成后自动唤醒 Agent 不在本期。复用既有受控图片工具，不扩展模型权限或新建 Agent Loop。旧切片的实际接受与限制仍以[图片能力成果](../../complete/report.md)为准，本次迁移不改写历史接受，也不代表全部图片协议或生产就绪。

## 迁移契约与 C0

实施前核对实际候选、未提交改动和既有接受，保留其他任务现场；按[图片 HTTP 契约](../../../../apis/compute.md#post-apiv1computeimages)及调用方建立当前 HTTP、工具、公开状态、错误、限额、供应商适配和恢复行为对照。A 的 COS 读写权限、媒体数据库配置及独占持久目录必须满足所需资产范围；不合并各域数据库、不重建业务数据。

| 必须保持           | 本期义务                                                                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HTTP 与工具        | 保留图片提交、查询和 /recover 路径；保留 list_image_models、submit_image_job、get_image_job 名称、请求字段与脱敏返回。                                                  |
| 身份与幂等         | 用户身份来自正式会话，模型不能提供 owner 或执行凭据；相同 owner/requestId 同输入复用原任务，冲突输入拒绝。保持 jobId、assetId 及用户归属。                              |
| 状态与路由         | 保留公开状态、错误语义、冻结路由、查询次数与绝对截止；内部执行、检查点和凭据字段不暴露给模型或普通客户端。                                                              |
| 历史和部分结果     | 复用现有图片任务与输出，增量迁移并继续历史查询；已有部分结果不得改判完整成功。                                                                                          |
| 首次提交与查询凭据 | 复用[供应商加密组件](../../../../providers.md)，保存首次提交的密文快照及版本绑定；首次提交沿原快照语义，后续查询沿任务所属用户当前有效 Key 语义，Key 更新回归不得丢失。 |
| 文件和资产         | 原始图片字节、数量、顺序、格式、摘要、ETag、唯一对象键与入库校验保持；原件不套用对话预览的缩放、压缩或尺寸限制。                                                        |

迁移范围、兼容要求、存储归属和切换方案明确后进入 C1。实施后的行为证据在 C1 收集；尚未证明的真实供应商调用、A 存储权限及旧任务对账不冒充通过，它们继续约束相应验证与运行切换。

## C1 实施与依赖顺序

| 开发单元             | 结果、依赖与验收                                                                                                                                                                                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A 图片领域与协议迁移 | src/generations/ 负责准入、存储、执行、查询调度、恢复及产物入库；src/integrations/onelink/ 迁入现有图片驱动、协议解析和受限结果下载。保留现有同步、异步、参考图和编辑；图片领域类型归生成模块，共享 A/B 协议仅留真实跨进程内容。类型检查、构建和 AST 边界覆盖新落点；A 不导入 B 内部实现。先通过迁移后的协议及输入校验回归。 |
| A 持久执行与恢复     | 在领域/协议契约固定后接入 PG 原子认领与后台执行。HTTP 鉴权、准入和落库后立即返回 jobId；网络期间不持有长事务。生成 POST 前持久化提交意图，结果不确定记 unknown，禁止自动重新生成。保存上游 ID、次数、绝对截止和下次查询时间；重启查询原任务，等待许可后发请求前再次检查截止。验证重复调度、重启、网络超时与查询边界。        |
| 凭据和结果恢复       | API Key 只在实际调用时解密，不进入工具结果、日志或媒体恢复文件。已收到图片先可靠落盘，再登记 PG 可恢复检查点，保存定位和摘要。COS 失败从已存图片恢复物化，不再生成；停机停止认领新任务，并沿持久状态恢复，不重放对话工具调用。验证 Key 更新、落盘、COS/PG 失败及部分上传。                                                   |
| 资源与文件生命周期   | 用既有 sharp 异步完整解码替换图片链路同步 FFmpeg 子进程；metadata() 只读头，不构成完整性验证。图片网络执行保持现有并发上限，解码初始并发为 1，与对话分别排队。COS 与 PG 对账成功后才清理临时产物；失败/未知保留，磁盘不足停止新准入，不自动删除恢复数据。                                                                    |
| HTTP、工具和装配     | 在生成服务可用后把原图片 HTTP 与受控 Agent 工具接到 A；工具不直接构造供应商请求。输出 assetId 可在后续对话看图、引用和编辑。生成服务独立显式启用并指定持久目录，不再以 RSA 配置推断启用；仅生图时不要求 B/MQ，重媒体按自身配置启用。同步修改验收入口及调用次数核验。                                                         |
| 旧执行链退役         | 依下节先排空、对账和切换，再退役 B 图片驱动、图片消费者及解密逻辑、图片 RSA 启动依赖。B 不再接收 OneLink Key；A 的 provider master key 保留。更新环境初始化、迁移、验收脚本和受影响现行规范；B 重媒体恢复回归通过。                                                                                                          |

各单元属于同一迁移任务，按真实依赖进入实施与验收，不用子单元完成替代整体迁移接受。阶段规则沿[统一生命周期](../../../../coordination.md#当前任务的生命周期)，不把规划就绪或静态通过记作业务接受。

## 切换、停止与回退

运行切换前盘点旧图片任务、MQ 消息、outbox、B journal 及可恢复部分结果。存在未对账任务、未对账 unknown、恢复数据缺失或 A 存储权限不足时停止切换；保留现场继续核对，不通过重发生成获取成功证据。

1. 暂停新的图片提交，继续历史查询。
2. 排空旧链，逐项对账任务、消息、outbox、journal 与部分产物。
3. 停止旧图片执行器，确认旧进程不再发送生成请求。
4. 启动 A 图片执行器，验证历史读取和新链路后恢复接单。
5. 退役 B 图片执行、图片消费者和解密逻辑，再移除相应启动依赖。
6. 核对环境、迁移、验收脚本与现行规范。

旧恢复数据和历史表不随代码退役清空。图片专用队列和密钥仅在核对后退役；视频队列与 B 的重媒体 journal 保留。A 尚未接收新任务时可回退旧版本；一旦 A 已提交新任务，必须先对账，不能直接交旧 B 重跑。代码候选形成不代表上述运行切换已经完成。

## 验证与接受

| 验证项     | 通过条件                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| 兼容       | 原 HTTP、工具与历史数据读取回归通过；相同请求复用任务，冲突仍拒绝；公开状态、错误、路由与用户归属保持。 |
| A 独立生成 | B 停止、图片无 MQ 配置时，同步和异步生成均可完成。                                                      |
| 多轮复用   | 当前轮生成，后续轮查询、看图、引用和编辑；重启后历史仍可使用。                                          |
| 幂等与恢复 | 提交意图、上游返回、查询、落盘及入库边界中断，不额外生成 POST 或重复资产；已持久结果可恢复。            |
| 查询边界   | 等待许可跨截止后不再请求；次数持久化；完成后停止查询。                                                  |
| 产物完整性 | 单张与多张输出的数量、原序号、格式、摘要、对象及 owner 下载内容一致；损坏图片不冒充成功。               |
| 存储故障   | COS 失败可恢复；磁盘故障不丢弃已确认检查点；部分结果状态明确。                                          |
| 权限与凭据 | 本人可用、他人 404、未登录 401；Key 更新语义保持，B 无生图凭据。                                        |
| 资源并行   | B 转码期间 A 对话与生成可用；记录实际资源和延迟，不据此宣称完全无竞争。                                 |
| 迁移与回退 | 旧任务对账完整，无双执行器接管；历史查询和 B 转码恢复正常。                                             |

自动化回归使用[常驻环境隔离通道](../../../../local-environments.md#自动化回归与人工数据)，真实业务验收使用获授权的常驻 mio_dev 现行各域配置并保留数据；破坏性故障与重放另建隔离现场。普通测试不读取私人凭据或自动调用供应商。

受影响测试、覆盖 pnpm check 的当前有效结论、独立代码审查、quality-review 和 norms-review 绑定同一干净候选，最终先进入 C1_EVIDENCE_PENDING。真实业务、迁移切换证据和人类接受齐备后才能记录 C1_RELEASED。完成标准为 A 独立承接现有云端图片生成及多轮复用，B 专注本地重媒体，身份、幂等、恢复和资产完整性保证得到保留。

现行规范按职责维护：[计算 API](../../../../apis/compute.md)、[供应商](../../../../providers.md)、[OneLink](../../../../integrations/onelink.md)、[PostgreSQL](../../../../integrations/postgres.md)、[COS](../../../../integrations/cos.md)和[本地环境](../../../../local-environments.md)。共享候选设计未采用的其他媒体方案不因本次迁移自动采纳；[既有成果](../../complete/records.json)保留各自原接受与限制。
