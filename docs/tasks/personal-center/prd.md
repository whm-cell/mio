# Web 个人中心 PRD

**评审稿。** 已登录的 Web 用户可以管理身份与资料、查看作品动态并清理个人空间。管理员可以发布公告、调整个人空间配额和提醒阈值。本轮已确认的产品规则见各单元，仍需产品决定的事项集中在文末。标为“候选”的 HTTP 接口供后续开发，当前可调用的接口以[API 领域导航](../../apis/index.md)为准。

## 交付顺序与共同约定

| 单元              | 首个可验收结果                                     | 依赖与顺序                                                                 |
| ----------------- | -------------------------------------------------- | -------------------------------------------------------------------------- |
| U1 资料与头像     | 改昵称或用 GIF 设置头像，重登仍能看到保存后的资料  | 先接通 Cookie 会话、资料展示和私有资产读取。                               |
| U2 登录方式管理   | 换绑手机或重新绑定微信、万联后仍进入同一账号       | 复用 U1 展示视图；覆盖微信、万联的两条重绑路径和换绑／解绑后的多设备会话。 |
| U3 账号注销       | 本人确认后立即关闭账号，所有设备失去访问权         | 注销时释放登录身份，24 小时内清完普通在线数据，普通备份按 30 天轮转。      |
| U4 系统公告       | 管理员发布，用户收到最新公告，已读跨登录保留       | 可与 U1、U2 并行，管理端与用户端分别鉴权。                                 |
| U5 创作日志       | 图片、视频、音频三类结果在同一个消息中心可查、可读 | 共用查询与已读接口，三个生产入口分别验收后同日开放。                       |
| U6 存储用量与提醒 | 管理员调整配额，用户看到生效值、用量和清理入口     | 首版交付计量、后台配置和提醒，满额后仍可继续创作。                         |

- **身份与前端接入。** 普通用户用 Mio Cookie 恢复会话。`GET /api/auth/get-session` 的空会话返回 `null`，`GET /api/v1/me` 的未登录响应为 401。页面依据服务端身份决定是否请求资料、通知和用量。网络故障或 503 显示可重试状态。退出沿用 `POST /api/auth/sign-out`。切换账号后丢弃旧会话的在途回执和预览。前端适配现有错误码到中文提示。当前用户相关的操作由服务端取身份，写请求沿用本域的 Origin 校验。[认证 HTTP 契约](../../apis/auth.md)
- **账号菜单。** 展示头像、昵称、脱敏手机号、微信和万联的绑定情况以及空间用量，提供编辑资料、管理资产及退出入口。管理入口由独立管理端核验 `GET /api/v1/admin/auth/me`。万联登录绑定状态 `onelinkBound`、用户凭据是否已配置、图像与视频水印分别取自各自契约。凭据和水印沿用 `/api/v1/providers/onelink`，菜单只消费所需展示状态。[管理员身份](../../apis/admin.md) · [万联用户配置](../../apis/providers.md)
- **接受方式。** C0 核对本单元的范围、决定与依赖，C1 在候选实现上验证下列场景。分别记录后端契约回归和目标 Web 客户端联调。需要真实微信或短信的场景注明实际环境、是否收到验证码或完成扫码。隔离替身、测试短信和真实用户操作分别留证。文档评审与各单元的业务接受各自登记。[规划交付要求](../../coordination.md#规划交付要求)

## U1 资料与头像

**复用与缺口。** `GET/PATCH /api/v1/me/profile` 已支持 `displayId`、昵称、`avatarAssetId`、手机号验证状态以及微信、万联绑定标志。默认资料返回手机号原值，头像用资产 ID 表示。`POST /api/v1/assets/uploads`、浏览器 PUT 和 `POST /api/v1/assets/{id}/complete` 已能完成私有直传。现行头像核验支持本人 ready 的 JPEG、PNG、WebP。通用资产下载地址为短期地址，头像还需要浏览器可直接展示的地址。[认证资料](../../apis/auth.md) · [资产上传与读取](../../apis/assets.md) · [对象存储约束](../../integrations/cos.md)

**C0 与候选接口。** 建议给现有 GET、PATCH 增加 `?view=display`，两种响应均只包含 `userId, displayId, name, avatarAssetId, avatarUrl, maskedPhoneNumber, phoneNumberVerified, wechatBound, wechatNickname, onelinkBound`。保留现有调用方的默认响应。`avatarUrl` 按本人当前资产签发短期可内联地址，持久身份仍用 `avatarAssetId`。微信展示名取自服务端已核实的微信授权资料，缺失时显示“已绑定”。盘点默认资料的消费者。已确认接受不超过 20 MiB 的 GIF 并保存为静态 WebP。候选 `POST /api/v1/me/profile/avatar/normalize {sourceAssetId}` 复核本人已就绪的 GIF 原件、实际格式与大小，取第一帧生成静态 WebP，返回 `{avatarAssetId}` 后沿用资料 PATCH。相同原件重试复用转换结果，作为头像输入的临时原件按 U6 暂存规则处理。

**C1 与验收。**

1. 旧账号缺 `displayId` 时展示 `userId`，未绑手机、未绑微信分别显示“未绑定”。检查资料 GET 和 PATCH 回执均仅带脱敏号。普通用户不获得管理权限。
2. 昵称失焦只提交有变化的 `name`。页面最多编辑 20 字，允许字母、数字、汉字、下划线、连字符、点和空格。连续相同符号合并，保存时去除首尾符号和空格。服务端默认契约继续支持 1–50 个 Unicode 字符。历史较长昵称在只改头像时完整保留。快速连续修改时以最近一次已确认保存的值为准，失败保留输入并允许重试。写请求已发出时，关闭弹窗提示操作仍可能生效，重新打开后用服务端资料核对。
3. 用户选择不超过 20 MiB 的头像后立即预览，完成直传和登记。JPEG、PNG、WebP 沿用原路径。用恰好 20 MiB 的有效动图验证可接收，超过上限或解码失败有明确提示。保存后 `avatarAssetId` 指向静态 WebP，刷新和重登都只显示同一帧。绑定处复核归属、实际大小、ready 状态和类型。他人或未就绪资产不能设成头像，上传、转换或保存失败时恢复上次确认的头像。地址过期后可重新获取。

## U2 登录方式管理

**复用与缺口。** 个人中心的手机操作仅开放换绑，认证域的首次绑号和注册流程沿用现行契约。微信已支持匿名登录、首次注册及近期原会话内的 `POST /api/auth/link-social`。万联已有 `POST /api/auth/onelink/start` 的登录、绑定两种意图，以及 `POST /api/auth/onelink/complete` 的确认动作。两者都需补解绑和登录页识别已解绑身份。微信还需支持扫码后暂存候选身份，万联可复用“绑定已有账号”的流程。[认证 HTTP 契约](../../apis/auth.md) · [微信授权](../../integrations/wechat.md) · [万联登录与绑定](../onelink-login/prd.md) · [短信预算](../../integrations/tencent-sms.md)

**C0 与候选接口。** 微信和万联解绑后各有两个重绑入口。**在个人中心**，已登录用户选择服务商。微信扫码后在微信端授权，返回个人中心查看结果。万联扫码授权后由本人确认绑定。**在登录页**，用户直接扫微信或万联二维码，服务端识别已解绑身份后，在本次登录流程内拉起“重新绑定已有账号”。用户验证目标账号、确认绑定后即可登录，无需往返个人中心。扫码完成只证明持有该第三方身份，确认成功前不会据此签发登录会话或新建账号。换绑手机号或解绑微信、万联后，当前设备和其他设备上原本有效的 Mio 会话均保持登录，期限和原有失效条件沿用现行契约。

| 操作               | 接入与回执                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 更换已绑定的手机号 | 候选 `POST /api/auth/phone-rebind/send-otp {phoneNumber}` 返回 `{status,expiresIn}`，`POST /api/auth/phone-rebind/confirm {phoneNumber,code}` 返回 `{status:true}`。要求近期原会话和已有验证号。手机号统一为认证域规范格式，页面可接受中国大陆 11 位输入。向新号发码，确认时在同一事务复核本人、发起会话、原号码和新号唯一性，一次性消费挑战，随后回读 U1。无手机号时显示“未绑定”。 |
| 个人中心重绑       | 微信沿 `link-social` 发起官方二维码授权，个人中心只显示“等待授权”和最终结果。回调后回读原 `userId` 与 `wechatBound=true` 才显示绑定成功。万联沿 `onelink/start` 的 `intent=bind` 发起授权，用 `bind_current` 显式确认，成功后回读原 `userId` 与 `onelinkBound=true`。                                                                                                               |
| 登录页扫码重绑微信 | 复用微信登录二维码和授权回调。候选扩展 `GET /api/auth/wechat/qr-session/{qrcode_id}/poll`，命中已解绑身份时返回 `rebind_required`。页面保留这次扫码结果，进入账号验证与“确认绑定并登录”。候选 `POST /api/auth/wechat/rebind/confirm` 绑定本次扫码候选与经验证的目标账号，成功后建立登录会话。                                                                                       |
| 登录页扫码重绑万联 | 从 `onelink/start` 的 `intent=login` 打开万联授权二维码。候选在已解绑身份的回调与待处理结果中标明需重绑，登录页显示“重新绑定已有账号”。服务端对这种候选只接受绑定已有账号，拒绝建号动作 `create`。目标有已验证手机号时，复用 `GET /api/auth/onelink/pending`、`POST /api/auth/onelink/existing/send-otp` 及 `onelink/complete` 的 `link_existing`，在确认成功后直接登录。           |
| 解绑微信或万联     | 候选 `DELETE /api/v1/me/wechat`、`DELETE /api/v1/me/onelink`。本人二次确认后撤下登录关联和相应展示资料并回读 U1。解绑前校验还剩至少一种可用登录方式，包括本人已有验证号且短信登录可用、本人已设真实密码且邮箱登录可用，或另一个已绑定且可用的服务商。万联的供应商凭据继续按其独立契约管理。                                                                                         |

登录页建议复用已有登录方式验证目标账号。有号可在绑定界面验证已有号码；无号或短信停用时，保留本次扫码候选，在同一流程内通过该账号另一种有效方式取得近期会话，再显示脱敏目标账号并确认。微信手机路径建议补 `POST /api/auth/wechat/rebind/send-otp`，将验证码绑定到本次扫码候选和目标手机号，由重绑确认接口统一消费。万联无号路径需补登录意图下衔接近期目标会话的确认，现有 `bind_current` 仍只服务由原会话发起的绑定。目标身份由服务端核验。按服务商与稳定身份区分当前绑定、从未绑定、曾主动解绑。当前绑定沿用正常登录，从未绑定沿用原注册或选账号流程。已解绑身份不能自动回到旧账号；最后一次确认须复核账号有效、身份仍可绑定、扫码候选未过期且属于本次浏览器操作。过期、重复确认或解绑前发起的旧回调均不能覆盖新绑定。

**C1 与验收。**

1. 向新号发换绑码，60 秒后可重发，实际有效期、频率与预算由服务端控制。成功后新号进入原 `userId`，旧号失去原账号访问权。覆盖无号调用、当前号、已占用号、并发争用、过期码和跨会话／用途的验证码。固定测试码同样核验挑战归属。注销专用码只向当前已验证号码发送。
2. 用同一个仍有效的账号逐一验证四种组合：微信在个人中心重绑、微信从登录页扫码重绑、万联在个人中心重绑、万联从登录页扫码重绑。每次先解绑；登录页两例须能看到确认界面，确认前无此次扫码生成的新号或业务会话，确认后直接进入原 `userId` 且相应绑定标志为真。覆盖无手机号账号在登录页使用另一有效方式完成验证。
3. 分别验证当前已绑定身份能直接登录，从未绑定的身份仍按原流程处理。取消、验证失败、扫码过期、切换账号、身份已被占用、迟到回调或重复确认均不会误绑或暗中建号；拒绝移除最后一种可用登录方式。已注销账号按 U3 处理。登录页沿用微信二维码轮询接口获取授权结果。
4. 同一账号在 A、B 两台设备登录。在 A 分别执行手机换绑、微信解绑、万联解绑；每次操作后，两台设备用原 Cookie 刷新资料并继续访问本人资源，仍是同一 `userId`。再用未登录的浏览器验证旧手机号不能进入原账号，已解绑第三方扫码只会拉起重绑。已退出、已撤销或自然过期的会话仍然无效。
5. 在个人中心发起微信绑定，分别在扫码前、手机已扫码但尚未授权时查看页面，两次均显示“等待授权”。授权成功后核对回调和本人绑定标志，再显示成功。授权取消、过期或失败时显示可核实的结果并允许重新发起，回读失败时可重试核对。登录页的微信二维码也只显示等待授权和最终结果。若已解绑，授权通过后进入目标账号验证与“确认绑定并登录”。

## U3 账号注销

**复用与缺口。** 认证域已有锁定用户、设置禁用状态、在同一 PostgreSQL 事务内撤销全会话的能力。管理员停用允许解禁。个人主动注销需要独立的永久终态、身份释放及持久清理记录。现有资产清理器只回收过期上传的暂存对象。正式媒体的引用核对和物理删除仍是统一资产库的规划，需要在本单元落地所用部分。[账号状态与会话](../../auth.md) · [认证事务](../../../src/auth/account.ts) · [现有 COS 清理范围](../../integrations/cos.md) · [资产引用与物理清理](../unified-asset-library/prd.md)

**C0 与候选接口。** 个人中心只提供“立即永久注销”。确认前告诉用户，所有设备将退出，原账号和作品无法恢复，需保留的作品应提前下载。已有已验证手机号时，候选 `POST /api/auth/account-deletion/send-otp` 向当前号码发注销专用码，挑战绑定本人、发起会话和号码。候选 `DELETE /api/v1/me` 提交 `{code}`。无手机号时，要求近期原会话和页面明确二次确认，提交 `{}`。

以注销事务提交的服务端时刻为 **T0**。在认证库的一个短事务内复核本人及挑战、将旧 `userId` 置为永久注销、撤销全部会话、解除并释放手机号、微信、万联及可登录邮箱，使旧验证码和绑定候选失效，并以旧 `userId` 为唯一键登记清理任务。全部提交后清除 Cookie 并返回 `{status:true,finalizedAt}`。登记失败则整个事务回滚。提交成功但响应丢失时，已登记的唯一任务继续执行。T0 起旧号不能登录、解禁或通过 U2 重绑恢复。同一身份可按正常流程注册全新 `userId`。后续清理只认旧 `userId` 及其确切资源，重新注册不会带回旧资料，也不会让新数据进入旧任务。

现有微信首注会为同一个 AppID 与 openid 生成固定占位邮箱。若保留旧用户行，注销事务还须将其邮箱唯一值替换为与登录身份无关的唯一技术值，释放微信首注所需的占位值。现有绑定回调可能在会话被撤销后才落库，因此最终写入第三方关联须与注销事务锁定同一用户并复核有效状态。旧回调即使在 T0 前通过验证，也不能在 T0 后重新占用身份。[微信身份与回调约定](../../integrations/wechat.md)

### 24 小时在线清理与 30 天备份轮转

**触发与期限。** 从注销事务提交时刻 T0 起，须在 **24 小时内**清完普通在线数据并逐域核对。T0 即可领取任务，用户关闭页面后清理继续。已注销账号即时失去业务访问权，服务端停止签发读写地址、使用该用户凭据或受理新的生成。注销前已签发的 COS 直连地址仍受原有效期和对象存续状态约束。已发出的外部请求按原任务收尾，迟到的输出只做核对和清理。最后一轮盘点要覆盖旧上传地址及在途写入可能产生的对象。[资产读取与上传](../../apis/assets.md) · [媒体任务结果](../../apis/compute.md)

主服务已有各域生命周期的装配入口，转码待发命令已有同事务持久登记、领取租约和带租约回执的实现，可复用其做法。账号注销任务由认证库持有。各域只操作自己拥有的存储。清理 B 本地内容须沿 A/B 协议按任务归属确认。对供应商端托管的素材，注销清理本地数据。需要远端级联删除或撤销授权时遵循该业务原有的独立授权约定。[主服务装配](../../../src/plugin.ts) · [PostgreSQL 边界](../../integrations/postgres.md) · [领取与回执实例](../../../src/compute/transcode/store.ts) · [对话正文存储](../../conversations.md) · [音频存储](../../apis/audio.md) · [A/B 计算协议](../compute-service/protocol.md) · [素材删除契约](../../apis/materials.md)

**重试、防止数据重新出现及完成口径。** 对仍会异步写入的域，先持久记录旧 `userId` 已关闭。任务的最终保存和发布须在本域事务内据此复核，使注销前领取的任务也不能在清理后写回。再按旧 `userId` 与原任务身份分批清除。已注销的结果不再发布为作品或日志，不重新向供应商提交生成。跨库通过各域的持久回执衔接。每次确认一批后才推进游标。数据库记录已经移除但对应文件尚未确认时，保留原任务及文件定位，重启后可幂等处理同一批。只有全部适用域已完成、例外对象有明确依据、在途写入收束且末次复查无待删项时才写 `completedAt`。任务入队、数据库行删除和 COS 删除请求发出都只是中间进度。

**逾期监控。** 运维监控最老待清任务的年龄、失败环节、剩余量及执行器心跳，告警检查独立于清理执行器。任务到 20 小时仍未完成时预警，到 24 小时仍未完成时记为超时并告警。短暂故障可按 1、5、15 分钟退避。权限或归属异常保留进度并告警，修复后接续同一任务，保留原截止时间和实际完成时间。

**普通备份与灾备恢复。** 普通备份按 **30 天滚动轮转**。最迟到 **T0 + 30 天**，普通备份中含旧账号待删数据的副本须全部淘汰。清理期间制作的备份及其后续复制都沿用该账号的原截止日。轮转期内恢复旧备份时，从备份之外取得最新注销记录。对恢复点之后注销的账号重放注销，对快照中已经注销但仍有待删数据的账号按旧 `userId` 补清。各域核对旧号无法登录、应清数据已移除，再开放服务。法定留存仅限有依据的最少记录，隔离保存并到期清理。普通备份、第三方独立托管和有依据的保留项分别记录，在线清理单独验收。[《个人信息保护法》第十九条、第四十七条](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)

**C1 与验收。**

1. 已绑号提交空码、换号后提交旧码或提交其他用途验证码均拒绝。无号用户用近期原会话明确确认可成功，过期会话被拒绝。验证注销和任务登记同成同败，成功时两台设备均立即失效，普通后台解禁和旧扫码均不能恢复旧号。
2. 用原手机号或第三方身份立刻注册新号并创建数据，旧任务执行前后均只能影响旧 `userId`。另验微信首注账号注销后用同一微信注册出不同 `userId`，以及微信绑定回调先通过会话验证、注销提交后才尝试落库，旧绑定不能写回，新账号仍可绑定。投递一条注销前已受理的迟到结果，并覆盖仍有效的旧直传地址，复核不会重新发布作品、泄漏凭据或漏清新到的旧对象。
3. 在隔离环境制造“注销提交后、执行器领取前重启”“删除成功但尚未记回执就重启”“两个实例并发”“某个域离线或 COS 暂不可用”。观察同一任务接续、分批重试与末次核对，验证共享文件和其他用户数据仍可读取。清单覆盖对话原生日志、媒体恢复文件和已登记的远端处理节点。
4. 以代表性的大账号及注销高峰验证 `completedAt − T0 ≤ 24 小时`，逐域核对在线记录和独占文件。用可控时钟验证 20 小时预警、24 小时超时告警。超时后接续成功仍能查到原违约记录。
5. 在隔离环境核对备份策略与实际副本清单。轮转期内分别还原注销前、注销已提交但在线清理尚未完成的快照。验证两次都按旧 `userId` 清理并复核后才开放服务，原身份即使已用于新账号也无法读到旧数据。查验备份及其复制件在 T0 + 30 天的实际清单，含旧账号待删数据的普通副本须全部淘汰。

## U5 创作日志

**复用与缺口。** 图片、视频、音频已有持久任务 ID、用户归属及可核对的结果。图片、视频会分别登记成功输出。音频任务和作品记录可以与成品资产分库，须在作品发布后读取结果。新增能力是把三个生产入口的业务结果送入同一个用户消息列表并记录已读。**三个入口须同日对用户开放。** [图片和视频任务](../../apis/compute.md) · [音频任务与作品](../../apis/audio.md)

**C0 与候选接口。** 首发建议采用下列消息口径。用户能区分“已有可查看的作品”“部分作品已保存”和“本次创作确定失败”。

| 媒体 | 何时记一条消息                                                                             | 避免误报                                                                            |
| ---- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 图片 | `completed` 记成功。`partial` 且已有可用作品时记部分成功。明确拒绝或不可恢复的失败记失败。 | 保存待恢复、结果未知和后台重试不产生失败消息。                                      |
| 视频 | 按该视频任务已登记的输出记成功或部分成功；无可用输出且确定失败才记失败。                   | 取消申请、轮询和转码进度不报成失败；部分成功经恢复变为全部成功时可记一次新结果。    |
| 音频 | 任务 `ready` 且作品记录已发布时记成功；确认无可恢复结果的失败才记失败。                    | `unknown`、正在保存和带可恢复检查点的 `failed` 延后判断。供应商受理本身不触发成功。 |

候选 `GET /api/v1/notifications?type=creation_log&page=1&pageSize=10` 返回 `{items,page,pageSize,hasMore,nextCursor}`。消息中心滚动加载下一页时附带上一页返回的游标 `cursor`，按发生时间和 ID 稳定倒序续读。单条含 ID、媒体类型、任务 ID、结果类型、标题、可公开给本人的简短摘要、发生时间及已读状态。`PATCH /api/v1/notifications/{id}/read` 幂等标记本人已读。系统通知页签由 U4 提供，团队协作维持待开放。未读总数、全部已读和单条删除随对应用户操作另排。

**已确定的存储方案。** 首版使用 PostgreSQL，在通知域建一张用户创作消息表。每个有意义的结果保存一条小记录，`read_at` 存已读时间。进度轮询、执行器重试、原始供应商响应及媒体文件留在各自现有位置。查询按用户、时间及 ID 读取下页，可用 `(owner_id, occurred_at DESC, id DESC)` 索引；`(owner_id, media_type, job_id, event_kind)` 唯一约束保证重试只留一条。同库可在一个事务中登记结果与消息；分库时可在生产者的结果事务内留一条待投递事件，按同一事件键补投。这样在音频作品已保存、消息暂未送达时可单独补记。[项目 PostgreSQL 约定](../../integrations/postgres.md) · [PostgreSQL 多列索引](https://www.postgresql.org/docs/18/indexes-multicolumn.html)

数据量由**每日产生的业务结果数 × 保留天数**决定。例如三类媒体合计每日产生 10 万条，按 90 天估算约有 900 万条消息。实际峰值需测量，正常账号的消息保留期限待产品决定，见文末。上线前用代表性数据测每条记录连同索引的字节数、峰值写入、个人列表翻页延迟及故障后补投积压。若出现明确瓶颈，先验证索引、归档或按时间分区的收益，按已选的 PostgreSQL 方案安排容量扩展。[PostgreSQL 表分区](https://www.postgresql.org/docs/18/ddl-partitioning.html)

**C1 与验收。**

1. 分别通过图片、视频、音频的实际生产入口完成一次创作，同一用户当天在同一列表看到三种结果。逐类用成功、确定失败和适用的部分成功／可恢复样例核对消息。模拟故障或状态回放的证据与真实创作记录分别登记。三条链路均达标后才开放首发。
2. 同一结果重复处理只出现一次。已有一项成功的任务随后全部完成，可以看到含义不同的部分成功和完成消息。中断消息写入再恢复，三类都可从已持久化的事实补记，保留原发生时间，无需重新生成或再次向供应商提交。
3. 混合三类媒体、同一时间存在多条且共超过 10 条时，连续翻页核对顺序、缺项和重复。A 读一条后刷新、重登仍为已读；B 无法查看或标记 A 的消息。空列表和加载失败各有可辨认的页面状态。
4. 保留期限确定后，按消息原发生时间验证回看边界，覆盖已读、未读和迟到补投。消息到期时只清对应通知和已读状态，核对仍由用户持有的作品可照常打开，生成历史按原规则查询。已注销账号的消息走 U3 的 24 小时清理。

## U6 存储用量与提醒

**复用与缺口。** 资产层已有用户归属、底层对象身份、大小与就绪状态。生成成品可登记为 `derived`，只筛 `original` 会漏算。资产库已规划目录、回收站与引用保护。现有旧库迁移范围排除了旧通知和旧配额，首次用量需从当前有效资产核对。`mio-admin-web` 已有全局配置页，管理域具备管理员鉴权、版本冲突检查及审计；现有 `/api/v1/admin/settings/global` 写入体仅接收认证配置。[资产契约](../../apis/assets.md) · [生图产物登记](../../../src/generations/image/store.ts) · [资产库规划](../unified-asset-library/prd.md) · [迁移范围](../legacy-migration/prd.md) · [管理配置契约](../../apis/admin.md#patch-apiv1adminsettingsglobal)

**C0 与候选接口。** 默认每人 **5 GiB**，可用空间**低于 1 GiB** 提醒，等于阈值仍为安全，用尽显示满额。本人上传和持有的生成成品按底层对象去重。内部预览、HLS 分片、暂存和仅由供应商托管的对象排除。回收站与当前头像、作品等有效引用继续占用，到最后一处有效持有释放才扣减。桌面本机空间和付费扩容另行规划。

管理员在 `mio-admin-web` 的“全局配置 → 存储空间”里可分别调整**配额**和**提醒阈值**。服务端保存成功即对所有存量及新账号按新值计算，已登录用户下次读取便看到新值，无需重登、重启或逐账号更新。**首版只做计量和提醒。** 即使已用量超过新配额，也展示实际用量。个人空间配额不会禁用上传、生成、查看、下载或清理入口。

| 使用方与候选接口                                                     | 响应与规则                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用户 `GET /api/v1/me/storage-usage`                                  | 返回 `quotaBytes, warningAvailableBytes, usedBytes, reservedBytes, availableBytes, usageRatio, objectCount, status, accountingStatus, writeBlocked, reminderVersion, thresholdReminderPending, calculatedAt`。首版个人配额 `reservedBytes=0`、`writeBlocked=false`，`availableBytes=max(0, quotaBytes-usedBytes)`。`usageRatio` 按真实已用量可超过 100%，可用空间为 0 时 `status=full`。其余状态为 `safe / warning`；`accountingStatus` 为 `ready / degraded`。 |
| 用户 `POST /api/v1/me/storage-usage/reminders/ack {reminderVersion}` | 成功返回 204。按本人和提醒版本幂等确认已展示，旧版本回执不能清除较新的提醒。                                                                                                                                                                                                                                                                                                                                                                                    |
| 管理员 `GET/PATCH /api/v1/admin/settings/storage`                    | GET 返回 `{revision,quotaBytes,warningAvailableBytes}`。PATCH 提交 `expectedRevision` 及至少一个配置字段，省略字段保留原值。两项可同时修改，按合并后的值校验整数且 `0 < warningAvailableBytes < quotaBytes`。后台用 GiB 展示，服务端用字节保存。并发保存时旧版本返回 409，审计记录管理员及修改前后值。                                                                                                                                                          |

**C1 与验收。**

1. 登录及资产写入成功后刷新用量。默认配置下验证可用空间恰为 1 GiB、低于 1 GiB 和为 0 的边界。满额提醒优先，按版本确认后重登不重复弹。调额、调阈值或清理使用户跨入提醒区、升至满额或回到安全后再次跨入时，按新状态生成提醒。同一状态内刷新或保存相同值不会反复弹窗。
2. 同一对象被多个目录、作品或头像引用仅计一次。核对上传、生成成品、内部派生物和回收站。删除一处引用仍可读取，最后一处有效持有释放后用量减少。存量账号和新账号分别对账，计量异常展示统计状态。
3. 在 `mio-admin-web` 将配额从 5 GiB 改为 8 GiB，旧账号保持登录，在保存成功后的下一次查询立即读到 8 GiB，新账号首次查询也是 8 GiB。只改阈值时，已有账号依新阈值触发或解除提醒且配额保持原值。再测同时改两项、刷新及重启后回读、普通用户写入被拒、非法组合与旧版本冲突。
4. 将一个已用 6 GiB 的账号降额到 5 GiB，显示“已用 6 GiB / 配额 5 GiB”、剩余 0 和满额提醒。用本来符合上传、生成条件的输入分别完成一次新增写入，均按实际大小继续计量。已有作品仍能查看、下载、删除。清理至安全区后解除提醒。新增上传拦截、生成空间预留及超额拒绝留给后续独立需求。
