# Web 个人中心 PRD

**评审稿。** 已登录的 Web 用户可以管理身份与资料、查看作品动态并清理个人空间。管理员可以发布公告、设置创作日志保留天数，以及调整个人空间配额和提醒阈值。各单元说明产品规则与验收条件，评审决定汇总在文末。标为“候选”的 HTTP 接口供后续开发，当前可调用的接口以[API 领域导航](../../apis/index.md)为准。

## 交付顺序与共同约定

| ----------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| U1 资料与头像     | 改昵称或用 GIF 设置头像，重登仍能看到保存后的资料  | 先接通 Cookie 会话、资料展示和私有资产读取。                                                                                                                                                                                                                            |
| U2 登录方式管理   | 换绑手机或重新绑定微信、万联后仍进入同一账号       | 复用 U1 展示视图；按已绑定／未绑定两态覆盖个人中心与登录页重绑路径及换绑／解绑后的多设备会话保留。                                                                                                                                                                      |
| U3 账号注销       | 本人确认后立即关闭账号，所有设备失去访问权         | 注销时释放登录身份，24 小时内清完普通在线数据；正式媒体物理删除复用[统一资产库 PRD](../unified-asset-library/prd.md)共享物理 GC（上线前置：将 `avatarAssetId` 及活跃对话视觉引用纳入统一引用保护，且共享 GC 退出 dry-run 并满足 ≤ 24 小时收敛），普通备份按 30 天轮转。 |

| U5 创作日志       | 图片、视频、音频三类结果在同一个消息中心可查、可读 | 三类媒体同日开放，管理员在 `mio-admin-web` 设置全局保留天数。                                                                                                                                                                                                           |
| U6 存储用量与提醒 | 管理员调整配额，用户看到生效值、用量和清理入口     | 去重计量依托[统一资产库 PRD](../unified-asset-library/prd.md)的归属引用汇总（C0 前置将 `avatarAssetId` 及活跃对话视觉引用纳入持久引用层）；首版交付计量、后台配置和提醒，满额后仍可继续创作。                                                                           |

- **身份与前端接入。** 普通用户用 Mio Cookie 恢复会话。`GET /api/auth/get-session` 的空会话返回 `null`，`GET /api/v1/me` 的未登录响应为 401。页面依据服务端身份决定是否请求资料、通知和用量。网络故障或 503 显示可重试状态。退出沿用 `POST /api/auth/sign-out`。切换账号后丢弃旧会话的在途回执和预览。前端适配现有错误码到中文提示。当前用户相关的操作由服务端取身份，写请求沿用本域的 Origin 校验。[认证 HTTP 契约](../../apis/auth.md)
- **账号菜单。** 展示头像、昵称、脱敏手机号、微信和万联的绑定情况以及空间用量，提供编辑资料、管理资产及退出入口。管理入口由独立管理端核验 `GET /api/v1/admin/auth/me`。万联登录绑定状态 `onelinkBound`、用户凭据是否已配置、图像与视频水印分别取自各自契约。凭据和水印沿用 `/api/v1/providers/onelink`，菜单只消费所需展示状态。[管理员身份](../../apis/admin.md) · [万联用户配置](../../apis/providers.md)
- **接受方式。** C0 核对本单元的范围、决定与依赖，C1 在候选实现上验证下列场景。分别记录后端契约回归和目标 Web 客户端联调。需要真实微信或短信的场景注明实际环境、是否收到验证码或完成扫码。隔离替身、测试短信和真实用户操作分别留证。文档评审与各单元的业务接受各自登记。[规划交付要求](../../coordination.md#规划交付要求)

## U1 资料与头像

**复用与缺口。** `GET/PATCH /api/v1/me/profile` 已支持 `displayId`、昵称、`avatarAssetId`、手机号验证状态以及微信、万联绑定标志。默认资料返回手机号原值，头像用资产 ID 表示。`POST /api/v1/assets/uploads`、浏览器 PUT 和 `POST /api/v1/assets/{id}/complete` 已能完成私有直传。现行头像核验支持本人 ready 的 JPEG、PNG、WebP。通用资产下载地址为短期地址，头像还需要浏览器可直接展示的地址。[认证资料](../../apis/auth.md) · [资产上传与读取](../../apis/assets.md) · [对象存储约束](../../integrations/cos.md)

**C0 与候选接口。** 建议给现有 GET、PATCH 增加 `?view=display`，两种响应均只包含 `userId, displayId, name, avatarAssetId, avatarUrl, maskedPhoneNumber, phoneNumberVerified, wechatBound, wechatNickname, onelinkBound`。保留现有调用方的默认响应。`avatarUrl` 按本人当前资产签发短期可内联地址，持久身份仍用 `avatarAssetId`；`GET`、仅改昵称或清空头像（`avatarAssetId: null`）的 `PATCH` 以及写后签发 `avatarUrl` 阶段遇到资产库或签名服务暂不可用时，仍返回 `200`、保留 `avatarAssetId` 并将 `avatarUrl` 降级为 `null`，避免媒体域抖动级联阻断用户资料与身份读取；但绑定**新的非空 `avatarAssetId`** 时仍按现行契约 fail-closed 强核验归属、实际大小、ready 状态与类型，资产核验不可用时返回 `503`。微信展示名取自服务端已核实的微信授权资料，缺失时显示“已绑定”。盘点默认资料的消费者。已确认接受不超过 20 MiB 的 GIF 并保存为静态 WebP。候选 `POST /api/v1/me/profile/avatar/normalize {sourceAssetId}` 直接在主服务 A 内完成（不引入 RabbitMQ 或计算 Worker B 绕行）：复核本人已就绪的 GIF 原件、实际格式与大小，仅解码首帧（`pages: 1`），实施硬像素与尺寸上限（如总像素 ≤ 16MP、单边 ≤ 8192）防止解压炸弹，限制进程内解码并发并在并发打满时快速返回 `503` 保护认证与对话线程，输出有界尺寸的静态 WebP 并返回 `{avatarAssetId}`，随后沿用资料 PATCH。相同原件重试复用转换结果，作为头像输入的临时原件按 U6 暂存规则处理。

**C1 与验收。**

1. 旧账号缺 `displayId` 时展示 `userId`，未绑手机、未绑微信分别显示“未绑定”。检查资料 GET 和 PATCH 回执均仅带脱敏号。普通用户不获得管理权限。
2. 昵称失焦只提交有变化的 `name`。页面最多编辑 20 字，允许字母、数字、汉字、下划线、连字符、点和空格。连续相同符号合并，保存时去除首尾符号和空格。服务端默认契约继续支持 1–50 个 Unicode 字符。历史较长昵称在只改头像时完整保留。快速连续修改时以最近一次已确认保存的值为准，失败保留输入并允许重试。写请求已发出时，关闭弹窗提示操作仍可能生效，重新打开后用服务端资料核对。
3. 用户选择不超过 20 MiB 的头像后立即预览，完成直传和登记。JPEG、PNG、WebP 沿用原路径。用恰好 20 MiB 的有效动图验证可接收，超过大小上限、超像素／单边尺寸上限或解压炸弹／解码失败有明确提示，解码并发打满时快速返回 `503` 且不阻塞正常资料读取。保存后 `avatarAssetId` 指向静态 WebP，刷新和重登都只显示同一帧。绑定新的非空 `avatarAssetId` 时 fail-closed 强核验归属、实际大小、ready 状态和类型，资产核验不可用时返回 `503`；他人或未就绪资产不能设成头像，上传、转换或保存失败时恢复上次确认的头像。`GET`、仅改昵称或清空头像的 `PATCH` 以及写后签发 `avatarUrl` 遇资产库或签名服务暂不可用时，资料接口仍返回 `200`、保留 `avatarAssetId` 并降级返回 `avatarUrl: null`；地址过期后可重新获取。

## U2 登录方式管理

**复用与缺口。** 个人中心的手机操作仅开放换绑，认证域的首次绑号和注册流程沿用现行契约。微信已支持匿名登录、首次注册及近期原会话内的 `POST /api/auth/link-social`。万联已有 `POST /api/auth/onelink/start` 的登录、绑定两种意图，以及 `mioOneLinkPending` 候选暂存与 `POST /api/auth/onelink/complete` 的确认动作。两者都需补解绑及无手机号账号在登录页验证已有账号的能力；微信还需将 `/api/auth/callback/wechat` 的未绑定扫码改为建号前暂存候选，对齐万联的显式确认流程。[认证 HTTP 契约](../../apis/auth.md) · [微信授权](../../integrations/wechat.md) · [万联登录与绑定](../onelink-login/prd.md) · [短信预算](../../integrations/tencent-sms.md)

**C0 与候选接口。** 按服务商与稳定外部身份仅维护两种状态：**当前已绑定**与**当前未绑定**（统一覆盖从未绑定与已解绑场景，不维护“曾主动解绑”永久第三态或解绑历史墓碑）。微信和万联解绑后各有两个重绑入口。**在个人中心**，已登录用户选择服务商：微信扫码后在微信端授权，返回个人中心查看结果；万联扫码授权后由本人确认绑定。**在登录页**，用户扫当前未绑定的微信或万联二维码时，服务端绝不自动建号或自动签发会话，而是创建短时待确认候选（`candidate_ready`），在本次登录流程内并列提供**「验证并绑定已有账号并登录」**和**「创建新账号」**（`create`）两个显式选择；选择绑定已有账号并完成验证后即可直接登录原账号，无需往返个人中心。扫码完成只证明持有该第三方身份，确认成功前不会据此签发登录会话或新建账号。换绑手机号或解绑微信、万联后，当前设备和其他设备上原本有效的 Mio 会话均保持登录，期限和原有失效条件沿用现行契约。认证短信预算层须对换绑、绑定已有账号与 U3 注销类验证码做独立子预算隔离，避免其异常突刺耗尽全站日常登录注册短信日配额。

| 操作               | 接入与回执                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 更换已绑定的手机号 | 候选 `POST /api/auth/phone-rebind/send-otp {phoneNumber}` 返回 `{status,expiresIn}`，`POST /api/auth/phone-rebind/confirm {phoneNumber,code}` 返回 `{status:true}`。要求近期原会话和已有验证号。手机号统一为认证域规范格式，页面可接受中国大陆 11 位输入。向新号发码（受独立非登录短信子预算保护），确认时在同一事务复核本人、发起会话、原号码和新号唯一性，一次性消费挑战，随后回读 U1。无手机号时显示“未绑定”。                                                                                                                                                                                                                    |
| 个人中心重绑       | 微信沿 `link-social` 发起官方二维码授权，个人中心只显示“等待授权”和最终结果。回调后回读原 `userId` 与 `wechatBound=true` 才显示绑定成功。万联沿 `onelink/start` 的 `intent=bind` 发起授权，用 `bind_current` 显式确认，成功后回读原 `userId` 与 `onelinkBound=true`。                                                                                                                                                                                                                                                                                                                                                                |
| 登录页未绑定微信   | 复用微信登录二维码、`sign-in/social` 与授权回调。在 `/api/auth/callback/wechat` 采用与万联一致的建号前回调暂存模式，命中当前未绑定身份时不让 Better Auth 自动建号，而是写入短时待确认候选（`candidate_ready`）并下发专用 `Path=/api/auth` HttpOnly 待处理 Cookie（对称 `mio.onelink_pending`），二维码与 `sign-in/social` 未绑定回调共用同一确认流程；候选扩展 `GET /api/auth/wechat/qr-session/{qrcode_id}/poll` 返回 `pending_confirm`（需候选确认，不要求用户会话 Cookie）。页面保留本次扫码候选，提供「验证并绑定已有账号并登录」与「创建新账号」（`create`），候选 `POST /api/auth/wechat/pending/confirm` 确认后建立登录会话。 |
| 登录页未绑定万联   | 从 `onelink/start` 的 `intent=login` 打开万联授权二维码。命中当前未绑定身份时直接复用 `mioOneLinkPending`（`candidate_ready`）与 `GET /api/auth/onelink/pending`，登录页并列展示「验证并绑定已有账号并登录」与「创建新账号」。目标有已验证手机号时，复用 `POST /api/auth/onelink/existing/send-otp` 及 `onelink/complete` 的 `link_existing`；用户明确建新号时沿用 `onelink/complete` 的 `create`，确认成功后直接登录。                                                                                                                                                                                                              |
| 解绑微信或万联     | 候选 `DELETE /api/v1/me/wechat`、`DELETE /api/v1/me/onelink`。本人二次确认后撤下登录关联和相应展示资料并回读 U1，不记录永久解绑历史态。解绑前校验还剩至少一种实际可用登录方式，包括本人已有验证号且短信登录可用、本人已设真实密码且邮箱登录可用，或另一个已绑定且可用的服务商。万联的供应商凭据继续按其独立契约管理。                                                                                                                                                                                                                                                                                                                |

登录页复用已有登录方式验证目标账号：有号可在绑定界面通过手机验证码核验已有号码；无号或短信停用时，保留本次扫码候选，在同一流程内通过该账号另一种有效方式取得近期会话，再显示脱敏目标账号并确认。微信手机路径建议补 `POST /api/auth/wechat/pending/send-otp`，将验证码绑定到本次扫码候选和目标手机号，由 `POST /api/auth/wechat/pending/confirm` 统一消费；万联无号路径需补登录意图下衔接近期目标会话的确认，现有 `bind_current` 仍只服务由原会话发起的绑定。目标身份均由服务端核验。当前已绑定身份沿用正常直接登录；当前未绑定身份均进入确认页，绝不自动回到旧账号或未经确认暗中建号。最后一次确认须复核账号有效、身份仍可绑定、扫码候选未过期且属于本次浏览器操作；过期、重放、跨浏览器或解绑前发起的旧回调均拒绝，不得覆盖新绑定。

**C1 与验收。**

1. 向新号发换绑码，60 秒后可重发，实际有效期、频率与子预算隔离由服务端控制（换绑、绑定已有账号与注销验证码突发不耗尽全站日常登录注册短信配额）。成功后新号进入原 `userId`，旧号失去原账号访问权。覆盖无号调用、当前号、已占用号、并发争用、过期码和跨会话／用途的验证码。固定测试码（bypass 模式）同样核验发起会话／待处理归属（live 模式同时核验挑战归属）。注销专用码只向当前已验证号码发送。
2. 用同一个仍有效的账号逐一验证四种组合：微信在个人中心重绑、微信从登录页扫码重绑、万联在个人中心重绑、万联从登录页扫码重绑。每次先解绑；登录页两例须能看到含「验证并绑定已有账号并登录」与「创建新账号」的确认界面，确认前无此次扫码生成的新号或业务会话，选择验证并绑定已有账号且确认后直接进入原 `userId` 且相应绑定标志为真。覆盖无手机号账号在登录页使用另一有效方式完成验证。
3. 分别验证当前已绑定身份能直接登录，当前未绑定身份（含从未绑定与已解绑）扫码后均进入确认页，选择「创建新账号」（`create`）可正常建立独立新 `userId`，选择「验证并绑定已有账号并登录」进入原账号。取消、验证失败、扫码过期、切换账号、身份已被占用、迟到／重放／跨浏览器回调或重复确认均不会误绑或暗中建号；拒绝移除最后一种实际可用登录方式。已注销账号按 U3 处理。登录页沿用微信二维码轮询接口获取授权结果。
4. 同一账号在 A、B 两台设备登录。在 A 分别执行手机换绑、微信解绑、万联解绑；每次操作后，两台设备用原 Cookie 刷新资料并继续访问本人资源，仍是同一 `userId`。再用未登录的浏览器验证旧手机号不能进入原账号，已解绑第三方扫码后进入待确认页（不自动回到旧账号，确认前不建新号或签发会话）。已退出、已撤销或自然过期的会话仍然无效。
5. 在个人中心发起微信绑定，分别在扫码前、手机已扫码但尚未授权时查看页面，两次均显示“等待授权”。授权成功后核对回调和本人绑定标志，再显示成功。授权取消、过期或失败时显示可核实的结果并允许重新发起，回读失败时可重试核对。登录页的微信二维码也只显示等待授权和最终结果；若命中未绑定身份，授权通过后轮询返回 `pending_confirm`，进入「验证并绑定已有账号并登录」／「创建新账号」确认流程。

## U3 账号注销

**复用与缺口。** 认证域已有锁定用户、设置禁用状态、在同一 PostgreSQL 事务内撤销全会话的能力。管理员停用允许解禁。个人主动注销需要独立的永久终态、身份释放及持久清理记录。现有资产清理器只回收过期上传的暂存对象，正式媒体的引用核对与物理删除统一依托[统一资产库 PRD](../unified-asset-library/prd.md)的共享物理 GC 管线落地，本单元不另建第二套平行 COS 引用删除器。[账号状态与会话](../../auth.md) · [认证事务](../../../src/auth/account.ts) · [现有 COS 清理范围](../../integrations/cos.md) · [资产引用与物理清理](../unified-asset-library/prd.md)

**C0 与候选接口。** 个人中心只提供“立即永久注销”。确认前告诉用户，所有设备将退出，原账号和作品无法恢复，需保留的作品应提前下载。已有已验证手机号时，候选 `POST /api/auth/account-deletion/send-otp` 向当前号码发注销专用码，挑战绑定本人、发起会话和号码。候选 `DELETE /api/v1/me` 提交 `{code}`。无手机号时，要求近期原会话和页面明确二次确认，提交 `{}`。

以注销事务提交的服务端时刻为 **T0**。在认证库的一个短事务内复核本人及挑战、将旧 `userId` 置为永久注销、撤销全部会话、解除并释放手机号、微信、万联及可登录邮箱，使旧验证码和绑定候选失效，并以旧 `userId` 为唯一键登记清理任务。全部提交后清除 Cookie 并返回 `{status:true,finalizedAt}`。登记失败则整个事务回滚。提交成功但响应丢失时，已登记的唯一任务继续执行。T0 认证事务提交后立即触发一次进程内尽力唤醒，第一时间撤销／清空 `providers` 凭据、取消该用户活跃对话回合，并将无 PII 的最小注销墓碑 `{userId, finalizedAt}` 归档至外部 COS 审计前缀，压缩从 T0 到后台清理栅栏之间的外部计费与崩溃窗口（唤醒短暂失败时由持久清理任务重试兜底，并作为 `completedAt` 前置门禁）。T0 起旧号不能登录、解禁或通过 U2 重绑恢复。同一身份可按正常流程注册全新 `userId`。后续清理只认旧 `userId` 及其确切资源，重新注册不会带回旧资料，也不会让新数据进入旧任务。

现有微信首注会为同一个 AppID 与 openid 生成固定占位邮箱。若保留旧用户行，注销事务还须将其邮箱唯一值替换为与登录身份无关的唯一技术值，释放微信首注所需的占位值。现有绑定回调可能在会话被撤销后才落库，因此最终写入第三方关联须与注销事务锁定同一用户并复核有效状态。旧回调即使在 T0 前通过验证，也不能在 T0 后重新占用身份。[微信身份与回调约定](../../integrations/wechat.md)

### 24 小时在线清理与 30 天备份轮转

**重试、防止数据重新出现及完成口径。** 对仍会异步写入的域，先持久记录旧 `userId` 已关闭。任务的最终保存和发布须在本域事务内据此复核，使注销前领取的任务或重连 Worker B 的迟到回传都不能在清理后写回；若迟到回传已将产物上传至 COS，A 须将其已校验的 COS 输出／清单对象键转交精确键物理清理／共享 GC 回收，避免产生 COS 孤儿对象。再按旧 `userId` 与原任务身份分批清除。已注销的结果不再发布为作品或日志，不重新向供应商提交生成。跨库通过各域的持久回执衔接，每次确认一批后才推进游标；对 A 本机原生日志与恢复文件，先确认文件移除或保留待删定位，重启后可幂等处理同一批。只有全部在线适用域已完成、旧 `userId` 正式资产逻辑引用归零且共享物理 GC 覆盖其零引用独占对象、`mio/staging` 暂存加速清零、外部最小注销墓碑已归档、例外对象有明确依据、在途写入收束且末次复查无待删在线项时才写 `completedAt`；离线 Worker B 的后续重连对账不阻塞 `completedAt`。任务入队与单域中间批次都只是中间进度。

**逾期监控。** 运维监控最老待清任务的年龄、失败环节、剩余量及执行器心跳，告警检查独立于清理执行器。任务到 20 小时仍未完成时预警，到 24 小时仍未完成时记为超时并告警。短暂故障可按 1、5、15 分钟退避。权限或归属异常保留进度并告警，修复后接续同一任务，保留原截止时间和实际完成时间。

**普通备份与灾备恢复。** 普通备份按 **30 天滚动轮转**。最迟到 **T0 + 30 天**，普通备份中含旧账号待删数据的副本须全部淘汰。清理期间制作的备份及其后续复制都沿用该账号的原截止日。轮转期内恢复旧备份时，从独立于数据库快照的外部最小注销墓碑归档（如专用私有 COS 审计前缀中的 `{userId, finalizedAt}`）取得最新注销清单，避免从被回滚的认证库自身读取注销记录的循环依赖；对恢复点之后注销的账号重放注销，对快照中已经注销但仍有待删数据的账号按旧 `userId` 补清。各域核对旧号无法登录、应清数据已移除，再开放服务。法定留存仅限有依据的最少记录，隔离保存并到期清理。普通备份、第三方独立托管和有依据的保留项分别记录，在线清理单独验收。[《个人信息保护法》第十九条、第四十七条](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)

**C1 与验收。**

1. 已绑号提交空码、换号后提交旧码或提交其他用途验证码均拒绝。无号用户用近期原会话明确确认可成功，过期会话被拒绝。验证注销和任务登记同成同败，成功时两台设备均立即失效、T0 后即时唤醒撤销 `providers` 凭据并取消活跃对话回合，普通后台解禁和旧扫码均不能恢复旧号。
2. 用原手机号或第三方身份立刻注册新号并创建数据，旧任务执行前后均只能影响旧 `userId`。另验微信首注账号注销后用同一微信注册出不同 `userId`，以及微信绑定回调先通过会话验证、注销提交后才尝试落库，旧绑定不能写回，新账号仍可绑定。投递一条注销前已受理的迟到结果，并覆盖仍有效的旧 5 分钟直传 PUT 地址，复核不会重新发布作品、泄漏凭据或漏清新到的 `mio/staging` 暂存旧对象。
3. 在隔离环境制造“注销提交后、执行器领取前重启”“批次删除成功但尚未记回执就重启”“共享 PG 域两实例并发领取”“某个在线域或共享物理 GC 暂不可用”“Worker B 离线与重连对账”。观察同一任务接续、分批重试与末次核对，验证共享文件和其他用户数据仍可读取。清单覆盖认证、对话元数据及持有本地卷实例的 `DSH_HOME` 原生日志、A 本机媒体恢复文件、`mio/staging` 暂存加速清理、正式资产逻辑引用释放与统一资产库共享物理 GC 收敛；离线 Worker B 不阻塞 `completedAt`，重连后完成自身本地清理，迟到回传由 A 按墓碑拦截不发布并回收其已校验的 COS 输出／清单对象，无旧数据回流或 COS 孤儿泄漏。
4. 以代表性的大创作账号与小账号并发注销及注销高峰验证按轮公平时间片（大账号不队头阻塞小账号）与 `completedAt − T0 ≤ 24 小时`，逐域核对在线记录、逻辑引用清零和共享物理 GC 独占文件删除。用可控时钟验证 20 小时预警、24 小时超时告警。超时后接续成功仍能查到原违约记录。
5. 在隔离环境核对备份策略、独立于 PG 快照的无 PII 外部最小注销墓碑归档与实际副本清单。轮转期内分别还原注销前、注销已提交但在线清理尚未完成的快照，验证恢复流程从外部墓碑读取最新清单并重放注销／按旧 `userId` 补清，复核无误后才开放服务，原身份即使已用于新账号也无法读到旧数据。查验备份及其复制件在 T0 + 30 天的实际清单，含旧账号待删数据的普通副本须全部淘汰。

## U4 系统公告

**复用与缺口。** 管理员认证、管理端写入鉴权和操作审计已有实现。需要新增公告内容、草稿和发布状态、弹窗开关，以及每个用户独立的已读记录。沿用独立管理前端和普通 Web 客户端各自的身份。[管理 HTTP 契约](../../apis/admin.md) · [管理后台职责](../web-admin-console/prd.md)

**C1 与验收。** 管理员保存一条草稿时 A、B 均不可见，发布启用后两人均可见。A 关闭弹窗、“我知道了”或打开公告详情后更新同一条已读记录，刷新或重登后不再弹，B 仍能收到。另发布新版公告，令 A 只读新版且留有未读旧版，验证下次登录返回空，旧版仍可从列表打开。写已读失败允许关闭并明确提示下次可能再提醒。“查看全部公告”进入消息中心系统通知页签。停用或删除后从用户列表和弹窗移除。验证普通用户不能发布、查草稿或替他人标记已读。

## U5 创作日志

**复用与缺口。** 图片、视频、音频已有持久任务 ID、用户归属及可核对的结果。图片、视频会分别登记成功输出。音频任务和作品记录可以与成品资产分库，须在作品发布后读取结果。三个生产入口的业务结果进入「消息中心 → 创作日志」，共用查询和已读记录，**三类媒体须同日对用户开放**。保留策略可复用 `mio-admin-web` 的全局配置页面，以及管理域的鉴权、版本校验和操作审计。现有全局设置接口仅接收认证配置，创作日志需要新增独立配置项和读写接口。[图片和视频任务](../../apis/compute.md) · [音频任务与作品](../../apis/audio.md) · [管理设置契约](../../apis/admin.md#patch-apiv1adminsettingsglobal)

**C0 与候选接口。** 首发建议采用下列消息口径。用户能区分“已有可查看的作品”“部分作品已保存”和“本次创作确定失败”。

| 媒体 | 何时记一条消息                                                                             | 避免误报                                                                            |
| ---- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 图片 | `completed` 记成功。`partial` 且已有可用作品时记部分成功。明确拒绝或不可恢复的失败记失败。 | 保存待恢复、结果未知和后台重试不产生失败消息。                                      |
| 视频 | 按该视频任务已登记的输出记成功或部分成功；无可用输出且确定失败才记失败。                   | 取消申请、轮询和转码进度不报成失败；部分成功经恢复变为全部成功时可记一次新结果。    |
| 音频 | 任务 `ready` 且作品记录已发布时记成功；确认无可恢复结果的失败才记失败。                    | `unknown`、正在保存和带可恢复检查点的 `failed` 延后判断。供应商受理本身不触发成功。 |

候选 `GET /api/v1/notifications?type=creation_log&page=1&pageSize=10` 返回 `{items,page,pageSize,hasMore,nextCursor}`。消息中心滚动加载下一页时附带上一页返回的游标 `cursor`，按发生时间和 ID 稳定倒序续读。单条含 ID、媒体类型、任务 ID、结果类型、标题、可公开给本人的简短摘要、发生时间及已读状态。`PATCH /api/v1/notifications/{id}/read` 幂等标记本人已读。系统通知页签由 U4 提供，团队协作维持待开放。未读总数、全部已读和单条删除随对应用户操作另排。

**管理员设置保留天数。** 管理员在 `mio-admin-web` 的「全局配置 → 创作日志」设置全站保留天数。首次配置前显示“未设置”，正常账号可查看已有消息，按天清理从首次保存有效天数起执行。候选 `GET /api/v1/admin/settings/creation-logs` 返回 `{revision,retentionDays}`，未设置时分别为 `0` 和 `null`。同路径 `PATCH` 接收 `{expectedRevision,retentionDays}`，天数须为正整数，非法值返回 400。保存沿用现有管理域单事务模式：在**管理库单事务**内完成配置更新、`expectedRevision` 409 冲突校验与管理员操作审计落库，返回新版本和生效值；用户读取热路径通过短 TTL（≤ 5 秒，写实例保存后立即刷新）的进程内只读快照消费，不跨连接池同步穿透管理库。

**变更与到期。** 配置保存后，新老账号从下一次查询起按新值生效（写实例即时生效，多实例短快照模式下至多 5 秒内收敛），包括游标续页。消息从原发生时刻满 `retentionDays × 24 小时` 时到期，已读与未读使用同一时限。首次设置或缩短期限时，后台在保存前提示管理员超出期限的旧消息会被清理。保存后超期消息立即在读取窗口过滤并退出列表，对其标记已读返回 404。因读侧已即时按新窗口过滤，后台采用**限速分批清理**（小批量 `LIMIT` + 批次间隔节流 + `SKIP LOCKED`）清除到期消息及已读状态，每批删除时核对当前策略，避免大幅缩短天数引发 WAL 与 autovacuum 风暴。延长期限后，仍在库的消息按新窗口展示，已清除的消息不回填。迟到补投按原发生时间判断，已超期的事件结束投递，已完成的投递不因调长而重放。作品、生成历史和 U4 公告沿用各自规则，已注销账号的消息仍按 U3 在 24 小时内清理。

**已确定的存储方案。** 首版使用 PostgreSQL，将用户创作消息表建在**媒体域 PostgreSQL 数据库**（`MIO_ASSETS_DATABASE_URL`）。每个有意义的结果保存一条小记录，`read_at` 存已读时间。进度轮询、执行器重试、原始供应商响应及媒体文件留在各自现有位置。查询按用户、时间及 ID 读取下页，可用 `(owner_id, occurred_at DESC, id DESC)` 索引；`(owner_id, media_type, job_id, event_kind)` 唯一约束配合 `ON CONFLICT (owner_id, media_type, job_id, event_kind) DO NOTHING` 保证重试只留一条。图片与视频生产者在媒体域同库，直接在结果提交的**同一 PostgreSQL 事务**内写入创作消息，免除三类媒体中两类的跨库 outbox 开销。仅对跨库的**音频**生产者（位于 `providers` 库）使用单向 outbox：在结果事务内登记带稳定 `event_id` 的待投递事件，并施加**硬性最大重试窗口**（如自 `occurred_at` 起 `7 天`，超窗未达则停止重试并告警／转死信）；媒体库在同一事务内写入消息并记录固定 TTL 去重回执 `(event_id, recorded_at)`（超期事件仅记回执），回执按固定 TTL **生产者最大重试周期 + 1 天**（例如自 `recorded_at` 起 `8 天`）到期自动清理——在 `retentionDays = null` 时同样定义明确、不随长保留期膨胀，且因生产者超窗即停止重试，任意缩短再延长的配置序列均无法使已清理消息复活，不引入双向“生产者确认回收回执”握手协议。[项目 PostgreSQL 约定](../../integrations/postgres.md) · [PostgreSQL 多列索引](https://www.postgresql.org/docs/18/indexes-multicolumn.html)

已配置保留期限时，消息量可按**每日产生的业务结果数 × 管理员设置的天数**估算。上线前用代表性数据测每条记录连同索引的字节数、峰值写入、个人列表翻页延迟及故障后补投积压。若出现明确瓶颈，先验证索引、归档或按时间分区的收益，按已选的 PostgreSQL 方案安排容量扩展。[PostgreSQL 表分区](https://www.postgresql.org/docs/18/ddl-partitioning.html)

**C1 与验收。**

1. 分别通过图片、视频、音频的实际生产入口完成一次创作，同一用户当天在同一列表看到三种结果。逐类用成功、确定失败和适用的部分成功／可恢复样例核对消息。模拟故障或状态回放的证据与真实创作记录分别登记。三条链路均达标后才开放首发。
2. 同一结果重复处理只出现一次。已有一项成功的任务随后全部完成，可以看到含义不同的部分成功和完成消息。中断消息写入再恢复，图片与视频随结果同事务一致落库、音频可通过单向 outbox 从已持久化事实补记，均保留原发生时间，无需重新生成或再次向供应商提交。
3. 混合三类媒体、同一时间存在多条且共超过 10 条时，连续翻页核对顺序、缺项和重复。A 读一条后刷新、重登仍为已读；B 无法查看或标记 A 的消息。空列表和加载失败各有可辨认的页面状态。
4. 管理员在 `mio-admin-web` 看到“未设置”，普通用户在自己的创作日志中可查到一条 15 天前的消息。管理员首次保存 14 天后，普通用户刷新列表（写实例即时生效，多实例短快照模式下至多 5 秒内收敛）时该消息退出。管理员刷新配置页、重启服务后均能回读 14 天。普通用户无法配置，零、负数和小数被拒。两名管理员基于同一版本保存时，后一次收到 409，审计可查成功变更的操作者和前后值。
5. 从 14 天缩至 7 天，新策略生效后（写实例即时生效，多实例短快照模式下至多 5 秒内收敛）在固定时刻查询已有账号的已读、未读消息和新账号的新消息。刚满 7 天的消息立即退出列表且无法标为已读，未满 7 天的消息仍可见，旧游标也遵循新窗口。核对后台按限速小批次实际清理超期消息；音频单向 outbox 受硬性最大重试窗口（如 7 天）约束，窗口内迟到补投在固定 TTL 去重回执（最大重试周期 + 1 天）保护下不令已清理消息重现，超窗未达则停止重试并告警／转死信。准备两条 10 天前的消息，清除其中一条后将期限延至 21 天。下一批清理应保留另一条，后者重新可查，已清除的那条不会恢复。核对作品、生成历史及系统公告仍可访问，注销账号仍按 U3 期限清理。

## U6 存储用量与提醒

**复用与缺口。** 资产层已有用户归属、底层对象身份、大小与就绪状态。生成成品可登记为 `derived`，只筛 `original` 会漏算。资产库已规划目录、回收站与引用保护。现有旧库迁移范围排除了旧通知和旧配额，首次用量需从当前有效资产核对。`mio-admin-web` 已有全局配置页，管理域具备管理员鉴权、版本冲突检查及审计；现有 `/api/v1/admin/settings/global` 写入体仅接收认证配置。[资产契约](../../apis/assets.md) · [生图产物登记](../../../src/generations/image/store.ts) · [资产库规划](../unified-asset-library/prd.md) · [迁移范围](../legacy-migration/prd.md) · [管理配置契约](../../apis/admin.md#patch-apiv1adminsettingsglobal)

**C0 与候选接口。** 默认每人 **5 GiB**，可用空间**低于 1 GiB** 提醒，等于阈值仍为安全，用尽显示满额。本人上传和持有的生成成品按底层对象去重。内部预览、HLS 分片、暂存和仅由供应商托管的对象排除。回收站与当前头像、作品等有效引用继续占用，到最后一处有效持有释放才扣减。计量依托[统一资产库 PRD](../unified-asset-library/prd.md)的 `(owner_id, asset_id)` 引用汇总维护按用户物化／索引的去重汇总（配合周期性后台对账），**禁止**在高频账号菜单 `GET /api/v1/me/storage-usage` 路径执行跨表实时 `DISTINCT` 扫描。C0 跨 PRD 前置须将 `avatarAssetId` 及活跃对话视觉引用纳入统一资产库的持久引用层与 GC 持有方集合，确保在用头像既受 GC 保护又被物化汇总准确计入。桌面本机空间和付费扩容另行规划。

管理员在 `mio-admin-web` 的“全局配置 → 存储空间”里可分别调整**配额**和**提醒阈值**。写入沿用管理域单事务模式：在**管理库单事务**内完成配置更新、`expectedRevision` 409 校验与操作审计落库，用户读取热路径通过短 TTL（≤ 5 秒，写实例保存后立即刷新）的进程内只读快照消费，避免每次打开账号菜单跨连接池查库。服务端保存成功后即对所有存量及新账号按新值计算（写实例即时生效，多实例短快照模式下至多 5 秒内收敛），无需重登、重启或逐账号更新。**首版只做计量和提醒。** 即使已用量超过新配额，也展示实际用量。个人空间配额不会禁用上传、生成、查看、下载或清理入口，也不预埋限写或降级死字段，待后续独立限写 PRD 获批后再增量引入相关字段。

**C1 与验收。**

1. 登录及资产写入成功后刷新用量，验证 `GET /api/v1/me/storage-usage` 严格只读且不含预埋限写／降级死字段。默认配置下验证可用空间恰为 1 GiB、低于 1 GiB 和为 0 的边界。满额提醒优先，按 `reminderVersion` 确认后重登不重复弹。调额、调阈值使生效配置变更（`configRevision` 递增），或清理引发任一向下降级（`full → warning` 或回落 `safe`，推进 `waterlineEpoch`）后再次向上跨入提醒区／满额时，均生成新的 `reminderVersion` 并提醒（显式覆盖 `full` 已确认 → 清理回落 `warning` → 再写入重回 `full` 场景）。同一状态内刷新或管理员保存相同配置值（`revision` 不递增）不会反复弹窗。
2. 同一对象被多个目录、作品或头像引用仅计一次，且从物化去重汇总读取而非热路径实时跨表 `DISTINCT`。核对上传、生成成品、内部派生物和回收站。删除一处引用仍可读取，最后一处有效持有释放后用量减少。存量账号和新账号分别对账；资产库或计量查询不可用时返回标准 `503` 并展示可重试状态。
3. 在 `mio-admin-web` 将配额从 5 GiB 改为 8 GiB，旧账号保持登录，保存成功后的下一次查询（写实例即时生效，多实例短快照模式下至多 5 秒内收敛）读到 8 GiB，新账号首次查询也是 8 GiB。只改阈值时，已有账号依新阈值触发或解除提醒且配额保持原值。再测同时改两项、刷新及重启后回读、普通用户写入被拒、非法组合与旧版本冲突。
4. 将一个已用 6 GiB 的账号降额到 5 GiB，显示“已用 6 GiB / 配额 5 GiB”、剩余 0 和满额提醒。用本来符合上传、生成条件的输入分别完成一次新增写入，均按实际大小继续计量。已有作品仍能查看、下载、删除。清理至安全区后解除提醒。新增上传拦截、生成空间预留及超额拒绝留给后续独立需求。
