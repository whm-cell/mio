# Mio 画布接口承接 PRD

**状态**　待评审。本文规划 `miioo` 画布接入 Mio 的产品行为、接口与验收。第 1–4 期是建议的本期开发单元，第 5、7、8 期可独立排期，第 6 期保留编号说明旧画布专属目录方案的退役与统一资产库的分工衔接。各期新增接口均为候选，当前仅交付规划。开发授权、候选验证和业务接受沿项目的[当前任务的生命周期](../../coordination.md#当前任务的生命周期)与[规划交付要求](../../coordination.md#规划交付要求)分别记录。[任务资料入口](../index.md) · [统一资产库 PRD](../unified-asset-library/prd.md)

## 用户目标与首个里程碑

登录用户创建一个项目，在其中打开多张画布，连接文本和媒体节点，明确选择本节点的当前输出。关闭页面后，用户能重新看到布局、选择和在途任务，并能查明一次生成用了哪些输入。首期面向用 Mio 账号新建个人画布的创作者。剧本、分集、协同编辑、整图自动调度和全站账号迁移分别有不同的权限或执行要求，留在本规划范围外。

**第 3 期的首个业务验收点**是“手写文本 → 图片节点生成 → 选中结果 → 刷新 → 下游再次使用所选图片”。第 4 期再用模型生成的文本走通同一条链。这样在文本上下文策略确定前，也可以验收真实的画布创作流程。

## 跨期接口约定

下面表格中的业务路径均省略 `/api/v1`。以 `/api/auth/` 开头的路径为完整路径。**复用**沿现行契约，**新增**与**扩展**在对应开发单元采纳后再纳入现行 API 文档。私有请求使用 Mio 登录 Cookie，写请求沿允许的精确 Origin 和 JSON 约定。服务端从会话取得 owner。跨用户资源按不可访问处理，错误沿 `{error:{code,message,requestId}}`。错误体里的 `requestId` 用于 HTTP 追踪，客户端写请求里的 `requestId` 标记一次用户操作。存储事务、私有对象签名与供应商提交分别遵循既有集成约束。[PostgreSQL](../../integrations/postgres.md) · [COS](../../integrations/cos.md) · [OneLink](../../integrations/onelink.md)

- **保存和重试。** 有幂等要求的创建、保存、结果写入、生成、复制和批量操作使用客户端稳定 UUID。同一用户在同一操作作用域重试相同输入时，先返回原操作或原回执，再处理新写入的版本校验。同键异参返回 409。独立编辑产生新键。客户端仅在明确知道原操作结果后更新本地版本。
- **文档与结果。** PostgreSQL 保存项目、画布文档及其 `revision`。节点以 `(canvasId,nodeId)` 定位，`nodeId` 支持前端已有的字符串标识。画布文档保存节点、草稿、参数、有序输入关系、分组与视口。可信结果由节点结果记录保存，生成来源由执行服务写入。节点另有 `currentResultId` 和 `outputVersion`。当前输出改变才推进该版本，单纯追加历史保留当前选择。GET 画布可一并投影各节点当前输出摘要，历史按需分页。布局撤销/重做只修改可编辑文档。
- **受理与结算。** 前端先完成草稿保存和所选输出登记，再发起执行。A 在短事务中核对画布、节点、`baseRevision` 与目标 `expectedOutputVersion`，冻结当时直接上游的顺序、槽位、正文或 `resultId/assetId`、版本，以及本次操作、模型和参数。上游引用只取自已保存的图。本次模型选项以受理请求为准，服务器按模型能力白名单校验。持久保存执行身份后才调用底层服务。页面刷新按原执行查询。服务在受理、下游回执、结果入库之间中断时，按原身份对账。
- **归档与删除。** 明确区分**归档**与**最终销毁**：现阶段画布项目与画布的 `DELETE` 语义固定只做**封存归档**，使项目/画布退出活动列表并停止新执行，但**继续持有全部有效媒体引用以支持重开与已受理任务回看**；迟到结果可从原执行查询，已删除的节点不会重新出现。“彻底销毁项目”本期不做、以后再考虑，因此现阶段仅明确的业务位置移除（删除媒体节点或清除独立输入槽并成功 `PATCH` 保存）释放画布引用。生成历史隐藏/恢复、我的资产文件删除/恢复与画布归档各自独立生效，仍可重开的结果、保留版本和在途任务继续保护底层原件；物理原件遵循统一资产库 U3 的 7 类有效持有关系全释放规则，全部持有解除后才进入物理清理。[删除与引用矩阵](../unified-asset-library/prd.md#6-删除与引用矩阵) · [回收站与物理清理](../unified-asset-library/prd.md#7-回收站与物理媒体清理)

## 第 1 期 · 项目、多画布与保存

**C0**　确认首发是否只接新建个人画布。建议保留前端“活动项目至少有一张画布”的规则，归档项目时整体退出活动列表。用代表性图文样本确定画布写入的字节、节点及连线边界。本地序列化样例含 32 个短文本和图片节点、16 条连线，文档已有 10,266 字节，应能正常保存。Mio 默认 JSON 读取上限为 8,192 字节，需要给此入口单独设限。[文档序列化](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/canvas/CanvasDocument.js#L253) · [请求读取器](../../../src/http-request.ts)

**C1 与前端**　先接 `CanvasProjects.js`、`UseCanvasProjects.js` 和 `CanvasPage.jsx` 的正式登录、建项目、打开入口，再接 `api/canvas.js`、`CanvasSaveSession.js` 的保存队列。由画布请求层把 camelCase 转为页面使用的字段，并读取 Mio 的错误体。替换 token/refresh 前置判断。把旧 `client_save_id/base_revision` 映射为稳定的 `requestId/baseRevision`。账号切换清理旧缓存和订阅。服务端校验节点唯一、父组存在且无环、有序来源指向本画布节点。新建文档为空。第 1 期保存仅接受已开放的字段，提前传入资产或结果引用时拒绝整次写入。第 2 期开放后按引用归属校验。以节点有序来源及槽位为准，按序列化规则校核重复表达的 `businessBindings`，不一致时保留原稿并报错。拖动、框选、连线、折叠与撤销沿已有本地交互，保存时统一提交。[前端保存队列](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/canvas/CanvasSaveSession.js)

**验收**　登录后建项目并模拟丢失创建响应，同键重试只得到原项目和首张画布。添加第二张，移动节点、连线、分组、缩放，关页重开后逐项一致。两个标签页从同一版本保存不同修改，后到者看到冲突并保留本地草稿。两个并发归档请求不能删空活动项目。验证确立的大小边界，超出时返回 413，原版仍能打开。另一账号读取或修改该画布不能取得内容。

## 第 2 期 · 私有资产、手工文本与当前输出

**C0 与排期**　画布第 1 期先提供真实 `canvasId`、节点和带版本的保存入口。统一资产库 [U1](../unified-asset-library/prd.md#u1--身份契约统一历史与引用保护底座) 提供稳定 `assetId`、显式引用保护底座、统一解析与生成历史，[U2](../unified-asset-library/prd.md#u2--我的资产文件库搜索与专用本地上传) 提供我的资产个人目录树与全库活动文件名搜索。两边对齐新选材与已有作品重开的权限、结果和槽位何时建立与解除引用、媒体类型及批量上限（建议沿用每批最多 200 个 ID）。画布可先做手工文本、结果历史、当前输出和选择器交互。U1/U2 交付解析、引用登记/释放与选材能力后，画布接入正式选材、节点结果写入与文档保存，并与 U1/U2 以同一次保存和重开联合验收；回收站清空与到期后的物理清理另随统一资产库 [U3](../unified-asset-library/prd.md#u3--30-天可恢复回收站与物理媒体-gc) 验证。[跨模块联合验收](../unified-asset-library/prd.md#跨模块联合验收)

- **验收。** 核对画布内部历史与全局历史共享同一 `historyId`；从画布内或全局删除一条历史均进入 30 天回收站并双向同步隐藏，刷新重开后节点当前输出与保留版本（含四图节点）完整保留且可重签读回；从回收站恢复后双向重新可见且不改变节点当前选择。将源画布的历史结果放入本人另一画布时不新增生成历史，删除源历史后两个画布的文件仍可打开。复制期间断线后查回同一副本，供应商调用数不增加。另一账号不能查询操作。陈旧排序返回冲突并保留当前顺序。「添加到新画布」的端到端验收随统一资产库 U4 联合执行。

### 第 6 期 · 旧资产目录方案退役

产品将资产一级入口统一调整为“生成历史、我的资产、Seedance 认证素材库、回收站”。旧方案中的画布专属集合与项目共享目录壳子退役（不为旧隐藏画布目录建兼容网盘），而**个人 10 层目录树、移动/复制、全库文件名搜索、目录清单签名与前端流式 ZIP 打包（应用服务器不中转文件字节）由统一资产库 [U2](../unified-asset-library/prd.md#u2--我的资产文件库搜索与专用本地上传) / [U4](../unified-asset-library/prd.md#u4--添加到新画布与下载清单签名) 的「我的资产」统一提供**；画布通过第 2 期选材、第 5 期同源历史、U4「添加到新画布」及持久引用与之协作。保留本期编号用于已有计划的追溯，四个菜单的接口、前端改造与业务验收归[统一资产库 PRD](../unified-asset-library/prd.md)，此处不再安排独立画布目录接口或开发单元，第 5 期的复制与排序可按自身依赖推进。

跨画布与归档保护仍保留对应回归：两张画布（或一个已归档画布项目与一张活动画布）引用同一 `assetId`，从生成历史删除并清空回收站后均可重签读回原件；仅在活动画布移除对应的媒体节点并成功 `PATCH` 保存后，另一张画布或已归档项目仍持有有效引用，原件不得被 GC 清理。最后一处释放、个人库副本最后解除及同一画布内多处位置的清理验证一并归统一资产库 [U3](../unified-asset-library/prd.md#u3--30-天可恢复回收站与物理媒体-gc) 与[清空与到期后的引用验收](../unified-asset-library/prd.md#清空与到期后的引用验收)。

### 第 7 期 · 公开分享、授权复制与本地文件

- **C0 与接口。** 确定分享当前已保存版本的可见字段、媒体范围、撤销后的短链有效期和跨账号导入后的资产归属。新增 `GET/PUT /canvases/{id}/share` 管理状态与令牌，`GET /canvas-shares/{token}` 返回公开投影，`GET /canvas-shares/{token}/assets/{assetId}` 只解析该分享内可见媒体。`POST /canvas-shares/{token}/imports` 由登录用户指定本人目标并返回操作 ID。建议为获准导入的媒体建立接收者可独立使用的合法资产，再发布副本。
- **C1 与前端。** `SharedCanvasPage.jsx` 匿名读公开接口，忽略登录刷新流程，展示可公开文档与当前媒体。服务端剥离私有结果历史、执行输入快照和凭据。现有 `.miioo.json` 由浏览器导出，可内嵌本地媒体。导入合并到当前画布并重分配节点 ID。内嵌媒体先走上传，已有资产重新校验归属，再用第 1 期保存。只有将来要求“上传文件创建新画布”时再定义 `POST /canvases/imports`。[文件交换实现](https://github.com/miioo-aigc/miioo/blob/1c1b36339afb1f0db026d0809a3c688d285200c2/frontend/src/components/canvas/UseCanvasFileActions.js)
- **验收。** 匿名访客可读分享媒体，无法读取作者的其他资产或历史。关闭或轮换令牌后旧入口停止签发地址，已签地址按约定到期。同一导入请求只产生一个副本，撤销来源分享后按已选归属策略核对接收者权限。本地文件合并保留原画布和内部连线，无法取得的媒体有明确提示，不创建可信生成记录。

### 第 8 期 · 视频、音频、认证素材与扩展编辑

- **C0 与接口。** 以精确操作、模型、输入规格及真实可用的结果/取消/恢复能力为单位选片。视频、音频和高级编辑扩展第 3 期 `POST /canvases/{id}/executions` 的操作白名单，继续复用查询、结果和选择；每个成功持久化媒体输出在同一确认链路上事务接入统一资产库 [U1](../unified-asset-library/prd.md#u1--身份契约统一历史与引用保护底座) 生成历史登记，按 `(executionId, index)` 去重，多输出部分成功保留成功项不撤销，保存的二次编辑独立结果（裁剪、重绘、消除、扩图、超清、视频剪辑、抽帧等）另记新输出与新历史、原结果保留，未保存预览/缩略图/播放转码/视频封面不入历史，回调/恢复重放幂等且尊重历史不可复活墓碑；平台不新增删除单个生成版本的能力，画布不新增导出视频能力。认证素材浏览复用 `GET /materials/groups`、`GET /materials/groups/{id}/materials`；用于视频执行仅允许有效认证身份，须由服务端验证本地 `materialId` 归属与认证状态后再解析上游身份，**服务端严禁向前端返回上游 `supplier_asset_id`**。既有单路转码仍沿 `POST /compute/jobs`；画布大视频播放所需的画布规格派生（`video.derivatives` `profile="canvas"` 及私有 HLS 鉴权入口，属内部附属派生物、不进入生成历史）以及视频剪辑（`video.trim`）、抽帧（`frames.extract`）等通用媒体编辑操作统一对接[通用媒体处理设计](../compute-service/media-compute.md)（待对应计算单元 M1–M3 接受后接入，显式保存的编辑独立结果按本节既有规则接入 U1 生成历史）。扩图、超清等模型侧编辑仅在确定具体业务服务后排入相应切片。[通用媒体处理设计](../compute-service/media-compute.md) · [视频 PRD](../onelink-video-generation/prd.md) · [音频 PRD](../onelink-audio-generation/prd.md) · [万联素材库 PRD](../onelink-material-library/prd.md)
- **C1 与前端。** `UseCanvasVideoGeneration.js`、`UseCanvasAudioGeneration.js` 和编辑面板按已就绪操作接入执行接口，提供该模式要求的槽位、限制和恢复动作。已上传视频/音频可以先作节点资产。认证素材选择器仅放行有效认证身份，预选后若在提交前发生失效，必须由服务端拦截并返回明确认证错误引导重新认证（**普通网络错误绝不判定为认证失效**）；**认证失效或删除认证素材/组不影响已生成的画布媒体与既有引用**。普通生成与认证素材联动独立验收。
- **验收。** 为每个开放模式用真实支持的最小规格完成一次受理、状态查询、持久资产登记、统一生成历史登记与重开展示；核对保存的二次编辑独立结果新记历史且原结果保留，回调/恢复重放不重复登记且不复活已彻底删除的历史。对不支持的输入返回明确原因。认证素材的归属或状态不符（含预选后失效）在提交前由服务端拦截并引导重新认证，验证普通网络错误不误判认证失效、响应不含上游 `supplier_asset_id`、认证失效或删除不影响已生成画布媒体，未知状态不重发。一个模式通过只承认该模式。[素材库已接受范围](../onelink-material-library/complete/report.md)

## 验收环境与首发决策

业务联调使用正式前端入口和真实画布 ID，联调时设置 `VITE_CANVAS_DEV_MOCK=false`，资产库 mock 开关保持关闭。选两个不同账号和同一账号的两个标签页，记录前后端候选、请求/执行/资产 ID、版本、操作前后的可见状态及必要的脱敏回执。重复、并发、故障与部分成功优先在隔离回归环境用可控响应验证。模型与 COS 的业务闭环在常驻开发环境逐次执行已授权的最小规格调用，保存原请求身份、实际产物与结论。外部结果未知时保留原记录，只沿支持的原身份核对。[常驻环境与回归边界](../../local-environments.md) · [验证与接受](../../coordination.md#验证与接受)

各期接受以该期用户入口跑通、适用的归属/冲突/恢复场景通过、持久事实与用户所见一致为条件。UI 模拟、单项已有服务成果和静态检查分别说明其覆盖。已采纳的 HTTP 契约随对应实现进入所属 API 域。当前画布端到端场景均待开发和验证。

首发优先决定三件事。第一，个人新建画布能否独立上线。若要无感承接存量，先以获准样本核对旧账号到 Mio 用户、旧文档到新节点/结果、旧文件到 Mio 底层资产与画布持久引用的映射（不自动塞入我的资产、不为旧隐藏画布目录建兼容网盘），以及在途任务的查询依据，再单独规划迁移验收。[旧后端数据迁移 PRD](../legacy-migration/prd.md) · [存量归位边界](../unified-asset-library/prd.md#9-存量归位边界) 第二，按第 1 期样本确定文档容量边界（现阶段画布项目与画布删除固定只做封存归档并继续持有全部有效媒体引用，“彻底销毁项目”本期不做、以后再考虑，仅明确的业务位置移除释放画布引用）。第三，在第 4 期前确定文本上下文与离页行为。分享授权与视频模式的决定分别留在对应扩展期。
