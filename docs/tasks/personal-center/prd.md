# Web 个人中心 PRD

**评审稿。** 已登录的 Web 用户可以管理身份与资料、查看作品动态并清理个人空间。管理员可以发布公告、调整默认云端配额。本轮已确认的产品规则见各单元，仍需产品决定的事项集中在文末。标为“候选”的 HTTP 接口供后续开发，当前可调用的接口以[API 领域导航](../../apis/index.md)为准。

## 交付顺序与共同约定

| 单元              | 首个可验收结果                                     | 依赖与顺序                                                |
| ----------------- | -------------------------------------------------- | --------------------------------------------------------- |
| U1 资料与头像     | 改昵称或用 GIF 设置头像，重登仍能看到保存后的资料  | 先接通 Cookie 会话、资料展示和私有资产读取。              |
| U2 登录方式管理   | 换绑手机或重新绑定微信、万联后仍进入同一账号       | 复用 U1 展示视图，分别核对三个登录入口。                  |
| U3 账号注销       | 本人确认后立即关闭账号，所有设备失去访问权         | 复用会话撤销与短信用途隔离，开放前补定保留和清除规则。    |
| U4 系统公告       | 管理员发布，用户收到最新公告，已读跨登录保留       | 可与 U1、U2 并行，管理端与用户端分别鉴权。                |
| U5 创作日志       | 图片、视频、音频三类结果在同一个消息中心可查、可读 | 共用查询与已读接口，三个生产入口分别验收后同日开放。      |
| U6 存储用量与提醒 | 管理员调整配额，用户看到生效值、用量和清理入口     | 计量、后台配置和提醒可先验收。新增写入是否强制拦截待 D7。 |

- **身份与前端接入。** 普通用户用 Mio Cookie 恢复会话。`GET /api/auth/get-session` 的空会话返回 `null`，`GET /api/v1/me` 的未登录响应为 401。页面依据服务端身份决定是否请求资料、通知和用量。网络故障或 503 显示可重试状态。退出沿用 `POST /api/auth/sign-out`。切换账号后丢弃旧会话的在途回执和预览。前端适配现有错误码到中文提示。当前用户相关的操作由服务端取身份，写请求沿用本域的 Origin 校验。[认证 HTTP 契约](../../apis/auth.md)
- **账号菜单。** 展示头像、昵称、脱敏手机号、微信和万联的绑定情况以及空间用量，提供编辑资料、管理资产及退出入口。管理入口由独立管理端核验 `GET /api/v1/admin/auth/me`。万联登录绑定状态 `onelinkBound`、用户凭据是否已配置、图像与视频水印分别取自各自契约。凭据和水印沿用 `/api/v1/providers/onelink`，菜单只消费所需展示状态。[管理员身份](../../apis/admin.md) · [万联用户配置](../../apis/providers.md)
- **接受方式。** C0 核对本单元的范围、决定与依赖，C1 在候选实现上验证下列场景。分别记录后端契约回归和目标 Web 客户端联调。需要真实微信或短信的场景注明实际环境、是否收到验证码或完成扫码。隔离替身、测试短信和真实用户操作分别留证。文档评审与各单元的业务接受各自登记。[规划交付要求](../../coordination.md#规划交付要求)

## U1 资料与头像

**复用与缺口。** `GET/PATCH /api/v1/me/profile` 已支持 `displayId`、昵称、`avatarAssetId`、手机号验证状态以及微信、万联绑定标志。默认资料返回手机号原值，头像用资产 ID 表示。`POST /api/v1/assets/uploads`、浏览器 PUT 和 `POST /api/v1/assets/{id}/complete` 已能完成私有直传。现行头像核验支持本人 ready 的 JPEG、PNG、WebP。通用资产下载地址为短期地址，头像还需要浏览器可直接展示的地址。[认证资料](../../apis/auth.md) · [资产上传与读取](../../apis/assets.md) · [对象存储约束](../../integrations/cos.md)

**C0 与候选接口。** 建议给现有 GET、PATCH 增加 `?view=display`，两种响应均只包含 `userId, displayId, name, avatarAssetId, avatarUrl, maskedPhoneNumber, phoneNumberVerified, wechatBound, wechatNickname, onelinkBound`。保留现有调用方的默认响应。`avatarUrl` 按本人当前资产签发短期可内联地址，持久身份仍用 `avatarAssetId`。微信展示名取自服务端已核实的微信授权资料，缺失时显示“已绑定”。盘点默认资料的消费者。已确认接受不超过 20 MiB 的 GIF 并保存为静态 WebP。候选 `POST /api/v1/me/profile/avatar/normalize {sourceAssetId}` 复核本人已就绪的 GIF 原件、实际格式与大小，取第一帧生成静态 WebP，返回 `{avatarAssetId}` 后沿用资料 PATCH。相同原件重试复用转换结果，作为头像输入的临时原件按 U6 暂存规则处理。

**C1 与验收。**

1. 旧账号缺 `displayId` 时展示 `userId`，未绑手机、未绑微信分别显示“未绑定”。检查资料 GET 和 PATCH 回执均仅带脱敏号。普通用户不获得管理权限。
2. 昵称失焦只提交有变化的 `name`。页面最多编辑 20 字，允许字母、数字、汉字、下划线、连字符、点和空格。连续相同符号合并，保存时去除首尾符号和空格。服务端默认契约继续支持 1–50 个 Unicode 字符。历史较长昵称在只改头像时完整保留。快速连续修改时以最近一次已确认保存的值为准，失败保留输入并允许重试。写请求已发出时，关闭弹窗提示操作仍可能生效，重新打开后用服务端资料核对。
3. 用户选择不超过 20 MiB 的头像后立即预览，完成直传和登记。JPEG、PNG、WebP 沿用原路径。用恰好 20 MiB 的有效动图验证可接收，超过上限或解码失败有明确提示。保存后 `avatarAssetId` 指向静态 WebP，刷新和重登都只显示同一帧。绑定处复核归属、实际大小、ready 状态和类型。他人或未就绪资产不能设成头像，上传、转换或保存失败时恢复上次确认的头像。地址过期后可重新获取。

## U2 登录方式管理

**复用与缺口。** 认证域已有首次绑号接口 `POST /api/auth/phone-binding/send-otp` 和 `POST /api/auth/phone-binding/confirm`。个人中心的手机操作仅开放换绑，已有注册和登录流程沿用现行契约。微信可用近期原会话发起 `POST /api/auth/link-social`。现有微信匿名扫码支持首次注册。万联已有 `POST /api/auth/onelink/start` 的登录、绑定两种意图及 `POST /api/auth/onelink/complete` 的确认动作。两种第三方登录都需要补解绑，以及解绑后匿名登录的识别规则。[认证 HTTP 契约](../../apis/auth.md) · [微信授权](../../integrations/wechat.md) · [万联登录与绑定](../onelink-login/prd.md) · [短信预算](../../integrations/tencent-sms.md)

**C0 与候选接口。** 换绑向**新号**发验证码，注销向**当前已验证号**发验证码。微信、万联解绑后，只能先用另一种有效方式进入本人账号，再在个人中心发起一次新的绑定。仅当绑定成功，该第三方身份才恢复登录资格。手机号按认证域的规范格式存储，页面可接受中国大陆 11 位输入。

| 操作               | 接入与回执                                                                                                                                                                                                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 更换已绑定的手机号 | 候选 `POST /api/auth/phone-rebind/send-otp {phoneNumber}` 返回 `{status,expiresIn}`，`POST /api/auth/phone-rebind/confirm {phoneNumber,code}` 返回 `{status:true}`。要求近期原会话和已有验证号，向规范化后的新号发码。确认时在同一事务复核本人、发起会话、原号码和新号唯一性，一次性消费挑战，随后回读 U1。无手机号时显示“未绑定”，无独立解绑操作。 |
| 绑定或重新绑定微信 | 用 `link-social` 提供的官方授权地址站内展示二维码，同源回调后回读 U1，以原 `userId` 且 `wechatBound=true` 确认成功。若 D2 确有中间态需求并取得可信信号，再补 `POST /api/auth/wechat/bind-session` 和 `GET /api/auth/wechat/bind-session/{ticket}/poll`。                                                                                            |
| 绑定或重新绑定万联 | 复用 `onelink/start` 的 `intent=bind`，查看待绑定身份，在原近期会话用 `bind_current` 确认，回读同一 `userId` 和 `onelinkBound=true`。登录解绑仅解除本地登录关联，用户已配置的供应商凭据继续按原契约管理。                                                                                                                                           |
| 解绑微信或万联     | 候选 `DELETE /api/v1/me/wechat`、`DELETE /api/v1/me/onelink`。二次确认后撤下当前绑定及相应展示资料，返回最新展示视图。服务端先确认至少还有一种实际可用的登录方式，核对短信是否启用、邮箱是否启用且设有真实密码、其他已绑定服务商当前是否可用。                                                                                                      |

认证域需要能区分“从未绑定”和“曾主动解绑”的第三方身份，按服务商及稳定身份保留最小解绑记录。匿名扫码或授权命中后，引导用户改用其他方式登录。微信不能借首次注册创建新号，万联不能通过匿名 `create` 或 `link_existing` 恢复关联。会话签发、建号与绑定确认时都以最新状态为准，解绑前发起的迟到回调和待确认操作不能恢复资格。重新绑定沿用既有唯一归属校验。

**C1 与验收。**

1. 已绑号用户对新号发码，60 秒后可重发，实际有效期、频率与预算由服务端控制。换绑后新号进入原 `userId`，旧号不能进入原账号。覆盖无号调用、当前号、已占用号、并发争用、过期码、跨会话和跨用途验证码，原绑定在失败时保留。固定测试码同样核验挑战的用途、用户、发起会话和新号。
2. 微信、万联各走一遍“解绑 → 退出 → 用同一第三方身份尝试登录 → 改用其他方式登录 → 在个人中心重新绑定 → 再次通过第三方进入原账号”。解绑期间核对零新号、零新登录会话、零意外关联。另测从未绑定的新身份、迟到回调、重复确认、其他账号已占用和仅余一种登录方式。
3. 扫码取消、过期或在回调前切换账号，页面均须回读真实绑定状态。若采用轮询，每 2 秒串行查询，页面隐藏暂停，连续三次失败可重新发起。换绑和解绑前分别登录两台设备，按文末 D2 所选策略验证存量会话。

## U3 账号注销

**复用与缺口。** 认证服务已有事务内禁用账号、撤销全部会话以及受保护入口核验禁用状态的能力。自助注销还需独立的注销状态、本人确认及数据处置。普通管理员解禁只能作用于管理员停用的账号。[账号状态与会话](../../auth.md) · [账号控制与资料扩展](../ai-drama-foundation/changes/auth-account-controls-and-profile/change.md)

**C0 与候选接口。** 已确认采用软注销。已绑手机时，候选 `POST /api/auth/account-deletion/send-otp` 仅向当前已验证号发码，按发起用户、会话和该号码绑定注销专用挑战，返回 `{status,expiresIn}`。候选 `DELETE /api/v1/me` 在有号时提交 `{code}`，无号时要求近期原会话并在页面明确二次确认后提交 `{}`。成功返回 `{status:true}` 并清除当前 Cookie。注销立即关闭原账号、撤销所有设备的会话。原手机号、微信和万联身份先保留占用，在途任务停止新增外部提交。已经提交的结果按最终保留或清除规则处理。具体时限及例外见文末 D3。

**C1 与验收。** 注销页先展示已确定的后果。用有号、无号账号分别从两台设备验证。已绑号提交空码、发码后换号、使用登录或换绑验证码，以及无号账号近期会话失效时，账号继续可用。合法确认后，注销与全会话撤销原子提交，两端均失去访问权，旧身份无法重新进入，普通后台解禁不能恢复。对一项排队任务和一项已经提交的任务，分别核对外部提交次数和结果去向。开放前按 D3 的期限对账身份占用、资产、任务与凭据的处置。

## U4 系统公告

**复用与缺口。** 管理员认证、管理端写入鉴权和操作审计已有实现。需要新增公告内容、草稿和发布状态、弹窗开关，以及每个用户独立的已读记录。沿用独立管理前端和普通 Web 客户端各自的身份。[管理 HTTP 契约](../../apis/admin.md) · [管理后台职责](../web-admin-console/prd.md)

**C0 与候选接口。** 已确认只检查已发布、已生效、启用且允许弹窗的最新一条公告，按发布时间和 ID 倒序确定先后。若最新一条已读，弹窗接口返回空。更早的有效公告仍在列表中。公告卡片至少提供 ID、标题、正文、发布时间和本人已读状态。

| 使用方   | 候选接口                                                                                                                                                                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理员   | `GET/POST /api/v1/admin/announcements` 查询、创建草稿。`PATCH/DELETE /api/v1/admin/announcements/{id}` 编辑、启停或确认删除。`POST /api/v1/admin/announcements/{id}/publish` 发布。支持设定是否弹窗，写入保留管理员及操作记录。                         |
| 登录用户 | `GET /api/v1/announcements?page=1&pageSize=10` 按发布时间和 ID 倒序返回 `{items,page,pageSize,hasMore}`。`GET /api/v1/announcements/latest-popup` 在登录后返回 `{announcement: 对象或 null}`。`POST /api/v1/announcements/{id}/read` 幂等记录本人已读。 |

**C1 与验收。** 管理员保存一条草稿时 A、B 均不可见，发布启用后两人均可见。A 关闭弹窗、“我知道了”或打开公告详情后更新同一条已读记录，刷新或重登后不再弹，B 仍能收到。另发布新版公告，令 A 只读新版且留有未读旧版，验证下次登录返回空，旧版仍可从列表打开。写已读失败允许关闭并明确提示下次可能再提醒。“查看全部公告”进入消息中心系统通知页签。停用或删除后从用户列表和弹窗移除。验证普通用户不能发布、查草稿或替他人标记已读。

## U5 创作日志

**复用与缺口。** 图片、视频、音频已有持久任务 ID、用户归属及可核对的结果。图片、视频会分别登记成功输出。音频任务和作品记录可以与成品资产分库，须在作品发布后读取结果。新增能力是把三个生产入口的业务结果送入同一个用户消息列表并记录已读。**三个入口须同日对用户开放。** [图片和视频任务](../../apis/compute.md) · [音频任务与作品](../../apis/audio.md)

**C0 与候选接口。** 首发建议采用下列消息口径。用户能区分“已有可查看的作品”“部分作品已保存”和“本次创作确定失败”。

| 媒体 | 何时记一条消息                                                                             | 避免误报                                                                            |
| ---- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 图片 | `completed` 记成功。`partial` 且已有可用作品时记部分成功。明确拒绝或不可恢复的失败记失败。 | 保存待恢复、结果未知和后台重试不产生失败消息。                                      |
| 视频 | 按该视频任务已登记的输出记成功或部分成功；无可用输出且确定失败才记失败。                   | 取消申请、轮询和转码进度不报成失败；部分成功经恢复变为全部成功时可记一次新结果。    |
| 音频 | 任务 `ready` 且作品记录已发布时记成功；确认无可恢复结果的失败才记失败。                    | `unknown`、正在保存和带可恢复检查点的 `failed` 延后判断。供应商受理本身不触发成功。 |

候选 `GET /api/v1/notifications?type=creation_log&page=1&pageSize=10` 返回 `{items,page,pageSize,hasMore,nextCursor}`。消息中心滚动加载下一页时附带上一页返回的游标 `cursor`，按发生时间和 ID 稳定倒序续读。单条含 ID、媒体类型、任务 ID、结果类型、标题、可公开给本人的简短摘要、发生时间及已读状态。`PATCH /api/v1/notifications/{id}/read` 幂等标记本人已读。系统通知页签由 U4 提供，团队协作维持待开放。未读总数、全部已读和单条删除随对应用户操作另排。

**存储选择。** 首版使用项目已采用的 PostgreSQL，在通知域建一张用户创作消息表。每个有意义的结果保存一条小记录，`read_at` 存已读时间。进度轮询、执行器重试、原始供应商响应及媒体文件留在各自现有位置。查询按用户、时间及 ID 读取下页，可用 `(owner_id, occurred_at DESC, id DESC)` 索引；`(owner_id, media_type, job_id, event_kind)` 唯一约束保证重试只留一条。同库可在一个事务中登记结果与消息；分库时可在生产者的结果事务内留一条待投递事件，按同一事件键补投。这样在音频作品已保存、消息暂未送达时可单独补记。[项目 PostgreSQL 约定](../../integrations/postgres.md) · [PostgreSQL 多列索引](https://www.postgresql.org/docs/18/indexes-multicolumn.html)

数据量由**每日产生的业务结果数 × 保留天数**决定。例如合计每日 10 万条、保留 90 天是 900 万条，仅作估算示例。目前缺少实际峰值与保留周期。上线前用代表性数据测每条记录连同索引的字节数、峰值写入、个人列表翻页延迟及故障后补投积压。若出现明确瓶颈，先验证索引、归档或按时间分区的收益，再评估引入独立文档数据库的成本。[PostgreSQL 表分区](https://www.postgresql.org/docs/18/ddl-partitioning.html)

**C1 与验收。**

1. 分别通过图片、视频、音频的实际生产入口完成一次创作，同一用户当天在同一列表看到三种结果。逐类用成功、确定失败和适用的部分成功／可恢复样例核对消息。模拟故障或状态回放的证据与真实创作记录分别登记。三条链路均达标后才开放首发。
2. 同一结果重复处理只出现一次。已有一项成功的任务随后全部完成，可以看到含义不同的部分成功和完成消息。中断消息写入再恢复，三类都可从已持久化的事实补记，保留原发生时间，无需重新生成或再次向供应商提交。
3. 混合三类媒体、同一时间存在多条且共超过 10 条时，连续翻页核对顺序、缺项和重复。A 读一条后刷新、重登仍为已读；B 无法查看或标记 A 的消息。空列表和加载失败各有可辨认的页面状态。

## U6 存储用量与提醒

**复用与缺口。** 资产层已有用户归属、底层对象身份、大小与就绪状态。生成成品可登记为 `derived`，只筛 `original` 会漏算。资产库已规划目录、回收站与引用保护。现有旧库迁移范围排除了旧通知和旧配额，首次用量需从当前有效资产核对。`mio-admin-web` 已有全局配置页，管理域具备管理员鉴权、版本冲突检查及审计；现有 `/api/v1/admin/settings/global` 写入体仅接收认证配置。[资产契约](../../apis/assets.md) · [生图产物登记](../../../src/generations/image/store.ts) · [资产库规划](../unified-asset-library/prd.md) · [迁移范围](../legacy-migration/prd.md) · [管理配置契约](../../apis/admin.md#patch-apiv1adminsettingsglobal)

**C0 与候选接口。** 默认每人 **5 GiB**，可用空间**低于 1 GiB** 提醒，用尽显示满额。本人上传和持有的生成成品按底层对象去重。内部预览、HLS 分片、暂存和仅由供应商托管的对象排除。回收站与当前头像、作品等有效引用继续占用，到最后一处有效持有释放才扣减。桌面本机空间和付费扩容另行规划。已确认由 `mio-admin-web` 配置额度。建议在“全局配置 → 存储空间”同一处调整额度和提醒阈值，新老账号下次读取用量时使用最新全局值。D7 决定超额时接收哪些新写入。

| 使用方与候选接口                                                     | 响应与规则                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用户 `GET /api/v1/me/storage-usage`                                  | 返回 `quotaBytes, warningAvailableBytes, usedBytes, reservedBytes, availableBytes, usageRatio, objectCount, status, accountingStatus, writeBlocked, reminderVersion, thresholdReminderPending, calculatedAt`。预留量用于已经受理但尚未结算的写入，无预留时为 0。`availableBytes=max(0, quotaBytes-usedBytes-reservedBytes)`，`status` 为 `safe / warning / full`，`accountingStatus` 为 `ready / degraded`。`writeBlocked` 反映已启用的服务端写入策略，满额和拦截分别展示。 |
| 用户 `POST /api/v1/me/storage-usage/reminders/ack {reminderVersion}` | 成功返回 204。按本人和版本幂等确认已展示，旧版本回执不能清除较新的提醒。                                                                                                                                                                                                                                                                                                                                                                                                    |
| 管理员 `GET/PATCH /api/v1/admin/settings/storage`                    | GET 返回 `{revision,quotaBytes,warningAvailableBytes}`。PATCH 仅需 `{expectedRevision,quotaBytes}`，保留当前提醒阈值。页面用 GiB 显示，配额须是正整数字节。若确定同时开放阈值编辑，PATCH 可选传 `warningAvailableBytes`，显式设置时须为正整数字节且小于配额。并发保存时旧版本返回 409，审计记录管理员和改动前后值。                                                                                                                                                         |

**C1 与验收。**

1. 登录和资产写入成功后刷新用量。默认配额下，可用恰为 1 GiB 仍为安全，低于 1 GiB 提醒，降为 0 后满额提示优先。展示后按版本确认，失败可重试，重登不重复弹已确认版本。升至满额、或清理回到安全区后再次跨阈值，都可收到新提醒。菜单可进入管理资产。
2. 同一对象被多个目录、作品或头像引用仅计一次。核对上传、生成成品、内部派生物和回收站，删除一处引用仍可读取；最后一处有效持有释放后用量减少。分别对账存量账号与新账号，计量异常须显示统计状态。
3. 管理员在 `mio-admin-web` 将 5 GiB 调为 8 GiB，保存、刷新、重启后值一致，按推荐的生效方式验证新老账号下次读取均看到 8 GiB。仅提交额度时原阈值保留。若允许同时调阈值，页面按新阈值提示。测试无管理权限、非法阈值、两位管理员用同一旧版本保存。降额到已用量以下显示满额，保留已有作品及查看、下载、清理入口。
4. **仅在 D7 选定拦截后验收。** 对纳入的上传或生成入口验证容量预留、按实际大小结算、取消或到期释放，以及并发申请和同一请求重试。走通“拒绝超额新写入 → 清理或调高额度 → 再次写入成功”。生成结果大于预估或已被供应商受理时，须验证结果可恢复且不会二次提交。

**D7 用一个网盘例子说明。** 账号还剩 100 MiB，你要上传一个 150 MiB 的视频。“只提醒”会告诉你空间不足，仍允许放进去，于是实际用量可以超过额度。“限写”会在上传前告诉你还差 50 MiB，清出 50 MiB 或管理员调高额度后就能再试。已有作品仍可打开、下载和删除。AI 生成多一步，点击生成时成品大小往往未知，等成品出来供应商可能已经计费，所以是否连生成也拦，需要单独选。

首批联合验收用同一账号贯穿修改资料、换绑手机号、解绑并重新绑定第三方、退出和重新登录，核对身份始终一致。公告、三类创作日志、注销和存储分别按所属单元取证。获批接口实施后再更新现行契约。[任务资料与成果入口](../index.md)
