# OneLink 模型目录刷新写入优化

```mio-change
{"version":1,"type":"fix","section":"W1：用户万联配置与模型能力目录"}
```

成功刷新原先将本配置全部当前模型标为 removed，再将返回成员 upsert 为 current。同一批 100 个模型重复刷新时，每个模型会发生两次行更新。随用户与刷新次数增加，这些中间状态更新增加数据库维护工作。

## 范围与契约

刷新事务只将本次完整目录中缺失的当前模型标为 removed。返回模型沿既有 upsert 更新元数据、凭据版本、目录版本与最近发现时间，复用稳定 model_key 与首次发现时间。精确 ID 按现有 C collation 比较，成功空目录仍移除全部当前成员。

每次成功继续发布新目录版本并使原验证失效，保留失败刷新、凭据轮换、刷新乱序、跨用户隔离和默认目标的现行规则。存储保持 PostgreSQL，用户模型成员数量仍按用户与曾发现的不同模型数增长。本单元减少中间状态写入，保留现有目录、历史实体与对外 discovery 数据。

## C0、C1 与验收

- C0 已核对用户的 PostgreSQL 优化目标、既有目录和身份契约，确定以删除重复状态更新作为本期开发单元。
- C1 修改刷新事务，在隔离 PostgreSQL 随机 schema 中通过行级触发器观察实际更新次数，并复用供应商、OneLink、对话及图片消费者的适用回归。
- 验收覆盖相同 100 模型目录刷新从 200 次模型行更新降为 100 次、仅移除缺失成员、重现复用身份、其它用户不受影响，以及现行空目录、失败、竞争和验证失效场景。质量审阅和规范对账绑定同一候选，完整检查覆盖依项目证据协议核对。

现行行为沿[供应商规范](../../../../providers.md)、[供应商 HTTP 契约](../../../../apis/providers.md)与[已有成果](../../complete/report.md)。本次优化不外推响应延迟、WAL 字节或生产容量的提升幅度，实际候选和验收状态从所属成果入口核对。
