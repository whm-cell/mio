# 协调工具的实现边界

操作判断与生命周期见[协调协议](../coordination.md)，字段与命令见[记录索引](../work-records.md)。本页用于修改工具时核对实现保证，不保存每轮实施经过。

## 职责与记录

任务协调位于 `scripts/harness/work/`，与工程护栏同属 `scripts/harness/`；Profile、启动与产物 smoke 位于 `scripts/service/`。两者按职责检查依赖，运行时不得导入。公共检查验证工具与公开资料，不读取成员私人记录；本地 `work check` 核对本人的任务。无需个人 Skills、后台服务或第二套进度台账。

ensure 用公共文档身份和稳定任务键定位记录；section 核对 Markdown 的真实唯一标题，更正 section 保留 source/key/ID。`revision` 是每次实际写入递增的整数，用于拒绝过期请求；`contractRevision` 只随目标、范围、授权、验收或规范等实质契约变化递增，进度和阶段更新不改变契约。正式候选 `{commit, contractRevision}` 中的 commit 是完整 Git 对象 ID。旧记录缺 revision 按 0 读取，首次正常编辑接入现行结构；旧候选字符串只作历史，不猜测 Git 对应关系或自动复用旧通过。

允许在脏工作区建档、修改计划和实施；`sync` 仅在提交且工作区干净时固定正式候选，正式 run、evidence、prepare、complete 也使用该候选。直接运行的脏工作区测试仅是反馈。候选由 Git 提交与任务契约标识，不建立所选文件内容哈希树、文件变更 watcher 或环境哈希；执行记录仍保存实际环境说明和原始证据的自动 checksum。

QUALITY-01 对真实源码 scope 触发算法成本、未使用公共 API 和已有实现复用审查；NORMS-01 对账需求／方案、现行规范和相关接受。CLI 核对原件的结构、候选和结论，不证明人工观察真实。维护不因审查创建开发 result。

## 分层读取与完整性

status 分页列任务，context／check 核对当前选中任务，guide 沿 Markdown 标题返回当前动作的章节入口，read 按需展开记录、核验和证据。输出有限，分页不要求手填内容哈希；读取期间现场变化时由使用者重新核对，不把不同次读取合成同一快照。操作成功、记录阶段、现场结论和真实接受分别表达。

每份 PRD 的 `documents.json` 登记公共需求资料的身份和位置；共享 resolver 核对归属、唯一性、路径与标题。变更索引由合法登记生成到所属 PRD 的固定路径。公共检查继续保护可发现性、链接及孤儿资料，独立于私人任务记录；具体归属见[资料导航](../index.md#增长与归属)。

## 每份 PRD 的公共包

可验收开发能力才设置 `plan.result={prd,key}`；维护在个人记录中核对和归档。公共成果位于注册 PRD 当前目录的 `complete/`。`records.json` 保存每项 key、名称、完成范围、入口、验证摘要、限制和接受声明，是唯一公共事实；`report.md` 由记录派生为导航，不再维护单独的记录内容哈希。新接受的 candidate 是 `{commit, contractRevision}`，已有历史接受和字符串候选保持原样。

read-result、receive 与公共检查沿注册 PRD 定位成果，不依赖全局成果索引或作者 `.work`。report 缺失或过期不隐藏有效 records：read-result 仍可读取；documents 在仅有派生导航漂移时列出有效 records／results，同时保留 issue 和非零退出。无效记录或孤儿产物仍拒绝。公共摘要无法恢复代码或原件；旧接受只证明当时明确接受的范围，不自动代表当前候选通过。

## 写入、恢复与保留

同任务 CLI 写操作通过锁串行化，revision 和原子比较并交换拒绝过期状态写入；读取和其他任务不因此阻塞。任务锁不提供代码隔离或跨任务公共文件的普遍事务。取消时等待执行子进程和执行组结算，无法确认结束保留未知及占用，不能靠时间或 PID 自动窃取；恢复步骤见[命令占用与异常恢复](../work-records.md#命令占用与异常恢复)。

run 在启动子进程前把指向唯一原始日志的观察保存为 pending，记录实际 argv、候选、环境、退出码／信号。进程组收束后才原位结算并计算日志 checksum；未收束时日志仍可能增长，保持 pending、无 checksum 和任务占用。起止两次核对干净状态与 HEAD 可以发现持续存在的漂移，但不能证明运行中没有改写后恢复；工具没有目录或 inode watcher。正式取证依靠独立 worktree、单写者，运行期间不编辑受验内容。后续失败或未知不能被旧通过掩盖。人工覆盖复核保留完整基线、实际 diff、定向增量、环境、目标和缺口，执行次数为 0 时不冒充命令；工具不维护跨任务自动证明链。详见[增量验证与同输入复用](../work-records.md#增量验证与同输入复用)。

人工原件放在忽略的任务 evidence 目录；普通、覆盖、质量与规范初稿由工具预填当前 candidate 和完整合同，其余必须来自实际观察。登记和后续核验按结构核对合同、原件及 checksum，不自动为旧无身份原件赋予当前候选，也不要求人工填写每页哈希。

prepare 在任务状态中冻结草稿并返回 opaque draftId；complete 再核对当前契约、checkpoint、必要原件和真实接受声明及来源。发布使用短暂锁，按 `records.json` → `report.md` → 任务状态逐项原子写入，保留兄弟成果；不维护交付 WAL 或要求人工传递草稿 SHA。已精确发布的同一 draft 与完整 result 可幂等读回及补状态，不倒推 revision；未完成恢复要求当前 revision。可补缺失 report、替换受验提交 C 中原有 report，或保留当前正确派生字节；人工改写的 report 拒绝覆盖，不能任意忽略脏文档或覆盖其他任务结果。受验代码提交 C 与发布文档后续提交 D 分别记录。

发布锁位于 `.work/publication/<所属 records 路径的稳定摘要>.lock`，占用错误给出具体路径。强杀留下锁时，先核对该发布进程与现场均已结束，再仅清除该标记并沿同一请求恢复；不根据 PID 或时间自动偷锁，也不重放旧 WAL。

首次发布从完整文件排他创建。替换既有文件使用 macOS 或 Linux 支持卷上的原子交换。工具会在目标父目录和恢复目录之间用空文件验证交换，并提前拒绝 Linux 的文件挂载点。预检失败时，工具在改写公共文件前报告 `WORK_PUBLISH_ATOMIC`。强杀中断预检时，确认进程结束后可清理留下的空 `.mio-publication-*.tmp` 探针文件。

交换取得实际被替换的文件。字节与发布前预期不符时，工具尝试原子恢复原文件并返回 `WORK_DELIVERY_CONFLICT`。恢复过程中再次被替换的编辑内容会留在错误所指的 `.work/publication/*.swap`，用于人工核对并保全两份版本。强杀可能把尚待核对的候选留在公共路径，后续 complete 在判断同一稿件能否重放前须处理该恢复文件。先保全独立编辑中的内容并确认公共记录和导航，再移出已核对的私有恢复文件并沿原请求恢复。

交接须实际取得固定代码和必要原件；接收方核对候选与授权，不自动继承通过或接受。`.work` 原件用于开发核验，archive 不删除文件；临时 fixture 可重建，不复制整仓作为长期成果。
