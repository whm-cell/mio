# 跨域质量修复计划

本期修复图片生成、对话、视频转码和工程检查中可分别验收的 11 项问题。授权覆盖本地实施和隔离验证。既有成果及其适用范围见各 PRD 的成果入口。[底座规格](../../foundation.md) · [任务资料与成果](../index.md)

## 执行顺序与验收

先实施 P1 的 Q01。P2 按图片、对话、Broker 和 CI 分组推进，组间无业务依赖的条目可并行。Q04 后接 Q05，避免同时改同一 SSE 生命周期。Q06 的幂等定位可与 Q02、Q03 并行实现，各自负责不同文件。三项集成后一起运行图片准入、执行和工具回归。P3 的本地检查与文档跟随对应 CI、Broker 路径核对。

每项按下文核对 C0 依赖后实施，进入验证时使用可定位的干净 Git 候选，记录实际场景、环境和结果。交回前核对计划、现行规范和旧接受记录，复核源码质量，取得覆盖 `pnpm check` 的有效结论，并明示隔离验证的范围。执行状态和取证沿仓库工作记录维护。[协调协议](../../coordination.md#验证与接受) · [测试导航](../../engineering/testing.md)

## P1

### Q01 图片恢复按本轮确认结果登记

- **C0** 核对 PG 登记与本地检查点是两个可独立恢复的事实，沿用已有输出键与 ETag、长度、SHA-256 元数据核验、重试次数和原始序号。隔离 PG 和受控 COS 可分别制造登记失败、HEAD 缺失或不匹配。[图片 API](../../apis/compute.md#post-apiv1computeimagesjobidrecover) · [COS 契约](../../integrations/cos.md)
- **C1** 持久保存检查点，将本轮通过 HEAD 核验的输出交 PG 登记。成功的部分资产保留，确认失败或未知的本地原件仍可用于后续恢复。
- **接受** 在同任务保留一张已登记资产，让另一张图片只有本地检查点且 HEAD 失败，验证现有资产可读、异常图片无新增 ready、原件可恢复；恢复 COS 后验证准确登记一次且供应商生成次数保持为一。

## P2

### Q02 OpenAI 同步图片出站字段

- **C0** 核对冻结路由和出站协议。OpenAI Images 的 JSON 生成只接收模型、提示词及支持的标量选项；兼容网关的 `aspect_ratio` 取冻结动态路由显式允许的值。编辑使用 multipart，参考图生成交给承担该能力的驱动。[图片 API](../../apis/compute.md#post-apiv1computeimages) · [OneLink 集成](../../integrations/onelink.md) · [供应商路由 PRD](../onelink-vendor-routing/prd.md)
- **C1** 按操作白名单构造出站字段；拒绝 OpenAI 生成请求的参考图组合。覆盖已持久路由和任务中的纯文本生成及 multipart 编辑。
- **接受** 在受控传输中核对普通生成、参考图编辑和受支持驱动的参考图生成请求，验证路径、允许的标量字段、显式许可的 `aspect_ratio`、图片字节与顺序。内部媒体元数据无出站，OpenAI 生成带参考图时模拟上游 POST 计数为零。

### Q03 参考图与遮罩签名先于 submitting

- **C0** 核对所有驱动共用的提交入口、冻结 MIME 与已经存在的图片签名识别。沿用私有 COS 条件读取、输入大小预算和唯一生成 POST 语义。[图片 API](../../apis/compute.md#post-apiv1computeimages) · [COS 契约](../../integrations/cos.md)
- **C1** 在向 PG 写入持久提交意图前检查每个参考图、遮罩的实际字节与格式，让驱动复用已读取字节。
- **接受** 注入签名和 MIME 不符的参考图及遮罩，观察任务在提交前失败、提交意图无写入且上游 POST 计数为零；有效输入仍走原有单次提交。

### Q04 SSE 快照与交接回放

- **C0** 核对订阅期间快照、回执及瞬态事件的协议，使用同请求的旧中间状态和最新终态构造交接顺序。[对话 SSE 契约](../../apis/conversations.md#get-apiv1conversationsidevents)
- **C1** 首帧发送 snapshot；回放有界缓冲时，结合该快照的回执与请求 ID 处理早于终态的旧事件。
- **接受** 让旧中间状态在读取基线时进入缓冲，并让快照看到该请求终态。客户端首先收到快照，同请求终态保持有效，其他请求事件仍正确关联，越界缓冲按契约关流。

### Q05 SSE 登录复核截止

- **C0** 核对一秒一次的同会话复核、现有鉴权错误和资源关闭路径，并复现挂起及迟到复核结果。单次复核等待对齐仓库现有 5 秒操作预算。[对话 SSE 契约](../../apis/conversations.md#get-apiv1conversationsidevents)
- **C1** 为单次复核设置有界等待；超期沿鉴权不可用路径结束订阅，清理 listener 和计时器。
- **接受** 复核永不返回时订阅限时关闭，迟到结果无新事件；正常复核时连接可继续接收事件，断开仍释放订阅资源。

### Q06 生图工具重试优先定位原任务

- **C0** 核对 owner、会话、轮次、操作键和输入冲突规则，读取旧任务持久路由与已存摘要，确认原有归一规则可用于重试；覆盖路由或凭据在首次受理后变化的场景。[Agent 工具 PRD](../onelink-agent-tools/prd.md) · [图片 API](../../apis/compute.md#post-apiv1computeimages)
- **C1** 在检查当前路由之前按现有幂等身份查找本人已受理任务，以该任务已存的路由快照还原首次归一并比较输入摘要；首次操作走当前准入。
- **接受** 首次提交后撤销路由或改变默认值，同键同输入返回同一任务；同键请求带冲突输入仍报冲突，两者均无第二次生成调用。

### Q07 B 的 AMQP 握手有界可停

- **C0** 核对 B 的连接、通道建立与运行关闭路径，使用本地受控端点复现握手停滞，并确认两个连接各自的关闭责任。[RabbitMQ 契约](../../integrations/rabbitmq.md) · [Worker 启动入口](../../../compute/src/main.ts)
- **C1** 为握手和启动等待设置上界，让停止信号及时收敛，关闭已建立和超期后取得的连接。
- **接受** 在首次连接、部分初始化和等待重连时请求停止，进程均在设定上限内退出；正常建立连接后仍能消费和关闭。

### Q08 A 的 Broker 退避随有效工作重置

- **C0** 核对 PG outbox 认领、发布确认、消费者注册与连接关闭，明确重置依据可以代表工作恢复；用连续故障与恢复的时序对照验证。[计算协议](../compute-service/protocol.md#路由回执与状态) · [计算服务](../../../src/compute/service.ts)
- **C1** 在 Broker 握手失败、握手后立即断开或收发未成功时保留既有指数退避增长；到达可观察的恢复点后重置。
- **接受** 连续故障推迟重试并受既有上限约束，单纯握手完成后立即断开仍保持增长；确认可用后处理待发消息，并恢复后续故障的初始退避。

### Q09 定向 CI 为实际 PG 测试供库

- **C0** 依据工作流核对 harness 路径实际选择的环境回归，确认其中的切换测试连接真实 PostgreSQL 及其隔离方式。[CI 工作流](../../../.github/workflows/check.yml) · [切换回归](../../../tests/environment/generation-cutover.test.ts) · [PostgreSQL 验证入口](../../integrations/postgres.md#验证入口与变更影响)
- **C1** 给执行该回归的定向 CI 准备隔离 PG 并保持原有测试选择和断言。按落地配置更新测试导航中的依赖说明。
- **接受** 核对定向工作流选择的服务和测试分组，使用对应 CI 数据库配置执行真实 PG 用例；分开记录本地等效运行和远端 CI 实际结论。

## P3

### Q10 check:local 支持离线回退

- **C0** 核对 `check:local` 的配置选择、测试发现与隔离入口，复现常驻配置缺失或服务不可达时，本可独立运行的定向测试被启动路径拦下。[常驻环境](../../local-environments.md#自动化回归与人工数据) · [测试入口](../../../scripts/harness/validation-entry.ts)
- **C1** 无可用常驻回归通道时回到定向测试的隔离入口；常驻通道可用时继续按既有规则复用，错误配置明确报错。
- **接受** 离线运行具备本地依赖的定向回归，返回实际测试结论；对依赖缺失或无效的测试保留可定位的失败。

### Q11 RabbitMQ 手册和历史协议与视频职责对齐

- **C0** 对照实际拓扑、A/B 账号权限与旧图片切换资料，定位手册和协议正文中仍把图片 MQ 写成当前用法的段落。[部署手册](../../../deploy/rabbitmq/README.md) · [部署拓扑](../../../scripts/service/compute-broker-topology.ts) · [图片切换](../../local-environments.md#图片生成迁移与切换)
- **C1** 让手册和协议正文明确当前 RabbitMQ 仅用于视频转码；历史图片消息、outbox、队列、权限和 journal 的排空对账走现行切换入口。
- **接受** 逐条比对部署手册、计算协议与实际拓扑，核对命令结果链、角色权限和排空入口；执行文档登记和链接检查，确认本计划 11 项均有范围、C0 核对动作、C1 结果和可观察接受条件。
